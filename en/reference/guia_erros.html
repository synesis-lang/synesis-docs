Error Guide

Every diagnostic of the Synesis compiler, with example, message and fix

Which version this page refers to

The codes, examples and messages below were verified with synesis 0.16.0. Each example was compiled, and the message shown is the one the compiler produced.

1 How to use this guide

Each diagnostic has a stable code, such as SYNESIS_E047. The letter gives the family: E (error), W (warning) and I (notice). Some E codes show as warnings; the severity of each one is in its section.

Severity Effect
error stops the export: no JSON, CSV or spreadsheet is written (unless --force)
error local to an EXPORT block stops only the artifact of that block
warning compilation proceeds; with --strict, warnings count as errors
notice only records a fact

1.1 Message format

Messages are one line each, with file, line and column. Paths are relative to the folder of the .synp:

annotations.syn:15:1  [ERROR]  Unknown field `extra` in ITEM block

The command line does not print the code. There are three ways to see it:

synesis compile project.synp --diagnostics-json diagnostics.json   # JSON report
synesis-help lookup E047                                            # the entry of one code
synesis-help search "bundle"                                        # search by subject

In VS Code the code comes with the diagnostic, together with the full explanation.

1.2 Options that change what shows

Option Effect
--check-codes lists every code without a concept (E004) instead of the summary (E090)
--strict treats warnings as errors; turns on --check-codes
--force writes the artifacts even with errors

2 Sources and bibliography

2.1 E001 — Reference not found in the .bib

Severity: error · Class: UnregisteredSource

The @bibref of a block matches no key in the bibliography file.

# annotations.syn
SOURCE @silvva2024
END SOURCE

ITEM @silvva2024
    quote: "text"
END ITEM
annotations.syn:1:1  [ERROR]  Reference `@silvva2024` not found in the .bib. Suggestions: `@silva2024`

How to fix: Check the spelling of the key or add the entry to the .bib. The message suggests similar keys when there are any.

2.2 E002 — ITEM without a SOURCE

Severity: error · Class: OrphanItem

An ITEM has a @bibref with no SOURCE block in the same file.

# annotations.syn
ITEM @silva2024
    quote: "text"
END ITEM
annotations.syn:1:1  [ERROR]  ITEM `@silva2024` has no matching SOURCE in this file

How to fix: Create the SOURCE @key block in the same .syn, before the items, or fix the @bibref of the ITEM.

2.3 E003 — SOURCE without ITEMs

Severity: warning · Class: SourceWithoutItems

A source was registered but none of its excerpts was analysed.

# annotations.syn
SOURCE @silva2024
END SOURCE
annotations.syn:1:1  [WARNING]  SOURCE `@silva2024` has no associated ITEM

How to fix: Add at least one ITEM or remove the SOURCE. It is a warning: compilation proceeds.

2.4 E070 — Duplicate SOURCE

Severity: error · Class: DuplicateSourceBibref

The same @bibref opens two SOURCE blocks in the same file.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "Cost limits adoption."
END ITEM

SOURCE @silva2024
END SOURCE
annotations.syn:8:1  [ERROR]  SOURCE `@silva2024` duplicated in this file

How to fix: Keep a single SOURCE block per reference; you may have as many ITEM blocks as needed.

2.5 E072 — Invalid BibTeX entry

Severity: error · Class: MalformedBibliographyEntry

An entry of the .bib is not valid BibTeX.

% references.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}

@article{souza2023,
    author = {Souza, Bia},
    title = {Open brace
references.bib:1:1  [ERROR]  Entry `@article` in `references.bib` is not valid BibTeX

How to fix: Fix the indicated entry (opening and closing braces, commas between fields).

2.6 E089 — Duplicate key across files

Severity: error · Class: DuplicateKeyAcrossFiles

The same key appears in two bibliography (or dataset) files. The first occurrence wins.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE BIBLIOGRAPHY "extra.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
% extra.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}
extra.bib:1:1  [ERROR]  Duplicate key `silva2024`: already defined in `references.bib:1`

How to fix: Decide which record is correct and remove the other.

3 Concepts and the organizing model

3.1 E004 — Code without a concept

Severity: warning · Class: UndefinedCode

A code used in a CODE field or in a chain has no ONTOLOGY block. The per-occurrence check is optional: it shows with --check-codes or --strict (see E090).

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    code: Costs
END ITEM
# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY
annotations.syn:4:1  [WARNING]  Code `Costs` is not defined in the organizing model. Suggested fix -> `Cost`

How to fix: Define the concept in a .syno file or fix the spelling of the code. The message suggests the closest concept.

3.2 E090 — Summary of codes without a concept

Severity: warning · Class: UndefinedCodesSummary

With the per-occurrence check off (the default), the compiler emits a single line with the number of codes without a concept.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    code: Costs, Trust
END ITEM
project.synp:1:1  [WARNING]  2 code(s) without a concept in the organizing model (2 occurrence(s)); use --check-codes to list them

How to fix: Use synesis compile --check-codes to list every occurrence. Before the ontology exists, this warning is expected.

3.3 E005 — ONTOLOGY without ONTOLOGY FIELDS

Severity: error · Class: OntologyWithoutTemplateFields

The project has ONTOLOGY blocks but the template does not declare which fields they accept.

# template.synt
TEMPLATE demo

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
END FIELD
# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY
project.synp:1:1  [ERROR]  Project has ONTOLOGY blocks but the template does not declare ONTOLOGY FIELDS

How to fix: Add the ONTOLOGY FIELDS block to the template, with the corresponding FIELD definitions.

3.4 E068 — Duplicate concept

Severity: error · Class: DuplicateOntologyConcept

Two ONTOLOGY blocks define the same concept (the comparison ignores case), in the same file or in different files.

# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY

ONTOLOGY cost
    definition: cost.
END ONTOLOGY
ontology.syno:5:1  [ERROR]  Concept `cost` duplicated in ontology.syno and ontology.syno

How to fix: Merge the two definitions into one block. If they are distinct concepts, rename one of them.

3.5 E103 — Names colliding after Unicode normalization

Severity: error · Class: IdentityCollision

Two names look different in the file (composed and decomposed characters) but have the same identity after NFC normalization.

ontology.syno:5:1  [ERROR]  Concepts `Café_Culture` and `Café_Culture` collide (same identity after Unicode normalization)

How to fix: Write the name always the same way; delete one of the blocks.

3.6 W071 — Identical definitions

Severity: warning · Class: DuplicateOntologyDescription

Two concepts have the same description, a frequent sign of a conceptual duplicate.

# ontology.syno
ONTOLOGY Cost
    description: Financial barrier.
END ONTOLOGY

ONTOLOGY Price
    description: Financial barrier.
END ONTOLOGY
ontology.syno:5:1  [WARNING]  Concepts `Cost` and `Price` have identical descriptions

How to fix: Differentiate the definitions or consolidate the concepts (see ROLE USE).

4 Chains and relations

A qualified chain alternates concepts and relations (A -> RELATION -> B) and requires the RELATIONS block in the template. A simple chain has only concepts (A -> B).

4.1 E007 — Arity not met

Severity: error · Class: ChainArityViolation

The chain has fewer concepts than the ARITY of the field requires.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 3
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Chain with 2 element(s), the template requires >= 3

How to fix: Complete the chain or revise ARITY in the template.

4.2 E008 — Named relations in a field without RELATIONS

Severity: error · Class: QualifiedChainWithoutRelations

The chain uses relation names but the field declares no RELATIONS. The compiler reads an upper-case middle element as a relation.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Chain with named relations in `chain`, but the template defines no RELATIONS

How to fix: Declare RELATIONS in the field or write a simple chain (A -> B).

4.3 E009 — Simple chain where relations are required

Severity: error · Class: SimpleChainWithRelationsRequired

The field declares RELATIONS but the chain names none.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Simple chain in `chain` but the template requires named relations

How to fix: Insert a declared relation between the concepts.

4.4 E010 — Undeclared relation

Severity: error · Class: InvalidChainRelation

The chain uses a relation that is not in the RELATIONS of the field.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> BLOCKS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Relation `BLOCKS` not declared in the template

How to fix: Use a declared relation or add the new one to the template, with its description.

4.5 E011 — Malformed qualified chain

Severity: error · Class: MalformedQualifiedChain

The concept → relation → concept alternation is broken; for instance, the chain ends with a relation.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption -> ENABLES
END ITEM
annotations.syn:6:5  [ERROR]  Qualified chain with incorrect structure: Cost -> INHIBITS -> Adoption -> ENABLES

How to fix: Keep an odd number of elements: concept, relation, concept.

4.6 E013 — Chain without the -> operator

Severity: error · Class: ChainWithoutArrowOperator

The value of a CHAIN field is a single element, with no ->. A line with several elements and no arrow usually shows as E028.

How to fix: Link at least two concepts with ->.

4.7 E014 — Concept named like a relation

Severity: error · Class: ConceptNameMatchesRelation

A concept in a code position has the same name as a declared relation.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: ENABLES -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  `ENABLES` is ambiguous: both concept and relation in `chain`

How to fix: Rename the concept or the relation.

4.8 E015 — Concept with spaces

Severity: error · Class: ConceptWithSpaces

A chain concept contains spaces.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Public Acceptance -> ENABLES -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Concept `Public Acceptance` contains spaces. Suggested fix -> `Public_Acceptance`

How to fix: Use underscores or CamelCase: Public_Acceptance.

5 Bundles

A BUNDLE groups fields that only make sense together and pairs them by position inside the ITEM.

5.1 E016 — Missing bundle member

Severity: error · Class: MissingBundleField

A bundle field appears without its partner, or a required bundle is absent.

# template.synt
ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    note: Cost is a barrier
END ITEM
annotations.syn:4:1  [ERROR]  Bundle (note, chain): missing fields `chain`

How to fix: Write every field of the bundle.

5.2 E017 — Unequal bundle counts

Severity: error · Class: BundleCountMismatch

The bundle fields occur in different numbers.

# template.synt
ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    note: Cost is a barrier
    chain: Cost -> INHIBITS -> Adoption
    note: Trust helps
END ITEM
annotations.syn:4:1  [ERROR]  Bundle (note, chain) with unequal counts: note=2, chain=1

How to fix: Each occurrence of a field needs its partner, in the same order.

5.3 E018 — Single-field bundle

Severity: error · Class: SingleFieldBundle

The template declares a bundle with only one field.

# template.synt
ITEM FIELDS
    REQUIRED BUNDLE quote
END ITEM FIELDS
template.synt:7:1  [ERROR]  Bundle `quote` declared with only one field in the template

How to fix: Declare at least two fields, or use a plain REQUIRED/OPTIONAL.

6 Field presence

6.1 E020 — Missing required field

Severity: error · Class: MissingRequiredField

A field listed as REQUIRED for that block type (SOURCE, ITEM or ONTOLOGY) is missing.

# template.synt
ITEM FIELDS
    REQUIRED quote, code
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
END ITEM
annotations.syn:4:1  [ERROR]  Required field `code` missing in ITEM block

How to fix: Fill in the field, or make it OPTIONAL in the template.

6.2 E021 — Forbidden field present

Severity: error · Class: ForbiddenFieldPresent

The block fills in a field listed as FORBIDDEN.

# template.synt
ITEM FIELDS
    REQUIRED quote
    FORBIDDEN note
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    note: x
END ITEM
annotations.syn:4:1  [ERROR]  Forbidden field `note` in ITEM block — remove this line

How to fix: Remove the line.

6.3 E022 — Unknown field

Severity: error · Class: UnknownFieldName

The file uses a field the template does not define for that scope.

# template.synt
ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    citation: x
END ITEM
annotations.syn:4:1  [ERROR]  Unknown field `citation` in ITEM block

How to fix: Fix the name, or declare the FIELD and list it in the FIELDS block of the scope.

6.4 E023 — Empty ITEM

Severity: error · Class: EmptyItemBlock

An ITEM block has no field at all.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
END ITEM
annotations.syn:4:1  [ERROR]  Empty ITEM block — no fields

How to fix: Fill in the block or remove it.

7 Values and field types

7.1 E026 — Decimal in an integer SCALE

Severity: error · Class: DecimalInIntegerScale

The FORMAT of the field uses integer bounds and the value has decimals.

# template.synt
FIELD confidence TYPE SCALE
    SCOPE ITEM
    FORMAT [1..5]
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    confidence: 3.5
END ITEM
annotations.syn:4:1  [ERROR]  Decimal value `3.5` in `confidence` — the field only accepts integers [1..5]

How to fix: Use an integer, or rescale the field (for example [0..2] instead of 0, 0.5 and 1). Decimals are accepted only when at least one FORMAT bound is not a whole number, as in [0..5.5]; writing [1.0..5.0] is not enough, despite what the diagnostic message suggests.

7.2 E027 — Value outside the ENUMERATED list

Severity: error · Class: InvalidEnumeratedValue

The value is not in the VALUES block.

# template.synt
FIELD status TYPE ENUMERATED
    SCOPE ITEM
    VALUES
        Asserted: stated as fact
        Negated: stated as not holding
    END VALUES
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    status: Maybe
END ITEM
annotations.syn:4:1  [ERROR]  Invalid value `Maybe` for `status`

How to fix: Use one of the declared values.

7.3 E028 — Incompatible value type

Severity: error · Class: InvalidFieldType

8 Template declaration

8.1 E039 — Listed field without a definition

Severity: error · Class: UndefinedFieldInScopeFields

A name appears in a FIELDS block but there is no FIELD with that name.

# template.synt

    REQUIRED quote, country
END ITEM FIELDS
template.synt:1:1  [ERROR]  Field `country` listed in `ITEM FIELDS` without a FIELD definition

How to fix: Define the FIELD or remove the name from the list.

8.2 E042 — Defined field never listed

Severity: warning · Class: OrphanFieldDefinition

A FIELD is used by no FIELDS block.

# template.synt
FIELD note TYPE MEMO
    SCOPE ITEM
END FIELD
template.synt:7:1  [WARNING]  Field `note` defined but missing from `ITEM FIELDS`

How to fix: List the field in the block of its scope or delete the definition.

8.3 E006 — Scope mismatch

Severity: error · Class: FieldScopeListMismatch

The field is listed in the block of one scope but its SCOPE is another.

# template.synt
ITEM FIELDS
    REQUIRED quote
    OPTIONAL note
END ITEM FIELDS
# template.synt
FIELD note TYPE MEMO
    SCOPE SOURCE
END FIELD
template.synt:8:1  [ERROR]  Field `note` listed in `ITEM FIELDS` but its declared SCOPE is SOURCE

How to fix: Make the SCOPE and the FIELDS block agree.

8.4 E047 — CHAIN without ARITY

Severity: error · Class: ChainWithoutArity

Every CHAIN field declares the minimum number of concepts.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
END FIELD
template.synt:8:1  [ERROR]  Field `chain` (CHAIN) without an ARITY declaration in the template

How to fix: Add, for instance, ARITY >= 2.

8.5 E048 — ARITY incompatible with RELATIONS

Severity: error · Class: ArityRelationsMismatch

    RELATIONS
        ENABLES: makes possible

template.synt:8:1  [ERROR]  Field `chain`: ARITY >= 4 requires more relations than the 1 declared

How to fix: Declare more relations or lower the arity.

8.6 E049 — ORDERED without VALUES

Severity: error · Class: OrderedWithoutValues

An ORDERED field needs its options, in order.

# template.synt
FIELD level TYPE ORDERED
    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `level` (ORDERED) without a VALUES block in the template

8.7 E050 — ENUMERATED without VALUES

    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `status` (ENUMERATED) without a VALUES block in the template

8.8 E051 — SCALE without FORMAT

Severity: error · Class: ScaleWithoutFormat

A SCALE field needs the numeric range.

# template.synt
FIELD confidence TYPE SCALE
    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `confidence` (SCALE) without a FORMAT declaration in the template

8.9 E052 — Invalid FORMAT syntax

8.13 E056 — RELATIONS outside CHAIN

8.14 E086 — VALUES outside ORDERED/ENUMERATED

Severity: error · Class: ValuesOnNonEnumerable

FIELD note TYPE TEXT

    END VALUES

The index establishes order, and ENUMERATED has none.

8.16 E057 — Duplicate FIELDS block

Severity: error · Class: DuplicateScopeBlock

There are two FIELDS blocks for the same scope. In version 0.16.0 the compiler does not emit this diagnostic: repeated blocks are accepted silently.

8.17 E058 — Value with leading or trailing whitespace

Severity: error · Class: ValueWithWhitespace

A value of the VALUES block has whitespace at the start or end. With the current template syntax the space is usually stripped while reading, so this is rare.

8.18 E059 — Duplicate value in VALUES

10 Files and paths

Paths in the .synp are relative to its folder. For safety, the compiler only reads files in that folder and below; the only exception is INCLUDE SHARED ONTOLOGY.

10.1 E073 — Annotations file not found

Severity: error · Class: MissingAnnotationsFile

INCLUDE ANNOTATIONS points to something that does not exist.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ANNOTATIONS "missing.syn"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
project.synp:5:5  [ERROR]  Annotations file `missing.syn` declared in the project was not found

How to fix: Check the name and the path.

10.2 E074 — Ontology file not found

Severity: error · Class: MissingOntologyFile

INCLUDE ONTOLOGY points to something that does not exist.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "missing.syno"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
project.synp:5:5  [ERROR]  Organizing model file `missing.syno` declared in the project was not found

How to fix: Check the path. An empty .syno is valid, but it must exist.

10.3 E075 — Path outside the project

Severity: error · Class: IncludePathEscapesProject

A path (literal or glob) leaves the project folder.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "ontology.syno"
    INCLUDE ONTOLOGY "../shared.syno"
END PROJECT
project.synp:6:5  [ERROR]  Path `../shared.syno` points outside the project folder

How to fix: Move the file inside the project. For a vocabulary shared by several projects, use INCLUDE SHARED ONTOLOGY.

10.4 E076 — Included file unreadable

Severity: error · Class: UnreadableIncludedFile

The file exists but cannot be read: syntax error, invalid encoding or size above 32 MB.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
annotations.syn:1:1  [ERROR]  File `annotations.syn` could not be read: error: annotations.syn:1:1: Unexpected token <EOF> END SOURCE Expected: END

How to fix: Open the indicated file and fix the problem described in the message.

10.5 E084 — SHARED outside ONTOLOGY

Severity: error · Class: SharedOnlyForOntology

INCLUDE SHARED is only accepted for ontologies.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE SHARED BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
project.synp:3:5  [ERROR]  `INCLUDE SHARED` invalid for BIBLIOGRAPHY — only ONTOLOGY accepts SHARED

How to fix: Copy the file into the project and use a plain INCLUDE.

11 Linking projects and datasets

Diagnostics E081, E082 and W083 only appear in the link step, when two or more projects are compiled together. See How to Link Independent Projects.

11.1 E077 — Duplicate identity value

Severity: error · Class: DuplicateIdentityValue

Two SOURCE blocks hold the same value in an IDENTIFIES field, which acts as a primary key.

# template.synt
FIELD researcher_id TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# annotations.syn
SOURCE @silva2024
    researcher_id: 001
END SOURCE

ITEM @silva2024
    quote: "a"
END ITEM

SOURCE @souza2023
    researcher_id: 001
END SOURCE

ITEM @souza2023
    quote: "b"
END ITEM
annotations.syn:9:1  [ERROR]  Value `1` of `researcher_id` (IDENTIFIES researcher) duplicated in `@silva2024` and `@souza2023`

How to fix: Each value identifies a single SOURCE: fix the data.

11.2 E078 — Linkage modifier outside SOURCE

Severity: error · Class: LinkageModifierOutsideSource

IDENTIFIES and REFERS TO only apply to SCOPE SOURCE fields.

# template.synt
FIELD author_id TYPE TEXT
    SCOPE ITEM
    REFERS TO researcher
END FIELD
template.synt:7:1  [ERROR]  `REFERS TO` in `author_id` (SCOPE ITEM) — only valid in SCOPE SOURCE

How to fix: Move the field to the SOURCE scope.

11.3 E079 — Value missing in the .bib

Severity: error · Class: MissingBibliographyValue

A REQUIRED ... ON BIBLIOGRAPHY field has no value in the entry of the SOURCE.

# template.synt
SOURCE FIELDS
    REQUIRED orcid ON BIBLIOGRAPHY
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS
% references.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}
annotations.syn:1:1  [ERROR]  Field `orcid` (ON BIBLIOGRAPHY) missing in the .bib entry of `@silva2024`

How to fix: Add the field to the BibTeX entry.

11.4 I080 — External reference declared

Severity: notice · Class: ExternalReferenceDeclared

The project declares REFERS TO and was compiled alone. It is informational: neither error nor warning.

# template.synt
FIELD author_id TYPE TEXT
    SCOPE SOURCE
    REFERS TO researcher
END FIELD
template.synt:11:1  [INFO]  External reference `researcher` (REFERS TO in author_id) — not materialized in isolation

How to fix: Nothing to do. To materialize the links, compile together with the project that declares IDENTIFIES.

11.5 E081 — Entity with two owners

Severity: error · Class: DuplicateEntityOwner

Two projects declare IDENTIFIES for the same entity label.

# lattes.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# orcid.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
<link>:0:0  [ERROR]  Entity `researcher` with a duplicate owner: `lattes` and `orcid`

How to fix: Choose the owner project; in the others use REFERS TO.

11.6 E082 — Diverging types in the link

Severity: error · Class: TypeMismatchInLinkage

The fields linked to the same entity have different TYPE.

# lattes.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# papers.synt
FIELD author_id TYPE SCALE
    FORMAT [0..999]
    SCOPE SOURCE
    REFERS TO researcher
END FIELD
<link>:0:0  [ERROR]  Tipos divergentes na entidade `researcher`: `lattes` TYPE TEXT vs `papers` TYPE SCALE

How to fix: Use the same TYPE on both sides.

11.7 W083 — Orphan reference

Severity: warning · Class: OrphanReference

A REFERS TO value matches no IDENTIFIES. If it would match ignoring case, the message reports the near-match. The compiler never merges entities.

# lattes.syn
SOURCE @lattes1
    rid: A01
END SOURCE

ITEM @lattes1
    quote: "x"
END ITEM
# papers.syn
SOURCE @papers1
    author_id: a01
END SOURCE

ITEM @papers1
    quote: "x"
END ITEM
<link>:0:0  [WARNING]  Orphan REFERS TO `a01` (researcher) — near match `A01` (differs only in case)

How to fix: Fix the spelling at the source. Orphans can be normal in real corpora.

11.8 E085 — Value missing in the dataset

Severity: error · Class: MissingDatasetValue

A REQUIRED ... ON DATASET field has no value in the TOML record of the SOURCE.

# template.synt
SOURCE FIELDS
    REQUIRED interview ON DATASET "interview.id"
    REQUIRED region ON DATASET "interview.region"
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS
# records/s1.toml
[interview]
id = "silva2024"
annotations.syn:1:1  [ERROR]  Field `region` (ON DATASET "interview.region") missing in the record `@silva2024`

How to fix: Complete the record, or make the field OPTIONAL.

18 Syntax errors

When the text does not follow the grammar, the compiler never reaches validation and there is no semantic code: the message shows where reading stopped (Unexpected token) and what was expected. In an included file it comes wrapped in E076; in the .synp or the template, in E064.

The most common causes:

Symptom Cause Fix
error right after the template name version: or author: on its own line write them on the same line: TEMPLATE name version: "1.0"
error inside the VALUES of an ORDERED index without brackets (1 low:) write [1] low: ...
Unexpected token <EOF> an END ... is missing close every block
error in a multi-line value continuation without indentation indent the following lines more than the field name
error in the .synp indented blocks mixed with blocks at column 0 indent all the content of PROJECT consistently
