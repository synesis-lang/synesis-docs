Synesis for Qualitative Research

A hands-on tutorial for humanities researchers

1 Welcome, Researcher!

In this tutorial we will build a qualitative analysis project together using Synesis. If you work with interviews, document analysis, grounded theory or thematic analysis, this guide is for you.

What you will build:

  • An interview analysis project
  • A conceptual coding system
  • Causal relations between concepts
  • Exports for quantitative analysis

Prerequisites:

  • Python 3.10+ and the compiler installed (pip install synesis)
  • A reference manager (Zotero recommended, but optional)
  • Basic familiarity with qualitative research
New to Synesis?

If you have never used Synesis, start with Getting Started. This tutorial assumes you know the basic commands.

1.1 Our Research Scenario

We will work on a fictitious study about resistance to telemedicine adoption in rural communities. Imagine you ran 3 semi-structured interviews and now need to analyse the data.

1.2 Step 1: Prepare the Sources

Create a project folder:

mkdir telemedicine-analysis
cd telemedicine-analysis

Create references.bib with the references of the interviews. The keys are neutral and do not identify participants:

@misc{interview01,
  author = {Participant 01},
  title = {Interview on access to health care},
  year = {2026},
  note = {Resident of a rural community, 45 minutes (fictitious data)}
}

@misc{interview02,
  author = {Participant 02},
  title = {Interview on technology and health},
  year = {2026},
  note = {Resident of a rural community, 60 minutes (fictitious data)}
}

@misc{interview03,
  author = {Participant 03},
  title = {Interview, professional perspective},
  year = {2026},
  note = {Rural physician, 40 minutes (fictitious data)}
}
Checkpoint ✓

You should have the folder telemedicine-analysis/ with the file references.bib and your 3 interviews.

1.3 Step 2: Define the Template

Create template.synt, fitted to qualitative analysis:

TEMPLATE qualitative_analysis version: "1.0"

# ============================================
# SOURCE FIELDS
# ============================================

SOURCE FIELDS
    REQUIRED speaker
END SOURCE FIELDS

FIELD speaker TYPE ENUMERATED
    SCOPE SOURCE
    DESCRIPTION Who speaks in the source
    VALUES
        User: Resident served by the service
        Professional: Health professional
    END VALUES
END FIELD

# ============================================
# ITEM FIELDS
# ============================================

ITEM FIELDS
    REQUIRED quote, memo, chain
    OPTIONAL context
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Textual excerpt from the interview
    GUIDELINES
        Copy the speech literally, in one to three sentences.
        Do not copy the interviewer's questions.
    END GUIDELINES
END FIELD

FIELD memo TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Analytical memo with the interpretation and the mechanism identified
    GUIDELINES
        Interpret the speech; do not repeat it.
        Separate what the source states from what you infer.
    END GUIDELINES
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    DESCRIPTION Causal or relational chain between ontology concepts
    RELATIONS
        MEDIATES: one factor softens or mediates the effect of another
        FAVORS: direct positive effect (A favors B)
        INHIBITS: limits or restricts (A reduces the viability of B)
        ENABLES: creates a condition for B to happen
    END RELATIONS
    GUIDELINES
        Record only relations the speech supports.
    END GUIDELINES
END FIELD

FIELD context TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Nuances of the moment of speech (tone, emotion, hesitation)
    GUIDELINES
        Fill in only with what was recorded during the interview.
    END GUIDELINES
END FIELD

# ============================================
# ONTOLOGY
# ============================================

ONTOLOGY FIELDS
    REQUIRED definition, group
END ONTOLOGY FIELDS

FIELD definition TYPE TEXT
    SCOPE ONTOLOGY
    DESCRIPTION Definition of the concept and application criterion
    GUIDELINES
        Define the concept and say when to apply it.
    END GUIDELINES
END FIELD

FIELD group TYPE TOPIC
    SCOPE ONTOLOGY
    DESCRIPTION Thematic group of the concept
    GUIDELINES
        Use a term without spaces.
    END GUIDELINES
END FIELD

Notice: the context field is optional and records qualitative nuances (hesitation, emotion, changes of tone).

Checkpoint ✓

Validate the template:

synesis validate-template template.synt

It should print OK.

1.4 Step 3: Build the Ontology

In qualitative research codes emerge from the data; let us create the initial ones from a first reading. Create ontology.syno:

ONTOLOGY technological_distrust
    definition: Fear about the effectiveness of remote medical care, such as doubting a diagnosis without physical examination.
    group: barriers
END ONTOLOGY

ONTOLOGY lack_of_infrastructure
    definition: Missing or precarious internet, equipment or power that makes use unfeasible.
    group: barriers
END ONTOLOGY

ONTOLOGY preference_for_in_person_contact
    definition: Valuing face-to-face meetings, linking quality of care to physical presence.
    group: barriers
END ONTOLOGY

ONTOLOGY low_digital_literacy
    definition: Difficulty with digital technologies, creating dependence on outside help.
    group: barriers
END ONTOLOGY

ONTOLOGY urgent_need
    definition: Emergency or lack of an in-person alternative that drives acceptance.
    group: facilitators
END ONTOLOGY

ONTOLOGY community_support
    definition: Help from relatives, neighbours or health agents that mediates access.
    group: facilitators
END ONTOLOGY

ONTOLOGY telemedicine_adoption
    definition: Patient's willingness to use remote medical services.
    group: outcomes
END ONTOLOGY

ONTOLOGY access_to_telemedicine
    definition: Concrete capacity to connect and use the remote service.
    group: outcomes
END ONTOLOGY

ONTOLOGY telemedicine_use
    definition: Actual use of remote consultations, autonomous or mediated.
    group: outcomes
END ONTOLOGY

ONTOLOGY telemedicine_acceptance
    definition: Receptiveness to telemedicine after experience or perceived need.
    group: outcomes
END ONTOLOGY

ONTOLOGY in_depth_diagnosis
    definition: Diagnosis requiring physical examination, named as a context unsuited to telemedicine.
    group: outcomes
END ONTOLOGY
Checkpoint ✓

You have 11 concepts in 3 groups (barriers, facilitators, outcomes). As you analyse the data you may add others.

1.5 Step 4: Annotate the Interviews

Now the main part. Create annotations.syn with the first interview:

SOURCE @interview01
    speaker: User
END SOURCE

ITEM @interview01
    quote: "I don't trust this business of talking to a doctor through a computer. How will they know what I have without examining me?"
    memo: Distrust of diagnostic effectiveness. The participant links quality of care to physical presence.
    chain: technological_distrust -> INHIBITS -> telemedicine_adoption
    context: Said this at the very beginning, before any direct question about telemedicine.
END ITEM

ITEM @interview01
    quote: "The internet drops all the time here. Sometimes it's out for two or three days. How am I going to book an appointment?"
    memo: Precarious infrastructure appears as a concrete barrier.
    chain: lack_of_infrastructure -> INHIBITS -> access_to_telemedicine
    context: Raised their voice, showing irritation.
END ITEM

Now it’s your turn! Add the second interview to the same file:

SOURCE @interview02
    speaker: User
END SOURCE

ITEM @interview02
    quote: "I tried it once when my granddaughter helped me. It was good, I sorted it out without leaving home. But on my own I can't, I need someone to work the phone."
    memo: Positive experience when mediated by a relative. Recognizes the benefit but depends on informal support.
    chain: community_support -> MEDIATES -> low_digital_literacy -> INHIBITS -> telemedicine_use
    context: Mentioned the granddaughter with gratitude and admitted the dependence with resignation.
END ITEM

ITEM @interview02
    quote: "When my son was in hospital in the capital, our doctor talked to theirs by video. It was a blessing, she explained the case to me properly."
    memo: Successful use between professionals, as continuity of care in a critical situation.
    chain: urgent_need -> FAVORS -> telemedicine_acceptance
END ITEM
Researcher’s Tip

The context field captures what the transcript alone loses. It is valuable in interpretation, and being optional it never forces you to invent what was not observed.

And the third, with the professional perspective:

SOURCE @interview03
    speaker: Professional
END SOURCE

ITEM @interview03
    quote: "Patients do struggle, but it's more the internet than unwillingness. When it works, they like it."
    memo: The professional points to infrastructure, not cultural resistance, as the main barrier.
    chain: lack_of_infrastructure -> INHIBITS -> telemedicine_use
    context: Visible frustration when mentioning the internet.
END ITEM

ITEM @interview03
    quote: "I prefer in person when I can, because I see things that don't show on screen. But for follow-ups and quick questions, telemedicine is perfect."
    memo: Distinguishes suitable and unsuitable contexts of use. Not rejection, but situated use.
    chain: preference_for_in_person_contact -> ENABLES -> in_depth_diagnosis
    context: Pragmatic tone, weighing pros and cons.
END ITEM

1.6 Step 5: Create the Project File

Create analysis.synp to connect everything:

PROJECT rural_telemedicine_analysis
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ONTOLOGY "ontology.syno"
    INCLUDE ANNOTATIONS "annotations.syn"

    METADATA
        version: 1.0
        author: Research team
        created: 2026-01-15
    END METADATA

    DESCRIPTION
    Thematic analysis of barriers and facilitators to
    telemedicine adoption in rural communities (fictitious data).
    END DESCRIPTION

    QUESTIONS
        Q1: Which barriers to using telemedicine do interviewees report?
        Q2: What favors acceptance?
    END QUESTIONS
END PROJECT

Note the indentation: the text lines of DESCRIPTION sit at the same level as the word DESCRIPTION.

1.7 Step 6: Compile and Analyse

synesis compile analysis.synp --stats
Compilation Summary:
  Sources        3
  Items          6
  Model entries  11  (11 concepts)
  Active codes   11
  Chains         6

Export the results:

synesis compile analysis.synp --json results/analysis.json --csv results/csv --xls results/analysis.xlsx
results/
├── analysis.json
├── analysis.xlsx
└── csv/
    ├── sources.csv
    ├── items.csv
    ├── ontologies.csv
    └── chains.csv

1.7.1 Analysis in Excel

Open analysis.xlsx. It has the sheets sources, items, ontologies and chains. The chains sheet has one row per relation, with the source and its location. An excerpt:

bibref from_code relation to_code
@interview01 technological_distrust INHIBITS telemedicine_adoption
@interview01 lack_of_infrastructure INHIBITS access_to_telemedicine
@interview02 community_support MEDIATES low_digital_literacy
@interview02 low_digital_literacy INHIBITS telemedicine_use
@interview03 lack_of_infrastructure INHIBITS telemedicine_use

With a pivot table you count relations, cross concepts with the type of speaker and go back to the excerpt behind each row.

Analytical Insight

lack_of_infrastructure appears in the speech of a user and of the professional. That suggests investigating the barrier as concrete and systemic, not just as “cultural resistance”. Three interviews raise the hypothesis; they do not demonstrate it.

1.8 Step 7: Refine the Analysis (Iterative Process)

After seeing the first patterns, go back to the data.

1.8.1 7.1 Add New Codes

Add to the ontology:

ONTOLOGY perceived_digital_exclusion
    definition: Feeling left out for lack of access to or command of digital technologies.
    group: barriers
END ONTOLOGY

1.8.2 7.2 Refine Existing Codes

If a code is ambiguous, split it into two with distinct definitions. If two codes are the same concept, consolidate them (see ROLE USE).

1.8.3 7.3 Annotate More and Recompile

Return to the interviews, annotate passages you missed on the first reading and compile again. A code still without a definition shows in a summary warning; to see every occurrence:

synesis compile analysis.synp --check-codes

1.9 Step 8: Visualize the Relations

In VS Code, with the Synesis extension, open annotations.syn and press Ctrl+Alt+F to see the relation graph of the file.

For a graph that opens in the browser, or a graph database:

pip install synesis-graph
synesis-graph html --project analysis.synp --output results/graph.html --all

See synesis-graph and How to export to Neo4j.

1.11 Good Practices for Researchers

1.11.1 1. Annotate Progressively

Do not wait for data collection to end: analysis helps you adjust the interview guide.

1.11.2 2. Use Memos Analytically

The memo field is not for repeating the quotation. Interpret, point out contradictions, raise hypotheses, connect with theory.

1.11.3 3. Document Decisions

Record why you assigned a code, in definitions and memos. The template GUIDELINES are your protocol.

1.11.4 4. Review Systematically

Every 5 to 10 annotations, compile and look at the distribution. Is a code too generic? Does another appear only once? Is there a pattern without a name?

1.11.5 5. Validate with Peers

Share the .syno and the template. Ask whether definitions are clear and whether there are overlaps.

1.11.6 6. Protect Participants

Use neutral keys, remove identifying data and check what goes to AI services.

1.12 Differences Between Methodological Approaches

1.12.1 Grounded Theory

  • Start with no ontology (the compiler sums up codes without a concept in a single warning)
  • Let codes emerge from the data and define them afterwards
  • Use chain to relate categories
  • Iterate until theoretical saturation

1.12.2 Thematic Analysis

  • Define initial themes (deductive) or let them emerge (inductive)
  • Group concepts with a TOPIC field
  • Use memos to reflect on recurring themes

1.12.3 Content Analysis

  • A stricter template, with ENUMERATED and ORDERED fields
  • Ontology defined a priori
  • Focus on frequency, from the CSV tables

1.12.4 Critical Discourse Analysis

  • Use the context field extensively (prosody, hesitation, silences)
  • Record discursive strategies in memos
  • Use chain to make assumptions explicit
