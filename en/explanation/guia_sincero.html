1 Why Not Just Do It in Excel?

An honest answer about when Synesis makes sense — and when it does not

1.1 The Inevitable Question

“If the final result is a spreadsheet, why learn a language? Why not write everything straight into Excel?”

This question is not cynical. It is methodologically healthy.

Every tool has to justify its cost.

1.2 Short Answer

If your project is small, simple and individual: use Excel.

Excel is an extraordinary tool. Flexible, accessible, powerful and universal.

Synesis does not exist to replace Excel. It exists to solve problems that appear when your spreadsheet:

  • Turns into a web of internal links that is hard to maintain.
  • Holds information so dense that it becomes visually exhausting.
  • Needs version control.
  • Must avoid conflict errors from real-time collaboration.

The difference is not technical. It is structural.

1.3 What Is Really at Stake

The question is not “which tool is more powerful”.

It is:

Where is the structure that organizes your thinking?

In Excel, structure is implicit. In Synesis, structure is explicit and validated.

The difference seems small at first. It becomes decisive as the project grows.

1.4 Where Excel Starts Showing Structural Limits

1.4.1 Conceptual Consistency

In Excel you can record:

Code Relation Code
Cost influences Adoption
cost INFLUENCES adoption
Price affects Acceptance

Are these three ways of saying the same thing? Or different concepts? Excel does not know. Neither will you remember six months from now.

Excel does not know. It was not built to know.

Yes, you can create a code sheet, use data validation, drop-down lists, cross references. It works. But as the project grows, keeping that discipline becomes manual and fragile.

The Synesis compiler does not depend only on the researcher’s memory or care. It validates content against a declared ontology.

That is not bureaucracy. It is syntactic and semantic control.

1.4.2 Interpretation Is Hard to Formalize

In Excel a typical structure is:

Quotation Code
“The price is too high” Economic Barrier

But:

  • Why is this not “Value Perception”?
  • Was the decision debated?
  • Did it change over time?
  • Can you reconstruct the reasoning a year from now?

Yes, you can add note columns. You can create a separate codebook. You can document method decisions. But those layers end up scattered. There is no structural guarantee that interpretation and evidence stay traceably linked.

Synesis can be configured to require interpretation as part of the record — not as an optional comment.

That makes analysis auditable, not merely organized.

1.4.3 Traceability Grows in Complexity

Excel can do:

  • Filters
  • VLOOKUP / XLOOKUP
  • Pivot tables
  • Power Query

It is technically capable.

The problem is not computing power. It is architecture.

Once you add dozens of sources, several researchers and successive revisions, questions appear:

  • Who changed this code?
  • In which version was this quotation different?
  • Why did two spreadsheets diverge?
  • How to reconcile conflicting classifications?

Excel was not designed as a versionable system.

Synesis works with structured text files. That allows version control, full history and merging of parallel contributions.

For a three-month project this is overkill. For a three-year project it is methodological survival.

1.4.4 Complex Relations Are Improvised

Try to represent formally:

Falta de Informação → GERA → Desconfiança → INIBE → Adoção

In Excel this becomes:

  • Multiple columns
  • Concatenated strings
  • Structures to be interpreted later

Nothing stops you. But nothing guarantees structural integrity.

Synesis treats causal chains as formal entities, not descriptive text.

That allows export to:

  • network analysis
  • knowledge graphs
  • automatic validation of relational consistency

1.5 What the “Extra Work” Really Is

It is not learning syntax. It is accepting that:

  • Concepts must be defined
  • Relations must be formalized
  • Interpretations must be justified
  • Structure must be explicit

Excel lets you postpone these decisions. Synesis makes you take them early. And that is uncomfortable.

1.6 When Excel Is the Best Choice

Use Excel when:

  • Data volume is small
  • Conceptual complexity is low
  • The project is exploratory
  • No team is collaborating
  • Formal traceability is not required
  • Methodological risk is low

Excel is excellent for exploration, initial organization and visualization. There is no virtue in needless sophistication.

1.7 When Synesis Becomes Rational

Consider Synesis when:

  • The vocabulary must be strictly controlled
  • Several people code at once
  • The project will continue or be reused
  • You need to defend method decisions
  • Causal relations are central to the analysis
  • Structural integrity is part of the result
  • You integrate large volumes of AI-generated data (Big Qual)

In these cases the issue is not immediate efficiency. It is the accumulated cost of inconsistency.

1.8 The Real Comparative Cost

1.8.1 Excel

  • Low entry cost
  • High hidden cost of structural maintenance
  • Silent errors
  • Heavy dependence on human discipline

1.8.2 Synesis

  • Higher initial cost
  • Explicit structure from the start
  • Errors detected early
  • Methodological scalability

1.9 The Right Question

It is not:

“Can I do this in Excel?”

You probably can.

It is:

“What is the cost of inconsistency in this project?”

If the cost is low, Excel will do. If the cost is high, structure is not a luxury — it is epistemological protection.

1.10 An Honest Position

Synesis does not replace Excel.

Excel is excellent as:

  • a visualization tool
  • a means of sharing
  • an exploration environment
  • an export format

That is why one of the export formats of the Synesis compiler is precisely Excel. The difference lies in where the source of truth is.

If the source of truth is the spreadsheet, you depend on manual discipline.

If the source of truth is a structured, checkable system, the spreadsheet becomes just an interface.

1.11 Conclusion

Synesis is not for everyone. And that is not a flaw — it is focus.

It makes sense when:

  • Structure matters more than initial speed
  • Rigor matters more than convenience
  • Scalability matters more than improvisation

The best tool is the one whose structural cost is proportional to the risk of your project. Sometimes it is Excel. Sometimes it is not.
