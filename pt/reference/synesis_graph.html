synesis-graph

Referência do pipeline de projetos Synesis para grafos

1 synesis-graph

O synesis-graph transforma um projeto Synesis compilado em um grafo navegável: num banco Neo4j, num banco ArcadeDB (em servidor ou local, sem servidor) ou numa visualização HTML autocontida.

A tradução é dinâmica: a ferramenta lê o template do projeto (.synt) e deriva dele a estrutura do grafo. Se você muda o template, o grafo muda junto, sem tocar na ferramenta.

Sem arquivos intermediários

O pipeline compila o projeto em memória e sincroniza direto com o destino. O compilador é a única fonte de verdade: um erro de compilação interrompe o processo antes de qualquer escrita no banco.

2 Instalação

Requer Python 3.10+ e synesis ≥ 0.16.0 (instalado como dependência).

pip install "synesis-graph[neo4j]"        # com o driver do Neo4j
pip install synesis-graph                 # ArcadeDB (servidor e local) e HTML
pip install "synesis-graph[embeddings]"   # busca semântica (traz o torch, ~2 GB)
synesis-graph --version
# synesis-graph, version 0.13.1

3 Os backends

Backend Comando Destino Quando usar
Neo4j synesis-graph neo4j servidor Neo4j (bolt://) consultas Cypher, métricas GDS, agentes MCP
ArcadeDB synesis-graph arcadedb servidor ArcadeDB (http://) grafo compartilhado, algoritmos nativos
ArcadeDB local synesis-graph arcadedb-embedded pasta no seu computador trabalhar sozinho, sem servidor nem Java instalado
HTML synesis-graph html arquivo .html único explorar, compartilhar, publicar

Os três backends de banco produzem o mesmo grafo a partir do mesmo projeto. O HTML aplica filtros de legibilidade (Seção 8).

3.1 Fonte dos dados

Todos aceitam duas formas de entrada, mutuamente exclusivas:

# A partir do projeto — compila em memória
synesis-graph neo4j --project projeto.synp

# A partir de um JSON exportado pelo compilador
synesis-graph neo4j --json export.json

4 Modelo de dados: Template → Grafo

Mapeamento de tipos
Tipo no template Elemento no grafo Aresta criada
CODE Nó de conceito MENTIONS (Item → Conceito)
CHAIN Relação entre conceitos RELATES_TO (com tipo e descrição)
TOPIC Nó de taxonomia GROUPED_BY
Campos ASPECT / DIMENSION do projeto Nós de taxonomia QUALIFIED_BY / BELONGS_TO
ROLE HIERARCHY KIND/PART/INSTANCE Hierarquia adotada KIND_OF, PART_OF, INSTANCE_OF (filho → pai)
ENUMERATED, TEXT, MEMO Propriedade do nó —
SCOPE SOURCE Propriedades do nó Source —

Os campos são reconhecidos pelo tipo declarado, não pelo nome: um CHAIN chamado mecanismo gera RELATES_TO normalmente. aspect e dimension não são tipos da linguagem; são desenhos de projetos específicos, reconhecidos pelo nome.

4.1 Nós sempre criados

Nós base
Nó Representa Propriedades
Source A fonte (artigo, entrevista, documento) bibtex, title, author, year e os campos SCOPE SOURCE
Item A unidade analítica identificador, citação, campos de ITEM, source_file, source_line
ProjectContext O contexto do projeto veja Seção 5

Cada Item é ligado à sua fonte por (:Item)-[:FROM_SOURCE]->(:Source), a invariante da linguagem de que todo ITEM pertence a um SOURCE.

4.2 Exemplo de tradução

FIELD category TYPE CODE
    SCOPE ITEM
END FIELD

FIELD theme TYPE TOPIC
    SCOPE ONTOLOGY
END FIELD
(:Item)-[:MENTIONS]->(:Category)-[:GROUPED_BY]->(:Theme)

O rótulo do nó de conceito deriva do nome do campo: um campo ordem_2a gera nós Ordem_2a.

4.3 Nomes preteridos (USE)

Um conceito consolidado com ROLE USE não vira nó: menções e cadeias vão ao alvo, que guarda o nome em aliases.

4.4 Aresta entre taxonomias

O pipeline deriva IS_LINKED_TO entre nós de taxonomia; a força (strength) conta as relações RELATES_TO entre os conceitos das duas categorias.

Rastreabilidade preservada

Cada item guarda o arquivo e a linha de origem. Um conceito no grafo pode sempre ser rastreado até o trecho do .syn que o sustenta.

5 O contexto viaja com o grafo: ProjectContext

Cada sincronização com um banco grava um vértice ProjectContext. Um esquema de banco informa a forma, não o significado; sem o contexto, quem consulta o grafo precisaria adivinhar os critérios de codificação.

Propriedade Conteúdo
description o bloco DESCRIPTION do .synp, literal
project_summary metadados, tamanho do corpus, proveniência e questões de competência
template_doc o template como documento legível: campos, escalas, GUIDELINES, regras e guia de navegação do grafo
source_count, item_count, concept_count contagens
compiler_version, synesis_graph_version, compiled_at, generated_at proveniência
load_state marca se a carga terminou 
MATCH (p:ProjectContext) RETURN p.description, p.project_summary;
MATCH (p:ProjectContext) RETURN p.template_doc;

O texto armazenado é escrito em português. O backend HTML não cria esse vértice.

6 Backends de banco

synesis-graph neo4j --project projeto.synp
synesis-graph arcadedb --project projeto.synp
synesis-graph arcadedb-embedded --project projeto.synp

6.1 Opções comuns

Opções
Opção Descrição
--project Caminho do .synp. Repetível — veja Seção 9
--json Alternativa: JSON já exportado
--config Arquivo TOML de configuração (padrão: config.toml)
--database Nome do banco; também nomeia o grafo unificado numa ligação
--mode rebuild\|update rebuild (padrão) apaga e reescreve; update grava só o que mudou, sem remover nada
Opções específicas
Opção Backends Descrição
--metrics all\|fast\|none ArcadeDB fast pula betweenness e comunidades; none pula as métricas
--vector-embeddings CAMPOS ArcadeDB cria vetores para busca semântica
--rebuild-embeddings ArcadeDB recalcula todos os vetores
--db-path DIR ArcadeDB local raiz onde o banco é criado (<DIR>/databases/<projeto>)

6.2 Configuração

Crie um config.toml (há um config.toml.example no repositório):

[neo4j]
uri = "bolt://127.0.0.1:7687"   # ou neo4j+s://... para o Aura
user = "neo4j"
password = "sua_senha"
database = "meu_corpus"          # opcional
# fulltext_analyzer = "brazilian"

[arcadedb]
uri = "http://localhost:2480"    # endpoint HTTP, não bolt://
user = "root"
password = "sua_senha"

[arcadedb-embedded]              # seção opcional; não há credenciais
# db_path = "."
Nunca versione as credenciais

Adicione config.toml ao .gitignore.

Para um corpus em português, fulltext_analyzer = "brazilian" faz a busca textual encontrar variações com e sem acento e no plural.

6.3 Métricas de rede

6.3.1 Métricas nativas (sempre disponíveis)

Nó Métricas
Conceito degree, in_degree, out_degree, mention_count (frequência), source_count (dispersão)
Taxonomia concept_count, weighted_degree, aspect_diversity, dimension_diversity
Fonte item_count, concept_count
mention_count e source_count medem coisas diferentes

Um conceito citado 40 vezes em uma única fonte é um tema daquele documento. Outro citado 8 vezes em 8 fontes é um achado transversal.

6.3.2 Métricas avançadas

pagerank, betweenness e community (Louvain) vêm de motores diferentes:

Backend Motor Requer
Neo4j Graph Data Science plugin GDS
ArcadeDB algoritmos nativos (algo.*) nada
Os valores não são comparáveis entre os dois

O GDS calcula sobre o subgrafo de conceitos; os algoritmos do ArcadeDB rodam sobre o grafo inteiro, e arestas como MENTIONS e GROUPED_BY também pesam. Ambas são centralidades válidas, mas respondem perguntas um pouco diferentes.

Sem o GDS no Neo4j, o pipeline avisa e continua com as métricas nativas. No GDS, a projeção se adapta ao template: RELATES_TO (há CHAIN), CO_TAXONOMY (há CODE e TOPIC) ou CO_CITATION (alternativa). Numa projeção por co-citação, uma comunidade agrupa conceitos que aparecem juntos, não conceitos que o pesquisador declarou relacionados.

6.4 Busca semântica (ArcadeDB)

synesis-graph arcadedb-embedded --project projeto.synp \
    --vector-embeddings ontology_description,topic

Os vetores são gerados localmente, sem chave de API, e guardados em <projeto>.embeddings.json; só os conceitos cujo texto mudou são recalculados. Campos TEXT e TOPIC são os indicados; vocabulários fechados repetem o mesmo texto em muitos conceitos. Para corpus em português, use um modelo multilíngue (o padrão):

[arcadedb-embedded.embeddings]
model = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
fields = ["ontology_description", "topic"]

Veja o estudo medido em Embeddings Vetoriais e GraphRAG.

6.5 Cargas grandes

A escrita é feita em segmentos. Se uma carga for interrompida, o ProjectContext fica marcado como incompleto: um novo rebuild resolve, e --mode update é recusado sobre um grafo parcial. Duas cargas simultâneas no mesmo grafo são recusadas.

7 Perguntar ao grafo (serve)

synesis-graph serve                       # publica ./databases; Ctrl+C encerra
synesis-graph serve --db-path ./grafos    # a mesma raiz usada na exportação
synesis-graph serve --install claude-desktop
synesis-graph serve --install vscode

serve mantém o banco local disponível por HTTP e por MCP, para que o Claude Desktop ou o VS Code consultem o corpus em linguagem natural.

Opção Descrição
--db-path raiz do servidor (padrão: pasta atual)
--port porta HTTP (padrão: 2480)
--allow-writes permite alterar o corpus (desligado por padrão)
--install claude-desktop\|vscode acrescenta o servidor à configuração do cliente, com cópia de segurança

A senha é gerada uma vez e lembrada; para escolher a sua, defina SYNESIS_DB_PASSWORD.

8 Backend HTML

synesis-graph html --project projeto.synp --output grafo.html

Gera um arquivo HTML único, que pode ser aberto localmente, anexado ou publicado como material suplementar.

Opções do backend html
Opção Padrão Descrição
--output ./graph.html arquivo de saída
--group-by automático campo de taxonomia para colorir comunidades
--min-frequency 3 oculta conceitos mencionados em menos de N itens
--min-source-count 2 oculta conceitos presentes em menos de N fontes
--max-nodes 200 os N conceitos de maior grau (0 = sem limite)
--max-hyperedges 50 máximo de hiperarestas
--include-isolated desligado inclui conceitos sem conexões de cadeia
--all — desliga todos os filtros

8.1 Por que há filtros por padrão

Um corpus real tem uma cauda longa de conceitos que aparecem uma ou duas vezes. Os padrões mostram os conceitos que se repetem e atravessam fontes. Para ver tudo:

synesis-graph html --project projeto.synp --output grafo.html --all
O filtro é de visualização, não de dados

Nada é descartado do projeto; os backends de banco recebem o grafo completo.

8.2 Hiperarestas

Quando um ITEM conecta três ou mais conceitos, a visualização o representa como uma região sombreada: é a diferença entre “A–B e B–C se relacionam” e “A, B e C aparecem juntos nesta passagem”.

8.3 Camadas: ontologia e evidência

O painel separa a ontologia (conceitos, taxonomia e, com papéis, pais e filhos) da evidência (os itens que sustentam cada conceito). Um conceito sem evidência aparece como tal.

8.4 Configuração via TOML

[html]
output_path = "./graph.html"     # aceita o marcador {project}
# group_by = "topic"
min_frequency = 3
min_source_count = 2
max_nodes = 200
max_hyperedges = 50
include_isolated = false

9 Grafos multiprojeto

Quando vários projetos declaram IDENTIFIES / REFERS TO (veja Como Ligar Projetos Independentes), os backends de banco reificam essas identidades como nós.

synesis-graph neo4j \
  --project lattes.synp \
  --project abstracts.synp \
  --database Quinto_Andar
Elementos da reificação
Elemento Origem Forma
Nó de identidade cada valor distinto de um campo IDENTIFIES (:Researcher {entity_id})
IDENTIFIED_AS o SOURCE proprietário (:Source)-[:IDENTIFIED_AS]->(:Researcher)
REFERS_TO cada valor de REFERS TO que casa (:Source)-[:REFERS_TO {entity, member}]->(:Researcher)

O nó nasce apenas do IDENTIFIES (uma referência órfã não cria nó); o casamento é exato, sem normalização de caixa; e bibrefs são qualificados pelo alias do membro (abstracts:@artigo_a), para que dois corpora não colapsem num só.

O backend HTML recusa multiprojeto

synesis-graph html com mais de um --project falha com erro explícito.

10 Fluxo típico

synesis compile projeto.synp --stats                           # 1. validar
synesis-graph html --project projeto.synp --output grafo.html  # 2. explorar
synesis-graph arcadedb-embedded --project projeto.synp         # 3. gravar o grafo
synesis-graph serve                                            # 4. perguntar

11 Consultas Cypher úteis

// Conceitos mais frequentes
MATCH (c)
WHERE c.mention_count IS NOT NULL
RETURN c.name, c.mention_count, c.source_count
ORDER BY c.mention_count DESC
LIMIT 10
// Achados transversais
MATCH (c)
WHERE c.source_count IS NOT NULL
RETURN c.name, c.source_count, c.mention_count
ORDER BY c.source_count DESC
LIMIT 10
// Evidência textual de um conceito
MATCH (s:Source)<-[:FROM_SOURCE]-(i:Item)-[:MENTIONS]->(c {name: "Custo"})
RETURN s.bibtex, i.citation
// Relações declaradas a partir de um conceito
MATCH (a {name: "Custo"})-[r:RELATES_TO]->(b)
RETURN a.name, r.type, b.name
// Evidência de um conceito e de todos os subtipos, sem contar duas vezes
MATCH (c {name: "phishing"})<-[:KIND_OF*0..]-(sub)<-[:MENTIONS]-(i:Item)
RETURN count(DISTINCT i)
// Grafo multiprojeto: fontes ligadas a um pesquisador
MATCH (r:Researcher)<-[:REFERS_TO]-(s:Source)
RETURN r.entity_id, collect(s.bibtex) AS fontes
