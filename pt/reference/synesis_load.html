1 Synesis: API em Memória (synesis.load)

Verificado com synesis 0.16.0

1.1 Introdução

A API synesis.load compila projetos Synesis diretamente em memória, sem arquivos em disco. É ideal para:

  • Jupyter Notebooks: análise interativa de dados qualitativos
  • Scripts Python: automação de pipelines de pesquisa
  • Integração com Pandas: exportação direta para DataFrames
  • Testes e prototipagem: validação rápida de anotações

1.1.1 Diferença entre CLI e API

Aspecto CLI (synesis compile) API (synesis.load)
Entrada Arquivos em disco Strings em memória
Saída Arquivos Dicts, tabelas, DataFrames
Uso Terminal, CI/CD Notebooks, scripts
I/O Leitura e escrita em disco Nenhuma

Para compilar um projeto que está em disco, use synesis.SynesisCompiler("projeto.synp").compile().

1.2 Instalação

pip install synesis
pip install pandas        # opcional, para os métodos de DataFrame

1.3 Quick Start

As strings começam na coluna 0

A indentação é significativa em Synesis. Uma string com todo o conteúdo recuado (comum em código Python) é um erro de sintaxe: escreva o texto na coluna 0 ou use textwrap.dedent.

import synesis

template = """
TEMPLATE Minimal

SOURCE FIELDS
    OPTIONAL date
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS

FIELD date TYPE DATE
    SCOPE SOURCE
END FIELD

FIELD quote TYPE QUOTATION
    SCOPE ITEM
END FIELD
"""

project = """
PROJECT Demo
    TEMPLATE "template.synt"
END PROJECT
"""

annotations = {
    "sample.syn": """
SOURCE @ref2024
    date: 2024-06-15
END SOURCE

ITEM @ref2024
    quote: A tecnologia mostra resultados promissores.
END ITEM
"""
}

bibliography = """
@article{ref2024,
    author = {Silva, Maria},
    title = {Estudo sobre Tecnologia},
    year = {2024}
}
"""

result = synesis.load(
    project_content=project,
    template_content=template,
    annotation_contents=annotations,
    bibliography_content=bibliography,
)

if result.success:
    print(f"Compilado: {result.stats.item_count} item(s)")
    print(result.to_dataframe("items"))
else:
    print(result.get_diagnostics())

1.4 Função synesis.load()

1.4.1 Assinatura

def load(
    project_content: str,
    template_content: str,
    annotation_contents: Optional[Dict[str, str]] = None,
    ontology_contents: Optional[Dict[str, str]] = None,
    bibliography_content: Optional[str] = None,
    dataset_index: Optional[Dict[str, Any]] = None,
    project_filename: str = "<project>",
    template_filename: str = "<template>",
    bibliography_contents: Optional[Dict[str, str]] = None,
    check_codes: bool = False,
) -> MemoryCompilationResult

1.4.2 Parâmetros

Parâmetro Tipo Obrigatório Descrição
project_content str Sim Conteúdo do .synp
template_content str Sim Conteúdo do .synt
annotation_contents Dict[str, str] Não {nome: conteúdo} dos .syn
ontology_contents Dict[str, str] Não {nome: conteúdo} dos .syno
bibliography_content str Não Conteúdo de um .bib
bibliography_contents Dict[str, str] Não Vários .bib, unidos na ordem do dicionário (não combine com o anterior)
dataset_index Dict Não Registros TOML já carregados, para campos ON DATASET
check_codes bool Não True: um aviso por ocorrência de código sem conceito (E004); False: um resumo (E090)
project_filename str Não Nome virtual nas mensagens de erro
template_filename str Não Nome virtual nas mensagens de erro

A função não lê o disco: os INCLUDE do projeto não são seguidos; o que entra é o que você passa.

1.4.3 Exemplo Completo

import synesis

project = """
PROJECT PesquisaQualitativa
    TEMPLATE "analysis.synt"
    INCLUDE BIBLIOGRAPHY "refs.bib"
    INCLUDE ANNOTATIONS "interviews.syn"
    INCLUDE ONTOLOGY "concepts.syno"
END PROJECT
"""

template = """
TEMPLATE QualitativeAnalysis

SOURCE FIELDS
    REQUIRED date
    OPTIONAL country
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
    OPTIONAL code
END ITEM FIELDS

ONTOLOGY FIELDS
    REQUIRED description
    OPTIONAL topic
END ONTOLOGY FIELDS

FIELD date TYPE DATE
    SCOPE SOURCE
END FIELD

FIELD country TYPE TEXT
    SCOPE SOURCE
END FIELD

FIELD quote TYPE QUOTATION
    SCOPE ITEM
END FIELD

FIELD note TYPE MEMO
    SCOPE ITEM
END FIELD

FIELD code TYPE CODE
    SCOPE ITEM
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        INFLUENCES: Relação de influência
        ENABLES: Relação de habilitação
    END RELATIONS
END FIELD

FIELD description TYPE TEXT
    SCOPE ONTOLOGY
END FIELD

FIELD topic TYPE TOPIC
    SCOPE ONTOLOGY
END FIELD
"""

annotations = """
SOURCE @silva2024
    date: 2024-03-15
    country: Brasil
END SOURCE

ITEM @silva2024
    quote: O custo é uma barreira significativa.
    note: Entrevistado identifica fator econômico
    chain: Cost -> INFLUENCES -> Adoption
END ITEM

ITEM @silva2024
    quote: A aceitação pública facilita a implementação.
    note: Relação entre fatores sociais e técnicos
    chain: Public_Acceptance -> ENABLES -> Implementation
END ITEM
"""

concepts = """
ONTOLOGY Cost
    description: Fator econômico de custo
    topic: Economics
END ONTOLOGY

ONTOLOGY Public_Acceptance
    description: Aceitação da comunidade
    topic: Social_Factors
END ONTOLOGY

ONTOLOGY Adoption
    description: Adoção de tecnologia
    topic: Technology
END ONTOLOGY

ONTOLOGY Implementation
    description: Implementação técnica
    topic: Technology
END ONTOLOGY
"""

bibliography = """
@article{silva2024,
    author = {Silva, João and Santos, Maria},
    title = {Fatores de Adoção Tecnológica},
    journal = {Revista Brasileira de Pesquisa},
    year = {2024}
}
"""

result = synesis.load(
    project_content=project,
    template_content=template,
    annotation_contents={"interviews.syn": annotations},
    ontology_contents={"concepts.syno": concepts},
    bibliography_content=bibliography,
)

if result.success:
    print(f"Sources: {result.stats.source_count}")
    print(f"Items: {result.stats.item_count}")
    print(f"Ontologies: {result.stats.ontology_count}")
    print(f"Chains: {result.stats.chain_count}")

Saída:

Sources: 1
Items: 2
Ontologies: 4
Chains: 2

Atributo Tipo Descrição

1.6 Métodos de Exportação

Método Retorna
to_json_dict() o JSON canônico (schema 3.1) como dicionário
to_csv_tables() {tabela: (cabeçalhos, linhas)}
to_dataframe(nome) um pandas.DataFrame
to_dataframes() todos os DataFrames
to_alpaca_pairs() pares instruction/input/output
to_okf_files(generated_at=None) {caminho: conteúdo} de um bundle OKF

1.6.1 to_json_dict()

data = result.to_json_dict()

data.keys()
# version, export_metadata, project, template,

for item in data["corpus"]:                       # uma entrada por ITEM

    print(item["traceability"])                   # arquivo e linha

data["ontology"]["Cost"]["frequency"]             # uso do conceito

import json
json_str = json.dumps(data, indent=2, ensure_ascii=False)
Seção Conteúdo
project nome, template, includes, metadados, descrição
template field_specs: cada campo com tipo, escopo, valores, relações e guidelines

1.7 Tabelas Disponíveis

As colunas derivam do template: cada campo do escopo vira uma coluna. Uma tabela só existe se houver campos (ou dados) para ela.

Tabela Colunas
sources bibref, os campos SOURCE, source_file, source_line, source_column
items bibref, os campos ITEM, source_file, source_line, source_column
ontologies uma coluna para cada campo CODE/CHAIN de ITEM (com o nome do conceito), os campos ONTOLOGY e a localização
chains bibref, from_code, relation, to_code, source_file, source_line, source_column

Com o template do exemplo acima:

sources     bibref, date, country, source_file, source_line, source_column
items       bibref, quote, note, code, chain, source_file, source_line, source_column
ontologies  code, chain, description, topic, source_file, source_line, source_column
chains      bibref, from_code, relation, to_code, source_file, source_line, source_column

Em cadeias simples (sem RELATIONS), não há relação nomeada.

1.9.2 Célula 2: Ler os arquivos do projeto

from pathlib import Path

base = Path("meu_projeto")
read = lambda p: p.read_text(encoding="utf-8")

result = synesis.load(
    project_content=read(base / "project.synp"),
    template_content=read(base / "template.synt"),
    annotation_contents={p.name: read(p) for p in base.glob("*.syn")},
    ontology_contents={p.name: read(p) for p in base.glob("*.syno")},
    bibliography_content=read(base / "references.bib"),
)

print(f"Sucesso: {result.success}")

1.10 Função compile_string()

Analisa um fragmento isolado, sem validação semântica.

def compile_string(content: str, filename: str = "<string>") -> List[Any]
nodes = synesis.compile_string("""
SOURCE @ref2024
    date: 2024-05-20
END SOURCE

ITEM @ref2024
    quote: Texto de exemplo.
END ITEM
""")

source, item = nodes
print(source.bibref)   # @ref2024
print(item.quote)      # Texto de exemplo.
Tipo de nó Bloco
SourceNode SOURCE
ItemNode ITEM
OntologyNode ONTOLOGY
ProjectNode PROJECT

O atributo quote do ItemNode só é preenchido por um campo chamado quote; para nomes livres, use item.entries, a lista das ocorrências escritas, ou synesis.semantic.occurrences.

1.11 Tratamento de Erros

1.11.1 Erros de Sintaxe

Levantam SynesisSyntaxError:

try:
    result = synesis.load(
        project_content="PROJECT Broken",   # falta END PROJECT
        template_content=template,
    )
except Exception as e:
    print(f"Erro de sintaxe: {e}")

1.11.2 Erros de Validação

Ficam no resultado:

result = synesis.load(
    project_content=project,
    template_content=template,
    annotation_contents={"bad.syn": """
ITEM @inexistente
    quote: Sem SOURCE correspondente
    note: x
    chain: Cost -> INFLUENCES -> Adoption
END ITEM
"""},
)

if not result.success:
    print(result.get_diagnostics(verbose=False))

As mensagens são em inglês:

=== ERRORS ===
[!] ITEM `@inexistente` has no matching SOURCE in this file
