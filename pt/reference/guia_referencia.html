1 Synesis: Guia de Referência da Linguagem

Linguagem 1.1 · verificado com o compilador synesis 0.16.0

1.1 Introdução

1.1.1 Definição

Synesis é uma Domain-Specific Language (DSL) declarativa para formalização, validação e compilação de corpora analíticos de pesquisas qualitativas. O compilador transforma anotações interpretativas em estruturas canônicas, assegurando inteligibilidade humana e rigor formal.

1.1.2 O que o Compilador Faz

  • Valida sintaxe e semântica de anotações
  • Gera AST (Abstract Syntax Tree)
  • Produz formatos estruturados: JSON, CSV, Excel, JSONL (Alpaca), bundle OKF e vocabulário SKOS
  • Valida e normaliza conceitos conforme templates configuráveis

1.1.3 O que o Compilador NÃO Faz

  • Não é runtime ou sistema de execução
  • Não realiza análise estatística
  • Não gerencia interface de usuário
  • Não persiste estado entre execuções
  • Não cria a estrutura dos dados para você
  • Não julga a validade teórica das relações: confere a forma, não a leitura

1.1.4 Fronteiras Rígidas

O compilador processa arquivos de texto, produz artefatos estruturados e termina. Não há estado persistente, loops condicionais ou side-effects além da escrita de arquivos de saída.

1.2 Instalação e linha de comando

Requer Python 3.10 ou superior.

pip install synesis
synesis --version
Comandos do compilador
Comando O que faz
synesis init cria um projeto mínimo na pasta atual
synesis compile <projeto.synp>… valida e compila; com dois ou mais projetos, faz a ligação
synesis export <projeto.synp> [bloco] executa os blocos EXPORT do projeto
synesis check <arquivo> confere só a sintaxe de um arquivo
synesis validate-template <template.synt> confere a estrutura de um template
synesis help-field [TIPO] mostra o que um tipo de campo exige, aceita ou proíbe
synesis export-snippets gera snippets de editor a partir das regras da linguagem
Opções de compile
Opção de compile Efeito
--json <arquivo> exporta o JSON canônico (schema 3.1)
--csv <pasta> exporta as tabelas CSV
--xls <arquivo> exporta uma planilha Excel
--alpaca <arquivo> exporta JSONL para ajuste fino de modelos
--okf <pasta> exporta um bundle OKF (experimental); a pasta deve ser nova ou vazia
--okf-generated-at <ISO> data gravada no OKF (omitida por padrão)
--stats mostra o resumo e o perfil estrutural
--check-codes lista cada código sem conceito na ontologia
--strict trata avisos como erros (liga --check-codes)
--force gera os artefatos mesmo com erros
--diagnostics-json <arquivo> grava todos os diagnósticos em JSON, mesmo quando há erros

synesis export aceita --check-codes, --force e --publish (SKOS: registra os IRIs publicados).

Para consultar a linguagem pelo terminal há o pacote synesis-help: synesis-help lookup CHAIN, synesis-help search bundle.

1.3 Arquivos e Formatos

1.3.1 Arquivos de Entrada

Extensão Descrição
.synp Arquivo de projeto (ponto de entrada único)
.syn Arquivos de anotação (SOURCE + ITEM)
.syno Arquivos de ontologia (ONTOLOGY)
.synt Arquivo de template (definições FIELD)
.bib Referências BibTeX/BibLaTeX
.toml Registros de dataset (INCLUDE DATASET)

Os arquivos .synr (propostas de revisão do synesis-coder) não fazem parte do projeto e não entram em nenhum INCLUDE.

1.3.2 Arquivos de Saída

Formato Como gerar Descrição
JSON --json ou EXPORT JSON representação completa do projeto, com a localização dos nós
CSV --csv ou EXPORT CSV tabelas sources, items, ontologies e chains
Excel --xls ou EXPORT XLS as mesmas tabelas como abas
Alpaca JSONL --alpaca ou EXPORT ALPACA pares instruction/input/output
OKF --okf ou EXPORT OKF pasta de Markdown legível por agentes (experimental)
SKOS EXPORT SKOS modelo organizador em Turtle
Diagnósticos --diagnostics-json erros, avisos e informativos com localização

1.3.3 Rastreabilidade

Todas as saídas gravam caminhos relativos à pasta do .synp, com barras normais. Duas cópias do mesmo projeto produzem o mesmo resultado (o JSON só difere no horário de exportação). Um arquivo fora da pasta (INCLUDE SHARED) aparece com ../.

Cada linha CSV inclui colunas de localização:

bibref,from_code,relation,to_code,source_file,source_line,source_column
'@silva2024,Cost,INHIBITS,Trust,annotations.syn,6,5

O apóstrofo antes de @silva2024 é proposital: o compilador protege células que começam com =, +, - ou @, para que uma planilha não as execute como fórmula. Remova-o ao processar o CSV em outra ferramenta.

1.3.4 Invariantes do Compilador

  1. Compilação determinística: mesma entrada produz mesma saída
  2. Erros reportados com arquivo, linha, coluna e contexto, em inglês
  3. Compilação com erros emite apenas diagnósticos; não exporta (salvo com --force)
  4. Validação de referências bibliográficas quando o projeto declara INCLUDE BIBLIOGRAPHY
  5. Vocabulário controlado: todo código usado em campo CODE ou em cadeia deve existir como ONTOLOGY. Um código sem conceito é um aviso; use --strict para tratá-lo como erro

1.4 Estrutura do Projeto (.synp)

O arquivo de projeto orquestra os componentes da análise e serve como ponto de entrada único para o compilador.

1.4.1 Sintaxe

PROJECT project_name

    TEMPLATE "filename.synt"
    [INCLUDE BIBLIOGRAPHY "filename.bib"]
    [INCLUDE ANNOTATIONS "arquivo, pasta ou padrão"]
    [INCLUDE ONTOLOGY "arquivo, pasta ou padrão"]
    [INCLUDE SHARED ONTOLOGY "../compartilhado/vocabulario.syno"]
    [INCLUDE DATASET "registros/*.toml"]

    [METADATA
        version: 1.0
        author: string
        [created: date]
        [modified: date]
        [dataset: string]
    END METADATA]

    [DESCRIPTION
    Texto livre descrevendo o projeto (no mesmo recuo da palavra DESCRIPTION).
    END DESCRIPTION]

    [QUESTIONS
        Q1: Pergunta que o projeto precisa responder
    END QUESTIONS]

    [PHASE ONTOLOGY nome
        FIELDS campo
    END PHASE]

    [EXPORT formato nome
        OUTPUT "caminho"
    END EXPORT]

END PROJECT

Os colchetes indicam partes opcionais; não fazem parte da sintaxe.

1.4.2 Semântica

  • PROJECT: palavra-chave obrigatória que inicia a definição do projeto
  • TEMPLATE: o arquivo .synt que define as regras de validação (obrigatório)
  • INCLUDE: declara os arquivos do projeto. Nada é carregado por descoberta: o que não é declarado não entra na análise
  • METADATA: metadados do projeto
  • DESCRIPTION: descrição livre, que acompanha as exportações. As linhas de texto ficam no mesmo recuo de DESCRIPTION; um recuo maior é erro de sintaxe
  • QUESTIONS, PHASE, EXPORT: veja O Modelo Organizador e Blocos EXPORT

Os itens do PROJECT devem estar todos no mesmo nível: ou todos recuados, ou todos na coluna 0.

1.4.3 INCLUDE: arquivos, pastas e padrões

Todos os INCLUDE aceitam um arquivo, uma pasta ou um padrão (curinga), e várias linhas do mesmo tipo se somam. Uma pasta é percorrida recursivamente pela extensão do tipo (.bib, .syn, .syno, .toml).

PROJECT corpus
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "Sources"
    INCLUDE BIBLIOGRAPHY "extra.bib"
    INCLUDE ANNOTATIONS "annotations_*/*.syn"
    INCLUDE ONTOLOGY "ontologia"
END PROJECT
  • Um .syn ou .syno presente na pasta do projeto e não declarado é erro (E061, E062).
  • Um .syn ou .syno vazio, ou só com comentários, é válido.
  • A mesma chave em dois arquivos .bib (ou .toml) é erro (E089).

Todos os caminhos são resolvidos relativos à pasta do .synp. Por segurança, o compilador só lê arquivos dessa pasta e de suas subpastas; um caminho que escape produz E075.

1.4.4 Ontologia compartilhada

INCLUDE SHARED ONTOLOGY é a única exceção à regra de contenção. Ela permite que vários projetos de um mesmo estudo usem um único vocabulário conceitual sem duplicá-lo:

PROJECT membro
    TEMPLATE "template.synt"
    INCLUDE SHARED ONTOLOGY "../compartilhado/vocabulario.syno"
END PROJECT

A autorização mora na declaração — a palavra SHARED, versionada e auditável no .synp — e não na geometria do caminho. Por isso aceita rede (\\servidor\...), outro drive (Z:/...) ou ...

SHARED vale apenas para ONTOLOGY

INCLUDE SHARED BIBLIOGRAPHY ou INCLUDE SHARED ANNOTATIONS produzem o erro E084.

1.5 Definição de Template (.synt)

O template define a estrutura e as regras de validação das anotações.

1.5.1 Cabeçalho do Template

TEMPLATE qualitative_analysis version: "1.0" author: "Researcher"

O cabeçalho é opcional. Quando presente, os metadados vão na mesma linha do nome: em linha própria, o template não compila.

1.5.2 Blocos de Campos

Cada escopo tem no máximo um bloco, que diz quais campos se aplicam e com que rigor:

SOURCE FIELDS | ITEM FIELDS | ONTOLOGY FIELDS
    [REQUIRED campo [, campo]]
    [OPTIONAL campo [, campo]]
    [FORBIDDEN campo [, campo]]
    [REQUIRED BUNDLE campo, campo [, campo]]
    [OPTIONAL BUNDLE campo, campo [, campo]]
    [REQUIRED | OPTIONAL campo ON BIBLIOGRAPHY]
    [REQUIRED | OPTIONAL campo ON DATASET "caminho.no.registro"]
END SOURCE FIELDS | END ITEM FIELDS | END ONTOLOGY FIELDS

ON BIBLIOGRAPHY e ON DATASET valem apenas em SOURCE FIELDS e em cláusulas de um único campo.

1.5.3 Exemplo Completo

TEMPLATE qualitative_analysis version: "1.0" author: "Researcher"

# ============================================
# CAMPOS DE SOURCE
# ============================================

SOURCE FIELDS
    OPTIONAL access_date
END SOURCE FIELDS

FIELD access_date TYPE DATE
    SCOPE SOURCE
    DESCRIPTION Data de acesso à fonte
END FIELD

# ============================================
# CAMPOS DE ITEM
# ============================================

ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
    OPTIONAL code
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Excerto textual extraído da fonte
END FIELD

FIELD note TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Memo analítico explicando a interpretação e o mecanismo causal identificado
END FIELD

FIELD code TYPE CODE
    SCOPE ITEM
    DESCRIPTION Conceitos de que o excerto é evidência
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    DESCRIPTION Cadeia causal/relacional entre conceitos da ontologia
    RELATIONS
        ENABLES: Condição necessária ou facilitadora (A permite que B ocorra)
        INFLUENCES: Efeito causal direto (A afeta ou muda B)
        CONSTRAINS: Limita ou restringe (A reduz opções ou viabilidade de B)
        CONTESTED-BY: Oposição ativa (A é contestado ou desafiado por B)
        RELATES-TO: Associação significativa genérica (A está relacionado a B)
    END RELATIONS
END FIELD

# ============================================
# CAMPOS DE ONTOLOGY
# ============================================

ONTOLOGY FIELDS
    REQUIRED description
    OPTIONAL topic
END ONTOLOGY FIELDS

FIELD description TYPE TEXT
    SCOPE ONTOLOGY
    DESCRIPTION Definição textual do conceito
END FIELD

FIELD topic TYPE TOPIC
    SCOPE ONTOLOGY
    DESCRIPTION Tópico ou domínio temático do conceito
END FIELD

Todo campo definido precisa estar listado em um bloco FIELDS (E042), e todo campo listado precisa de um FIELD (E039) com o mesmo escopo (E006).

Comentários começam com #. Dentro de um bloco GUIDELINES o # não é comentário: a linha faz parte da instrução enviada à IA.

1.6 Definição de Campos (FIELD)

A declaração FIELD especifica o tipo, o escopo e as restrições de cada campo.

1.6.1 Sintaxe

FIELD nome TYPE tipo
    SCOPE SOURCE | ITEM | ONTOLOGY
    [DESCRIPTION texto de uma linha]

    [ARITY operador número]          # somente CHAIN (obrigatório)
    [RELATIONS                       # somente CHAIN
        NOME: descrição
    END RELATIONS]

    [VALUES                          # somente ORDERED e ENUMERATED (obrigatório)
        [índice] valor: descrição    # ORDERED: com [índice]
        valor: descrição             # ENUMERATED: sem índice
    END VALUES]

    [FORMAT [mín..máx]]              # somente SCALE (obrigatório)

    [IDENTIFIES entidade]            # somente SCOPE SOURCE
    [REFERS TO entidade]             # somente SCOPE SOURCE

    [ROLE família [espécie]]         # somente SCOPE ONTOLOGY

    [CONTEXT FROM DATASET "seção"]   # qualquer tipo
    [GUIDELINES                      # qualquer tipo
        Instruções de preenchimento.
    END GUIDELINES]
END FIELD

1.6.2 Exemplo Completo de FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    DESCRIPTION Cadeia causal entre conceitos
    ARITY >= 2
    RELATIONS
        INFLUENCES: Relação de influência causal
        ENABLES: Relação de habilitação
        INHIBITS: Relação de inibição
    END RELATIONS
END FIELD

FIELD aspect TYPE ORDERED
    SCOPE ONTOLOGY
    DESCRIPTION Aspecto modal de Dooyeweerd
    VALUES
        [1] quantitative: Aspecto numérico
        [2] spatial: Aspecto espacial
        [3] kinematic: Aspecto cinético
        [4] physical: Aspecto físico
        [5] biotic: Aspecto biótico
    END VALUES
END FIELD

FIELD sentiment TYPE ENUMERATED
    SCOPE ITEM
    DESCRIPTION Sentimento expresso no excerto
    VALUES
        positive: Sentimento positivo
        negative: Sentimento negativo
        neutral: Sentimento neutro
    END VALUES
END FIELD

FIELD confidence TYPE SCALE
    SCOPE ITEM
    DESCRIPTION Nível de confiança da interpretação
    FORMAT [1..5]
END FIELD

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Excerto textual extraído da fonte
    GUIDELINES
        Extract the exact verbatim quote from the source text.
        Do not paraphrase or summarize — preserve the original wording.
        Include enough context for the quote to be self-explanatory.
        Omit only if the passage is not quotable (e.g., tables, figures).
    END GUIDELINES
END FIELD

1.6.3 Bloco GUIDELINES

GUIDELINES é um especificador opcional, aceito em qualquer FIELD. Seu conteúdo é texto livre com instruções sobre como o campo deve ser preenchido, destinado a agentes de IA ou anotadores humanos. DESCRIPTION diz o que o campo é; GUIDELINES diz como preenchê-lo bem.

1.6.3.1 Propósito

GUIDELINES transforma o template de um esquema de dados em um protocolo de codificação:

  • Instrução por campo: a IA recebe regras específicas para cada campo, reduzindo ambiguidade
  • Rastreabilidade de decisões: as regras ficam no template, versionadas e auditáveis
  • Ciclo de correção: a IA gera blocos Synesis → o compilador valida → os erros servem de instrução de correção

O synesis-coder avisa quando um campo não tem GUIDELINES; com --require-guidelines, o aviso vira erro.

1.6.3.2 Semântica

  • O conteúdo é texto livre; o compilador não o interpreta nem valida
  • Múltiplas linhas são preservadas, e o recuo interno é removido
  • Um bloco vazio resulta em null no JSON
  • O valor compilado é exportado no campo "guidelines" de cada especificação de campo no JSON

1.6.3.3 O que funciona na prática

  • Pares Correto/Errado, um por decisão que o codificador vai enfrentar
  • Testes em uma frase (“Teste: todo A é um B?”)
  • Dizer a unidade de cada valor (“um estatuto por cadeia”)
FIELD note TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Memo analítico do mecanismo causal identificado
    GUIDELINES
        Identify the causal mechanism linking the quote to the research question.
        State the mechanism in one sentence: "[Factor] [verb] [outcome] because [reason]."
        Ground the interpretation in the text — do not infer beyond what is stated.
        If causality is ambiguous, describe the relationship as associative.
    END GUIDELINES
END FIELD

1.6.4 Função dos campos de ontologia: ROLE

Em campos SCOPE ONTOLOGY, ROLE declara a função do valor no modelo organizador: rótulo (LABEL PREFERRED|ALTERNATIVE|HIDDEN), nota (NOTE DEFINITION|USAGE|EXAMPLE|COUNTEREXAMPLE), hierarquia (HIERARCHY KIND|PART|INSTANCE) ou nome preterido (USE). A tabela completa está em O Modelo Organizador.

1.7 Tipos de Campo

1.7.1 Tabela de Tipos

Tipo Semântica Forma do valor Exige
QUOTATION Excerto textual da fonte texto —
MEMO Anotação analítica do pesquisador texto —
TEXT Texto livre genérico texto —
CODE Rótulo conceitual (categorização) conceitos separados por vírgula —
CHAIN Relação entre conceitos A -> B ou A -> REL -> B ARITY
TOPIC Agrupamento dinâmico um termo sem espaços —
ENUMERATED Valor de lista fechada sem ordem um dos valores, com a mesma grafia VALUES
ORDERED Valor de lista fechada com ordem o índice da opção VALUES com [índice]
SCALE Número em um intervalo número FORMAT
DATE Data texto (o formato não é conferido) —

Os três escopos aceitam os mesmos tipos. A única assimetria é deliberada: IDENTIFIES e REFERS TO só existem em SCOPE SOURCE, e ROLE só em SCOPE ONTOLOGY. Use synesis help-field <TIPO> para ver a matriz de propriedades de cada tipo.

1.7.2 ORDERED: grave o índice

Em um campo ORDERED, o dado é a posição; o rótulo é exibição (o editor o mostra ao lado do índice).

ONTOLOGY Cost
    aspect: 4
END ONTOLOGY

Escrever o rótulo (aspect: physical) produz E088, com o índice a usar.

1.7.3 Distinção: Linguagem vs Template

Nível FIXO (linguagem) CONFIGURÁVEL (template)
Palavras-chave SOURCE, ITEM, ONTOLOGY, FIELD, END Nomes de campos como aspect, quote
Tipos de dados QUOTATION, MEMO, CODE, CHAIN, TEXT etc. Valores em listas ORDERED/ENUMERATED
Estrutura Blocos SOURCE/ITEM/ONTOLOGY, sintaxe FIELD…END Quais campos são REQUIRED/OPTIONAL
Modificadores BUNDLE, REQUIRED, OPTIONAL, SCOPE, TYPE Quais campos formam um BUNDLE

As palavras-chave não diferenciam maiúsculas de minúsculas.

1.8 Blocos Estruturais

1.8.1 SOURCE

Unidade de proveniência: de onde vem a informação. Cada SOURCE referencia uma entrada do .bib (ou um registro de dataset).

SOURCE @smith2023
    access_date: 2025-01-15
END SOURCE

ITEM @smith2023
    quote: "The technology shows promising results."
    note: Autor expressa otimismo sobre resultados
    chain: Technology -> INFLUENCES -> Acceptance
END ITEM

O corpo do SOURCE é opcional quando o template não exige campos. Um mesmo @bibref não pode abrir dois blocos SOURCE no mesmo arquivo, e todo ITEM precisa de um SOURCE com o mesmo @bibref no mesmo arquivo.

1.8.2 ITEM

Unidade analítica fundamental. Contém excertos, memos, códigos e cadeias. Pertence a exatamente um SOURCE.

ITEM @ref2025
    quote: Texto extraído

    note: Primeira interpretação
    chain: A -> INFLUENCES -> B

    note: Segunda interpretação
    chain: C -> ENABLES -> D
END ITEM

1.8.3 ONTOLOGY

Define um conceito do vocabulário controlado.

ONTOLOGY Cost
    topic: Economics
    description: Economic factor representing financial expenditure
END ONTOLOGY

ONTOLOGY Public_Acceptance
    topic: Social_Factors
    description: Community-level support for technology
END ONTOLOGY

Use nomes sem espaços (um conceito com espaços não pode ser citado em cadeias). A comparação entre o código usado e o conceito ignora maiúsculas e minúsculas. Dois blocos para o mesmo conceito são erro (E068).

1.8.4 Valores de várias linhas

Um valor pode continuar nas linhas seguintes, com recuo maior que o do nome do campo. As duas formas abaixo são equivalentes:

ITEM @smith2023
    quote: A primeira linha do excerto
        e a sua continuação.
    note:
        Um memo que começa na linha seguinte
        e ocupa duas linhas.
END ITEM

A continuação vale para texto, listas de códigos e cadeias. (Entre as versões 0.13.4 e 0.15.0, as linhas de continuação eram descartadas sem aviso; atualize para 0.16.0 ou superior.)

1.9 Códigos e vocabulário controlado

Um campo CODE recebe um ou mais conceitos, separados por vírgula ou em linhas repetidas:

ITEM @smith2023
    quote: Texto
    code: Climate_Belief, Risk_Perception
    code: Trust
END ITEM

Quando um código não tem bloco ONTOLOGY, o compilador emite por padrão uma única linha de resumo no .synp (E090) — útil antes de a ontologia existir. Para ver cada ocorrência, com sugestão do conceito mais próximo (E004):

synesis compile project.synp --check-codes

1.10 Cadeias Semânticas (CHAIN)

1.10.1 Chain Qualificada

Quando o campo define RELATIONS, a cadeia alterna conceitos e relações:

ITEM @smith2023
    chain: Climate_Belief -> INFLUENCES -> Support
    chain: A -> INFLUENCES -> B -> ENABLES -> C
END ITEM

1.10.2 Chain Simples

Quando o campo não define RELATIONS, só há conceitos; a relação é implícita.

ITEM @smith2023
    chain: A -> B
    chain: A -> B -> C
END ITEM

1.10.3 Aridade

ARITY é obrigatório em todo campo CHAIN e conta conceitos: ARITY >= 2 aceita uma ligação; ARITY >= 3 exige um mediador (antecedente → mediador → resultado). Os operadores são >=, >, <=, < e =.

1.10.4 Conceitos sem aspas

Conceitos compostos não levam aspas, mas não podem ter espaços.

Anotação incorreta (E015):

chain: Institutional Barrier -> ENABLES -> Financial Barrier

Anotação correta:

chain: Public_Acceptance -> INFLUENCES -> CCS_Support -> ENABLES -> Deployment

Uma relação não pode ter o mesmo nome de um conceito (E014).

1.11 Modificador BUNDLE

BUNDLE define grupos de campos que formam uma unidade repetível de interpretação.

ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
    OPTIONAL BUNDLE page, section
END ITEM FIELDS

1.11.1 Semântica

  • REQUIRED BUNDLE: ao menos uma ocorrência completa do grupo
  • OPTIONAL BUNDLE: o grupo pode faltar por inteiro; se um membro aparece, todos precisam aparecer
  • Os membros aparecem em igual quantidade: len(campo1) == len(campo2)
  • Correspondência posicional: campo1[i] se relaciona com campo2[i]
ITEM @ref2025
    quote: Texto extraído da fonte

    note: Primeira interpretação
    chain: A -> INFLUENCES -> B

    note: Segunda interpretação
    chain: C -> ENABLES -> D
END ITEM

Membro ausente produz E016; contagens diferentes, E017; bundle de um campo só, E018.

Um uso importante é qualificar uma afirmação: chain, status (afirmada, hipotética, negada) e justification no mesmo bundle, para que uma hipótese não apareça como achado nas exportações.

1.12 Tipo TOPIC

TOPIC define categorias que agrupam conceitos de forma dinâmica, sem lista pré-definida no template.

Característica ENUMERATED TOPIC
Valores permitidos Lista fechada pré-definida Aberto, dinâmico
Uso Categorização controlada Agrupamento emergente
Validação Rejeita valores fora da lista Qualquer termo sem espaços 
ONTOLOGY Cost
    topic: Economics
    description: Economic factor representing financial expenditure
END ONTOLOGY

ONTOLOGY Public_Acceptance
    topic: Social_Factors
    description: Community-level support for technology
END ONTOLOGY

1.13 Ligação entre Projetos (IDENTIFIES / REFERS TO)

Permite triangular corpora heterogêneos — currículos, abstracts, perfis institucionais — sem transformá-los numa única unidade de compilação. Cada projeto continua independente; a ligação é declarada no template e resolvida num passo explícito na linha de comando.

O modelo é o do linker de C/C++: cada projeto compila isolado e expõe suas referências externas; um passo de ligação (synesis compile p1.synp p2.synp) resolve as referências entre eles e produz o agregado.

1.13.1 Os dois modificadores

Modificador Papel relacional Semântica
IDENTIFIES <entidade> Chave primária O campo identifica a entidade. Cada valor corresponde a um único SOURCE.
REFERS TO <entidade> Chave estrangeira O campo aponta para a entidade. Pode repetir.

Ambos são exclusivos de campos SCOPE SOURCE; em outro escopo produzem E078.

1.13.2 Sintaxe

O projeto proprietário da entidade declara a chave primária:

# lattes.synt — o corpus de currículos é dono da entidade "researcher"
FIELD lattes_id TYPE TEXT
    SCOPE SOURCE
    DESCRIPTION Identificador Lattes do pesquisador
    IDENTIFIES researcher
END FIELD

Os projetos periféricos apontam para ela:

# abstracts.synt — cada artigo aponta para o pesquisador que o escreveu
FIELD autor_id TYPE TEXT
    SCOPE SOURCE
    DESCRIPTION Identificador Lattes do autor
    REFERS TO researcher
END FIELD

O projeto periférico não nomeia o proprietário, apenas o rótulo da entidade. Acrescentar um terceiro corpus não exige editar os templates existentes.

1.13.3 Origem do valor: ON BIBLIOGRAPHY

Alguns identificadores são metadados da fonte, não conteúdo extraível do texto. ON BIBLIOGRAPHY declara que o valor vive na entrada .bib do SOURCE:

SOURCE FIELDS
    REQUIRED lattes_id ON BIBLIOGRAPHY
    OPTIONAL orcid ON BIBLIOGRAPHY
END SOURCE FIELDS
@misc{curriculo_maria,
    author    = {Silva, Maria},
    title     = {Currículo Lattes},
    year      = {2026},
    lattes_id = {3474000000000167}
}

O sufixo só é válido em cláusula de campo único: REQUIRED a, b ON BIBLIOGRAPHY é erro de sintaxe. Esses campos não são cobrados no bloco SOURCE; se o valor faltar no .bib, o erro é E079.

1.13.4 Compilação isolada

Um projeto com REFERS TO compila normalmente sozinho. O compilador emite apenas o informativo I080:

synesis compile abstracts.synp --json abstracts.json
abstracts.synt:11:1  [INFO]  External reference `researcher` (REFERS TO in autor_id) — not materialized in isolation

1.13.5 Passo de ligação

synesis compile lattes.synp abstracts.synp --json estudo.json --csv saida/

O passo de ligação:

  1. Compila cada membro isoladamente (validação completa)
  2. Resolve cada REFERS TO contra o IDENTIFIES proprietário, por rótulo de entidade + igualdade exata do valor
  3. Gera uma aresta por casamento (n:1 e n:n; um campo multivalorado gera uma aresta por valor)
  4. Qualifica os bibrefs pelo alias do membro (abstracts:@artigo_a), evitando colisões

Um erro em qualquer membro aborta a ligação.

O compilador nunca funde entidades

A comparação é por igualdade exata depois de remover espaços nas pontas, sem normalizar maiúsculas e minúsculas. Um valor que casaria apenas sob normalização vira aviso de quase-casamento (W083).

1.13.6 Saídas do agregado

Opção Comportamento no passo de ligação
--json agregado no schema 3.1: kind: "link", entity_owners, seção links com arestas e órfãos
--csv gera links.csv com as arestas resolvidas
--xls aqui indica uma pasta: um .xlsx por membro e links.xlsx
--stats estatísticas por membro e agregadas (ontologia compartilhada não é somada em dobro)
--alpaca, --okf sem exportador no agregado: o compilador avisa
--diagnostics-json ainda não suportado: o compilador avisa
O editor nunca carrega o agregado

A ligação é exclusiva da linha de comando. O servidor de linguagem trabalha com projetos isolados, o que mantém a edição rápida.

Veja o guia Como Ligar Projetos Independentes.

1.14 Campos Proibidos (FORBIDDEN)

FORBIDDEN declara, num bloco FIELDS, um campo do mesmo escopo que não pode ter valor naquele bloco. Serve, por exemplo, para um template derivado que mantém a definição de um campo mas não quer que ele seja preenchido.

ITEM FIELDS
    REQUIRED quote, code
    FORBIDDEN note
END ITEM FIELDS

Um bloco que preenche o campo proibido produz o erro E021: Forbidden field 'note' in ITEM block — remove this line.

1.15 Valores de um Dataset (ON DATASET, INCLUDE DATASET, CONTEXT FROM DATASET)

Assim como ON BIBLIOGRAPHY traz o valor da entrada .bib, ON DATASET traz o valor de um registro TOML, um arquivo por registro. O valor não é digitado no .syn.

1.15.1 Declarar o dataset no projeto

PROJECT entrevistas
    TEMPLATE "template.synt"
    INCLUDE DATASET "registros/*.toml"
    INCLUDE ANNOTATIONS "anotacoes"
END PROJECT

1.15.2 Ligar cada registro a um SOURCE

Um campo de SCOPE SOURCE com IDENTIFIES e ON DATASET é a chave do registro: o valor nesse caminho do TOML deve ser igual ao bibref do SOURCE.

SOURCE FIELDS
    REQUIRED entrevista ON DATASET "entrevista.id"
    OPTIONAL regiao ON DATASET "entrevista.regiao"
END SOURCE FIELDS

FIELD entrevista TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES entrevista
END FIELD

FIELD regiao TYPE TEXT
    SCOPE SOURCE
END FIELD
# registros/s1.toml — associado ao SOURCE @s1
[entrevista]
id = "s1"
regiao = "Nordeste"
  • A string depois de ON DATASET é um caminho dentro do registro (notação de ponto), não o nome do arquivo.
  • O sufixo só vale em cláusula de campo único.
  • No JSON compilado, os valores ficam na seção dataset, indexados pelo bibref.
  • Um campo REQUIRED … ON DATASET sem valor no registro produz E085.

1.15.3 Contexto para a codificação: CONTEXT FROM DATASET

CONTEXT FROM DATASET é uma propriedade do bloco FIELD, irmã de GUIDELINES. Ela não dá valor ao campo: indica as seções do registro TOML que o synesis-coder envia ao modelo como contexto ao gerar aquele campo.

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    CONTEXT FROM DATASET "entrevista"
    GUIDELINES
        Copie de uma a três frases contínuas, palavra por palavra.
    END GUIDELINES
END FIELD

Várias seções se separam por vírgula: CONTEXT FROM DATASET "recorte", "texto".

1.16 Blocos EXPORT

Cada bloco EXPORT do .synp declara um artefato. synesis export projeto.synp executa todos; synesis export projeto.synp json executa os de um formato (ou o de um nome). Caminhos de OUTPUT partem da pasta do .synp.

Formato Obrigatório Opcional
JSON, OKF OUTPUT GENERATED_AT
CSV, XLS OUTPUT —
ALPACA OUTPUT INSTRUCTION, MAP <campos> TO …
SKOS OUTPUT, NAMESPACE, LANGUAGE GENERATED_AT, MIN_SOURCES, ALIAS_LABEL, REGISTRY, MAP RELATIONS …

Um erro em um bloco impede só aquele artefato; na compilação, aparece como aviso. Um erro do projeto impede todos (salvo --force). A exportação SKOS está descrita em O Modelo Organizador.

1.16.1 Exportação Alpaca (EXPORT ALPACA)

EXPORT ALPACA grava um JSONL para ajuste fino de modelos de linguagem. Cada linha tem instruction, input e output, as três como texto.

  • Sem MAP nem INSTRUCTION: o compilador escolhe pares embutidos. Eles não levam o qualificador de um BUNDLE que contém uma CHAIN (por exemplo, o estatuto epistêmico), e uma hipótese sai como se fosse afirmação. O informativo I167 diz isso.
  • Com MAP <campos> TO INSTRUCTION | INPUT | OUTPUT (synesis ≥ 0.16): o pesquisador declara quais campos formam cada chave.
PROJECT estudo
    TEMPLATE "template.synt"

    EXPORT ALPACA mecanismo
        OUTPUT "saida/mecanismo.jsonl"
        INSTRUCTION Identifique a relação causal e como o texto a apresenta.
        MAP trecho TO INPUT
        MAP chain, estatuto, justificativa TO OUTPUT
    END EXPORT

    EXPORT ALPACA zona
        OUTPUT "saida/zona.jsonl"
        INSTRUCTION Classifique a zona retórica do trecho.
        MAP trecho TO INPUT
        MAP zona TO OUTPUT
    END EXPORT
END PROJECT

Uma linha por quê. Um BUNDLE no mapa define as linhas: uma por ocorrência do bundle. Os campos fora dele são contexto, repetido inteiro em cada linha do ITEM, e nunca multiplicam linhas. Sem bundle, há uma linha por ITEM. No exemplo, um ITEM com duas cadeias gera duas linhas, ambas com o mesmo trecho.

Texto de uma chave. Um campo só gera o valor ("Resultado"). Vários campos geram um bloco rotulado por campo, na ordem do MAP:

chain:
isca → EXPLORA → confiança
estatuto: Hipotética
justificativa:
O autor sugere a relação, mas não a testa.

A CHAIN entra com todas as triplas. Um campo sem valor numa linha fica fora do texto. Uma linha com todos os campos do OUTPUT vazios não é gravada. Só a duplicata exata das três chaves é removida.

Cartão do dataset. Ao lado do JSONL, <nome>.card.json registra a composição, os hashes do .synp e do template, as contagens (linhas, vazias, ITEMs sem o bundle, duplicatas), a contagem de cada valor dos ENUMERATED/ORDERED do OUTPUT e os campos que ficaram de fora.

Regras. Cada regra impede só este artefato:

  • No modo declarado, MAP <campos> TO OUTPUT é obrigatório (E158).
  • Há exatamente uma origem de instrução (E159).
  • Um campo do OUTPUT não pode estar também em INPUT ou INSTRUCTION (E162): a resposta vazaria no prompt.
  • Campos de dois bundles são recusados (E163).
  • Campos de ONTOLOGY e de SOURCE com ON BIBLIOGRAPHY ou ON DATASET ainda não são suportados (E164).

Deixar fora do mapa um qualificador do bundle (por exemplo, estatuto) é só informativo (I166).

1.17 Pipeline de Compilação

# Etapa Responsabilidade
1 Descoberta Ler o .synp, resolver caminhos, expandir pastas e padrões
2 Template Ler e validar o .synt
3 Bibliografia e dataset Carregar .bib e registros TOML
4 Parsing Analisar os .syno e .syn (parser LALR)
5 Transformação Converter as árvores em AST tipada
6 Validação semântica Referências, tipos, campos obrigatórios, bundles, cadeias, papéis
7 Ligação (linking) Associar ITEMs a SOURCEs, códigos e cadeias à ontologia; construir índices
8 Exportação Gerar os artefatos pedidos 
Projeto = Template + Bibliografia/Dataset + Anotações + Ontologia

a.syn:4:1  [ERROR]  Bundle (note, chain) with unequal counts: note=2, chain=1

1.20 Apêndice A: Sintaxe Consolidada

1.20.1 Projeto (.synp)

PROJECT project_name
    TEMPLATE "filename.synt"
    INCLUDE BIBLIOGRAPHY "filename.bib"
    INCLUDE ANNOTATIONS "annotations"
    INCLUDE ONTOLOGY "filename.syno"

    METADATA
        version: 1.0
        author: Research team
    END METADATA

    DESCRIPTION
    Texto livre descrevendo o projeto.
    END DESCRIPTION

    QUESTIONS
        Q1: Quais barreiras são relatadas?
    END QUESTIONS

    EXPORT JSON
        OUTPUT "out/projeto.json"
    END EXPORT
END PROJECT

1.20.2 Template (.synt)

TEMPLATE name version: "1.0"

ITEM FIELDS
    REQUIRED quote
    OPTIONAL chain
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Excerto literal
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: condição que possibilita
    END RELATIONS
    GUIDELINES
        Instruções de preenchimento.
    END GUIDELINES
END FIELD

1.20.3 Anotações (.syn)

SOURCE @bibref
END SOURCE

ITEM @bibref
    quote: Trecho da fonte
    chain: A -> ENABLES -> B
END ITEM

1.20.4 Ontologia (.syno)

ONTOLOGY concept_name
    description: Definição do conceito
END ONTOLOGY
