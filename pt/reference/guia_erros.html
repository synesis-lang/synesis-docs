Guia de Erros

Todos os diagnósticos do compilador Synesis, com exemplo, mensagem e correção

A que versão esta página se refere

Os códigos, exemplos e mensagens abaixo foram verificados com o synesis 0.16.0. Cada exemplo foi compilado, e a mensagem mostrada é a que o compilador produziu. Versões anteriores desta página usavam outra numeração.

1 Como usar este guia

Cada diagnóstico tem um código estável, no formato SYNESIS_E047. A letra indica a família: E (erro), W (aviso) e I (informativo). Alguns códigos E aparecem como aviso; a severidade de cada um está na sua seção.

Severidade Efeito
erro interrompe a exportação: nenhum JSON, CSV ou planilha é gravado (salvo com --force)
erro local ao bloco EXPORT impede só o artefato daquele bloco
aviso a compilação prossegue; com --strict, avisos contam como erros
informativo apenas registra um fato

1.1 Formato das mensagens

As mensagens saem em inglês, em uma linha, com arquivo, linha e coluna. Os caminhos são relativos à pasta do .synp:

annotations.syn:15:1  [ERROR]  Unknown field `extra` in ITEM block

A linha de comando não imprime o código. Para vê-lo, há três caminhos:

synesis compile project.synp --diagnostics-json diagnostics.json   # relatório em JSON
synesis-help lookup E047                                            # a ficha de um código
synesis-help search "bundle"                                        # busca por assunto

No VS Code, o código acompanha o diagnóstico, com a explicação completa.

1.2 Opções que mudam o que aparece

Opção Efeito
--check-codes lista cada código sem conceito (E004) em vez do resumo (E090)
--strict trata avisos como erros; liga --check-codes
--force gera os artefatos mesmo com erros

2 Fontes e bibliografia

2.1 E001 — Referência não encontrada no .bib

Severidade: erro · Classe: UnregisteredSource

O @bibref de um bloco não corresponde a nenhuma chave do arquivo de bibliografia.

# annotations.syn
SOURCE @silvva2024
END SOURCE

ITEM @silvva2024
    quote: "text"
END ITEM
annotations.syn:1:1  [ERROR]  Reference `@silvva2024` not found in the .bib. Suggestions: `@silva2024`

Como corrigir: Confira a grafia da chave ou acrescente a entrada ao .bib. A mensagem sugere chaves parecidas quando existem.

2.2 E002 — ITEM sem SOURCE

Severidade: erro · Classe: OrphanItem

Há um ITEM cujo @bibref não tem um bloco SOURCE no mesmo arquivo.

# annotations.syn
ITEM @silva2024
    quote: "text"
END ITEM
annotations.syn:1:1  [ERROR]  ITEM `@silva2024` has no matching SOURCE in this file

Como corrigir: Crie o bloco SOURCE @chave no mesmo .syn, antes dos itens, ou corrija o @bibref do ITEM.

2.3 E003 — SOURCE sem ITEMs

Severidade: aviso · Classe: SourceWithoutItems

Uma fonte foi registrada, mas nenhum trecho dela foi analisado.

# annotations.syn
SOURCE @silva2024
END SOURCE
annotations.syn:1:1  [WARNING]  SOURCE `@silva2024` has no associated ITEM

Como corrigir: Acrescente ao menos um ITEM ou remova o SOURCE. É um aviso: a compilação prossegue.

2.4 E070 — SOURCE duplicada

Severidade: erro · Classe: DuplicateSourceBibref

O mesmo @bibref abre dois blocos SOURCE no mesmo arquivo.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "Cost limits adoption."
END ITEM

SOURCE @silva2024
END SOURCE
annotations.syn:8:1  [ERROR]  SOURCE `@silva2024` duplicated in this file

Como corrigir: Mantenha um único bloco SOURCE por referência; os ITEM podem ser quantos forem necessários.

2.5 E072 — Entrada BibTeX inválida

Severidade: erro · Classe: MalformedBibliographyEntry

Uma entrada do .bib não está em formato BibTeX válido.

% references.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}

@article{souza2023,
    author = {Souza, Bia},
    title = {Open brace
references.bib:1:1  [ERROR]  Entry `@article` in `references.bib` is not valid BibTeX

Como corrigir: Corrija a entrada indicada (chaves de abertura e fechamento, vírgulas entre campos).

2.6 E089 — Chave repetida entre arquivos

Severidade: erro · Classe: DuplicateKeyAcrossFiles

A mesma chave aparece em dois arquivos da bibliografia (ou do dataset). Vale a primeira ocorrência.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE BIBLIOGRAPHY "extra.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
% extra.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}
extra.bib:1:1  [ERROR]  Duplicate key `silva2024`: already defined in `references.bib:1`

Como corrigir: Decida qual registro é o correto e remova o outro.

3 Conceitos e modelo organizador

3.1 E004 — Código sem conceito

Severidade: aviso · Classe: UndefinedCode

Um código usado em um campo CODE ou em uma cadeia não tem bloco ONTOLOGY. A verificação por ocorrência é opcional: aparece com --check-codes ou --strict (veja E090).

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    code: Costs
END ITEM
# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY
annotations.syn:4:1  [WARNING]  Code `Costs` is not defined in the organizing model. Suggested fix -> `Cost`

Como corrigir: Defina o conceito em um arquivo .syno ou corrija a grafia do código. A mensagem sugere o conceito mais parecido.

3.2 E090 — Resumo dos códigos sem conceito

Severidade: aviso · Classe: UndefinedCodesSummary

Com a verificação por ocorrência desligada (o padrão), o compilador emite uma única linha com o total de códigos sem conceito.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    code: Costs, Trust
END ITEM
project.synp:1:1  [WARNING]  2 code(s) without a concept in the organizing model (2 occurrence(s)); use --check-codes to list them

Como corrigir: Use synesis compile --check-codes para listar cada ocorrência. Antes de a ontologia existir, este aviso é esperado.

3.3 E005 — ONTOLOGY sem ONTOLOGY FIELDS

Severidade: erro · Classe: OntologyWithoutTemplateFields

O projeto tem blocos ONTOLOGY, mas o template não declara quais campos eles aceitam.

# template.synt
TEMPLATE demo

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
END FIELD
# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY
project.synp:1:1  [ERROR]  Project has ONTOLOGY blocks but the template does not declare ONTOLOGY FIELDS

Como corrigir: Acrescente o bloco ONTOLOGY FIELDS ao template, com os respectivos FIELD.

3.4 E068 — Conceito duplicado

Severidade: erro · Classe: DuplicateOntologyConcept

Dois blocos ONTOLOGY definem o mesmo conceito (a comparação ignora maiúsculas e minúsculas), no mesmo arquivo ou em arquivos diferentes.

# ontology.syno
ONTOLOGY Cost
    definition: Cost.
END ONTOLOGY

ONTOLOGY cost
    definition: cost.
END ONTOLOGY
ontology.syno:5:1  [ERROR]  Concept `cost` duplicated in ontology.syno and ontology.syno

Como corrigir: Una as duas definições em um só bloco. Se forem conceitos distintos, renomeie um deles.

3.5 E103 — Nomes que colidem após normalização Unicode

Severidade: erro · Classe: IdentityCollision

Dois nomes parecem diferentes no arquivo (caracteres compostos e decompostos), mas têm a mesma identidade depois da normalização NFC.

ontology.syno:5:1  [ERROR]  Concepts `Café_Culture` and `Café_Culture` collide (same identity after Unicode normalization)

Como corrigir: Escreva o nome sempre da mesma forma; apague um dos blocos.

3.6 W071 — Definições idênticas

Severidade: aviso · Classe: DuplicateOntologyDescription

Dois conceitos têm a mesma descrição, sinal frequente de duplicata conceitual.

# ontology.syno
ONTOLOGY Cost
    description: Financial barrier.
END ONTOLOGY

ONTOLOGY Price
    description: Financial barrier.
END ONTOLOGY
ontology.syno:5:1  [WARNING]  Concepts `Cost` and `Price` have identical descriptions

Como corrigir: Diferencie as definições ou consolide os conceitos (veja ROLE USE).

4 Cadeias (CHAIN) e relações

Uma cadeia qualificada alterna conceitos e relações (A -> RELACAO -> B) e exige o bloco RELATIONS no template. Uma cadeia simples só tem conceitos (A -> B).

4.1 E007 — Aridade não atendida

Severidade: erro · Classe: ChainArityViolation

A cadeia tem menos conceitos do que o ARITY do campo exige.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 3
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Chain with 2 element(s), the template requires >= 3

Como corrigir: Complete a cadeia ou revise o ARITY no template.

4.2 E008 — Cadeia com relações em um campo sem RELATIONS

Severidade: erro · Classe: QualifiedChainWithoutRelations

A cadeia usa nomes de relação, mas o campo não declara RELATIONS. O compilador reconhece como relação um elemento intermediário escrito em maiúsculas.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Chain with named relations in `chain`, but the template defines no RELATIONS

Como corrigir: Declare RELATIONS no campo ou escreva a cadeia simples (A -> B).

4.3 E009 — Cadeia simples onde há relações obrigatórias

Severidade: erro · Classe: SimpleChainWithRelationsRequired

O campo declara RELATIONS, mas a cadeia não nomeia a relação.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Simple chain in `chain` but the template requires named relations

Como corrigir: Intercale uma relação declarada entre os conceitos.

4.4 E010 — Relação não declarada

Severidade: erro · Classe: InvalidChainRelation

A cadeia usa uma relação que não está no RELATIONS do campo.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> BLOCKS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Relation `BLOCKS` not declared in the template

Como corrigir: Use uma relação declarada ou acrescente a nova ao template, com sua descrição.

4.5 E011 — Cadeia qualificada malformada

Severidade: erro · Classe: MalformedQualifiedChain

A alternância conceito → relação → conceito foi quebrada; por exemplo, a cadeia termina em uma relação.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Cost -> INHIBITS -> Adoption -> ENABLES
END ITEM
annotations.syn:6:5  [ERROR]  Qualified chain with incorrect structure: Cost -> INHIBITS -> Adoption -> ENABLES

Como corrigir: Garanta número ímpar de elementos: conceito, relação, conceito.

4.6 E013 — Cadeia sem o operador ->

Severidade: erro · Classe: ChainWithoutArrowOperator

O valor de um campo CHAIN tem um único elemento, sem ->. Uma linha com vários elementos sem seta costuma aparecer como E028.

Como corrigir: Ligue ao menos dois conceitos com ->.

4.7 E014 — Conceito com nome de relação

Severidade: erro · Classe: ConceptNameMatchesRelation

Um conceito em posição de código tem o mesmo nome de uma relação declarada.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        ENABLES: makes possible
        INHIBITS: limits
    END RELATIONS
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: ENABLES -> INHIBITS -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  `ENABLES` is ambiguous: both concept and relation in `chain`

Como corrigir: Renomeie o conceito ou a relação.

4.8 E015 — Conceito com espaços

Severidade: erro · Classe: ConceptWithSpaces

Um conceito de cadeia contém espaços.

# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    chain: Public Acceptance -> ENABLES -> Adoption
END ITEM
annotations.syn:6:5  [ERROR]  Concept `Public Acceptance` contains spaces. Suggested fix -> `Public_Acceptance`

Como corrigir: Use sublinhado ou CamelCase: Public_Acceptance.

5 Bundles

Um BUNDLE reúne campos que só fazem sentido juntos e os emparelha pela posição dentro do ITEM.

5.1 E016 — Membro de bundle ausente

Severidade: erro · Classe: MissingBundleField

Um campo do bundle aparece sem o parceiro, ou um bundle obrigatório está ausente.

# template.synt
ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    note: Cost is a barrier
END ITEM
annotations.syn:4:1  [ERROR]  Bundle (note, chain): missing fields `chain`

Como corrigir: Escreva todos os campos do bundle.

5.2 E017 — Contagens diferentes no bundle

Severidade: erro · Classe: BundleCountMismatch

Os campos do bundle aparecem em quantidades diferentes.

# template.synt
ITEM FIELDS
    REQUIRED quote
    REQUIRED BUNDLE note, chain
END ITEM FIELDS
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    note: Cost is a barrier
    chain: Cost -> INHIBITS -> Adoption
    note: Trust helps
END ITEM
annotations.syn:4:1  [ERROR]  Bundle (note, chain) with unequal counts: note=2, chain=1

Como corrigir: Cada ocorrência de um campo precisa do par correspondente, na mesma ordem.

5.3 E018 — Bundle com um único campo

Severidade: erro · Classe: SingleFieldBundle

O template declara um bundle de um só campo.

END ITEM FIELDS

Como corrigir: Declare ao menos dois campos, ou use REQUIRED/OPTIONAL simples.

7 Valores e tipos de campo

7.1 E026 — Decimal em SCALE inteira

Severidade: erro · Classe: DecimalInIntegerScale

O FORMAT do campo usa limites inteiros e o valor tem casas decimais.

# template.synt
FIELD confidence TYPE SCALE
    SCOPE ITEM
    FORMAT [1..5]
END FIELD
# annotations.syn
SOURCE @silva2024
END SOURCE

ITEM @silva2024
    quote: "text"
    confidence: 3.5
END ITEM
annotations.syn:4:1  [ERROR]  Decimal value `3.5` in `confidence` — the field only accepts integers [1..5]

Como corrigir: Use um inteiro ou reescale o campo (por exemplo, [0..2] no lugar de 0, 0,5 e 1). Decimais só são aceitos quando ao menos um limite do FORMAT não é um número inteiro, como em [0..5.5]; escrever [1.0..5.0] não basta, apesar do que sugere a mensagem de diagnóstico.

8 Declaração do template

8.1 E039 — Campo listado sem definição

Severidade: erro · Classe: UndefinedFieldInScopeFields

Um nome aparece em um bloco FIELDS, mas não há FIELD com esse nome. (Agrupa os antigos códigos 39 a 41.)

# template.synt
ITEM FIELDS
    REQUIRED quote, country
END ITEM FIELDS
template.synt:1:1  [ERROR]  Field `country` listed in `ITEM FIELDS` without a FIELD definition

Como corrigir: Defina o FIELD ou retire o nome da lista.

8.2 E042 — Campo definido e não listado

Severidade: aviso · Classe: OrphanFieldDefinition

Há um FIELD que nenhum bloco FIELDS usa.

# template.synt
FIELD note TYPE MEMO
    SCOPE ITEM
END FIELD
template.synt:7:1  [WARNING]  Field `note` defined but missing from `ITEM FIELDS`

Como corrigir: Liste o campo no bloco do seu escopo ou apague a definição.

8.3 E006 — Escopo divergente

Severidade: erro · Classe: FieldScopeListMismatch

O campo está listado em um bloco de um escopo, mas seu SCOPE é outro.

# template.synt
ITEM FIELDS
    REQUIRED quote
    OPTIONAL note
END ITEM FIELDS
# template.synt
FIELD note TYPE MEMO
    SCOPE SOURCE
END FIELD
template.synt:8:1  [ERROR]  Field `note` listed in `ITEM FIELDS` but its declared SCOPE is SOURCE

Como corrigir: Faça o SCOPE e o bloco FIELDS concordarem.

8.4 E047 — CHAIN sem ARITY

Severidade: erro · Classe: ChainWithoutArity

Todo campo CHAIN declara o número mínimo de conceitos.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
END FIELD
template.synt:8:1  [ERROR]  Field `chain` (CHAIN) without an ARITY declaration in the template

Como corrigir: Acrescente, por exemplo, ARITY >= 2.

8.5 E048 — ARITY incompatível com RELATIONS

Severidade: erro · Classe: ArityRelationsMismatch

A aridade pede mais ligações do que as relações declaradas conseguem formar.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 4
    RELATIONS
        ENABLES: makes possible
    END RELATIONS
END FIELD
template.synt:8:1  [ERROR]  Field `chain`: ARITY >= 4 requires more relations than the 1 declared

Como corrigir: Declare mais relações ou reduza a aridade.

8.6 E049 — ORDERED sem VALUES

Severidade: erro · Classe: OrderedWithoutValues

Um campo ORDERED precisa das opções, em ordem.

# template.synt
FIELD level TYPE ORDERED
    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `level` (ORDERED) without a VALUES block in the template

Como corrigir: Acrescente o bloco VALUES com os índices [N].

8.7 E050 — ENUMERATED sem VALUES

Severidade: erro · Classe: EnumeratedWithoutValues

Um campo ENUMERATED precisa da lista fechada de valores.

# template.synt
FIELD status TYPE ENUMERATED
    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `status` (ENUMERATED) without a VALUES block in the template

Como corrigir: Acrescente o bloco VALUES.

8.8 E051 — SCALE sem FORMAT

Severidade: erro · Classe: ScaleWithoutFormat

Um campo SCALE precisa do intervalo numérico.

# template.synt
FIELD confidence TYPE SCALE
    SCOPE ITEM
END FIELD
template.synt:7:1  [ERROR]  Field `confidence` (SCALE) without a FORMAT declaration in the template

Como corrigir: Acrescente, por exemplo, FORMAT [1..5].

8.9 E052 — Sintaxe de FORMAT inválida

Severidade: erro · Classe: InvalidFormatSyntax

O FORMAT de um campo SCALE não tem a forma [mín..máx].

# template.synt
FIELD confidence TYPE SCALE
    SCOPE ITEM
    FORMAT percent
END FIELD
template.synt:7:1  [ERROR]  Invalid FORMAT in `confidence`: `percent` — use `[min..max]`

Como corrigir: Escreva FORMAT [mín..máx].

8.10 E053 — Operador de ARITY inválido

Severidade: erro · Classe: InvalidArityOperator

Os operadores aceitos são >=, >, <=, < e =. Outras grafias costumam produzir antes um erro de sintaxe.

Como corrigir: Use um dos operadores aceitos.

8.11 E054 — FORMAT fora de SCALE

Severidade: erro · Classe: FormatOnNonScale

FORMAT só vale para campos SCALE.

FIELD note TYPE TEXT
    SCOPE ITEM
    FORMAT [1..5]
END FIELD
template.synt:7:1  [ERROR]  FORMAT declared in `note` (type TEXT) — FORMAT is exclusive to SCALE

Como corrigir: Remova a linha ou troque o tipo.

8.12 E055 — ARITY fora de CHAIN

Severidade: erro · Classe: ArityOnNonChain

ARITY só vale para campos CHAIN.

# template.synt
FIELD note TYPE MEMO
    SCOPE ITEM
    ARITY >= 2
END FIELD
template.synt:7:1  [ERROR]  ARITY declared in `note` (type MEMO) — ARITY is exclusive to CHAIN

Como corrigir: Remova a linha ou troque o tipo.

8.13 E056 — RELATIONS fora de CHAIN

Severidade: erro · Classe: RelationsOnNonChain

RELATIONS só vale para campos CHAIN.

# template.synt
FIELD note TYPE TEXT
    SCOPE ITEM
    RELATIONS
        ENABLES: makes possible
    END RELATIONS
END FIELD
template.synt:7:1  [ERROR]  RELATIONS declared in `note` (type TEXT) — RELATIONS is exclusive to CHAIN

Como corrigir: Remova o bloco ou troque o tipo.

8.14 E086 — VALUES fora de ORDERED/ENUMERATED

Severidade: erro · Classe: ValuesOnNonEnumerable

Em qualquer outro tipo a lista seria ignorada, por isso é recusada.

# template.synt
FIELD note TYPE TEXT
    SCOPE ITEM
    VALUES
        High: high
    END VALUES
END FIELD
template.synt:7:1  [ERROR]  VALUES declared in `note` (type TEXT) — VALUES is exclusive to ORDERED/ENUMERATED

Como corrigir: Remova o bloco VALUES ou troque o tipo.

8.15 E087 — Índice [N] em ENUMERATED

Severidade: erro · Classe: IndexOnEnumeratedValue

O índice estabelece ordem, e ENUMERATED não tem ordem.

# template.synt
FIELD status TYPE ENUMERATED
    SCOPE ITEM
    VALUES
        [1] Asserted: stated as fact
        [2] Negated: stated as not holding
    END VALUES
END FIELD
template.synt:7:1  [ERROR]  `[N]` prefix in the VALUES of `status` (ENUMERATED type) — the index is exclusive to ORDERED

Como corrigir: Retire o prefixo, ou use ORDERED se a ordem for intencional.

8.16 E057 — Bloco FIELDS duplicado

Severidade: erro · Classe: DuplicateScopeBlock

Há dois blocos FIELDS para o mesmo escopo. Na versão 0.16.0 o compilador não emite este diagnóstico: blocos repetidos são aceitos sem aviso.

Como corrigir: Una as listas em um só bloco.

8.17 E058 — Valor com espaço nas pontas

Severidade: erro · Classe: ValueWithWhitespace

Um valor do bloco VALUES tem espaço no início ou no fim. Na sintaxe atual de template o espaço costuma ser descartado na leitura, de modo que o aviso é raro.

Como corrigir: Remova o espaço excedente.

8.18 E059 — Valor duplicado em VALUES

Severidade: erro · Classe: DuplicateValue

O mesmo valor aparece duas vezes na lista.

# template.synt
FIELD status TYPE ENUMERATED
    SCOPE ITEM
    VALUES
        Active: in use
        Active: repeated
    END VALUES
END FIELD
template.synt:11:9  [ERROR]  Duplicate value `Active` in the VALUES block of `status`

Como corrigir: Mantenha uma só entrada.

8.19 E060 — ARITY com valor não inteiro

Severidade: erro · Classe: NonIntegerArityValue

O número de ARITY precisa ser inteiro.

# template.synt
FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2.0
END FIELD
template.synt:8:1  [ERROR]  ARITY of field `chain` uses non-integer value `2.0` — use an integer (e.g. 2)

Como corrigir: Escreva 2, não 2.0.

8.20 E069 — Campo definido duas vezes

Severidade: erro · Classe: DuplicateFieldName

Dois FIELD têm o mesmo nome.

# template.synt
FIELD note TYPE MEMO
    SCOPE ITEM
END FIELD

FIELD note TYPE MEMO
    SCOPE ITEM
END FIELD
template.synt:11:1  [ERROR]  Field `note` defined more than once in the template

Como corrigir: Remova ou renomeie um deles.

Os caminhos do .synp são relativos à pasta dele. Por segurança, o compilador só lê arquivos dessa pasta e de suas subpastas; a única exceção é INCLUDE SHARED ONTOLOGY.

10.1 E073 — Arquivo de anotações não encontrado

Severidade: erro · Classe: MissingAnnotationsFile

O INCLUDE ANNOTATIONS aponta para algo que não existe.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ANNOTATIONS "missing.syn"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
project.synp:5:5  [ERROR]  Annotations file `missing.syn` declared in the project was not found

Como corrigir: Confira o nome e o caminho.

10.2 E074 — Arquivo de ontologia não encontrado

Severidade: erro · Classe: MissingOntologyFile

O INCLUDE ONTOLOGY aponta para algo que não existe.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "missing.syno"
    INCLUDE ONTOLOGY "ontology.syno"
END PROJECT
project.synp:5:5  [ERROR]  Organizing model file `missing.syno` declared in the project was not found

Como corrigir: Confira o caminho. Um .syno vazio é válido, mas precisa existir.

10.3 E075 — Caminho fora do projeto

Severidade: erro · Classe: IncludePathEscapesProject

Um caminho (literal ou curinga) sai da pasta do projeto.

# project.synp
PROJECT demo
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "references.bib"
    INCLUDE ANNOTATIONS "annotations.syn"
    INCLUDE ONTOLOGY "ontology.syno"
    INCLUDE ONTOLOGY "../shared.syno"

project.synp:6:5  [ERROR]  Path `../shared.syno` points outside the project folder

Como corrigir: Mova o arquivo para dentro do projeto. Para um vocabulário comum a vários projetos, use INCLUDE SHARED ONTOLOGY.

10.4 E076 — Arquivo incluído ilegível

Severidade: erro · Classe: UnreadableIncludedFile

O arquivo existe, mas não pode ser lido: erro de sintaxe, codificação inválida ou tamanho acima de 32 MB.

# annotations.syn

END SOURCE

    quote: "text"
annotations.syn:1:1  [ERROR]  File `annotations.syn` could not be read: error: annotations.syn:1:1: Unexpected token <EOF> END SOURCE Expected: END

Como corrigir: Abra o arquivo indicado e corrija o problema descrito na mensagem.

10.5 E084 — SHARED fora de ONTOLOGY

INCLUDE SHARED só é aceito para ontologias.

# project.synp

Como corrigir: Copie o arquivo para dentro do projeto e use INCLUDE simples.

11 Ligação entre projetos e datasets

Os diagnósticos E081, E082 e W083 só aparecem no passo de ligação, quando dois ou mais projetos são compilados juntos. Veja Como Ligar Projetos Independentes.

11.1 E077 — Valor de identidade repetido

Severidade: erro · Classe: DuplicateIdentityValue

Dois SOURCE têm o mesmo valor em um campo IDENTIFIES, que funciona como chave primária.

# template.synt
FIELD researcher_id TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# annotations.syn
SOURCE @silva2024
    researcher_id: 001
END SOURCE

ITEM @silva2024
    quote: "a"
END ITEM

SOURCE @souza2023
    researcher_id: 001
END SOURCE

ITEM @souza2023
    quote: "b"
END ITEM
annotations.syn:9:1  [ERROR]  Value `1` of `researcher_id` (IDENTIFIES researcher) duplicated in `@silva2024` and `@souza2023`

Como corrigir: Cada valor identifica um único SOURCE: corrija o dado.

11.2 E078 — Modificador de ligação fora de SOURCE

Severidade: erro · Classe: LinkageModifierOutsideSource

IDENTIFIES e REFERS TO só valem em campos SCOPE SOURCE.

# template.synt
FIELD author_id TYPE TEXT
    SCOPE ITEM
    REFERS TO researcher
END FIELD
template.synt:7:1  [ERROR]  `REFERS TO` in `author_id` (SCOPE ITEM) — only valid in SCOPE SOURCE

Como corrigir: Mova o campo para o escopo SOURCE.

11.3 E079 — Valor ausente no .bib

Severidade: erro · Classe: MissingBibliographyValue

Um campo REQUIRED ... ON BIBLIOGRAPHY não tem valor na entrada do SOURCE.

# template.synt
SOURCE FIELDS
    REQUIRED orcid ON BIBLIOGRAPHY
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS
% references.bib
@article{silva2024,
    author = {Silva, Ana},
    title = {Study},
    year = {2024}
}
annotations.syn:1:1  [ERROR]  Field `orcid` (ON BIBLIOGRAPHY) missing in the .bib entry of `@silva2024`

Como corrigir: Acrescente o campo à entrada BibTeX.

11.4 I080 — Referência externa declarada

Severidade: informativo · Classe: ExternalReferenceDeclared

O projeto declara REFERS TO e foi compilado sozinho. É informativo: não é erro nem aviso.

    SCOPE SOURCE
    REFERS TO researcher
END FIELD
template.synt:11:1  [INFO]  External reference `researcher` (REFERS TO in author_id) — not materialized in isolation

Como corrigir: Nada a fazer. Para materializar as ligações, compile junto com o projeto que declara IDENTIFIES.

11.5 E081 — Entidade com dois donos

Severidade: erro · Classe: DuplicateEntityOwner

Dois projetos declaram IDENTIFIES para o mesmo rótulo de entidade.

# lattes.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# orcid.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
<link>:0:0  [ERROR]  Entity `researcher` with a duplicate owner: `lattes` and `orcid`

Como corrigir: Escolha o projeto dono; nos demais use REFERS TO.

11.6 E082 — Tipos divergentes na ligação

Severidade: erro · Classe: TypeMismatchInLinkage

Os campos ligados à mesma entidade têm TYPE diferentes.

# lattes.synt
FIELD rid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD
# papers.synt
FIELD author_id TYPE SCALE
    FORMAT [0..999]
    SCOPE SOURCE
    REFERS TO researcher
END FIELD
<link>:0:0  [ERROR]  Tipos divergentes na entidade `researcher`: `lattes` TYPE TEXT vs `papers` TYPE SCALE

Como corrigir: Use o mesmo TYPE dos dois lados.

11.7 W083 — Referência órfã

Severidade: aviso · Classe: OrphanReference

Um valor de REFERS TO não casa com nenhum IDENTIFIES. Se o valor casaria ignorando maiúsculas e minúsculas, a mensagem avisa do quase-casamento. O compilador nunca funde entidades.

# lattes.syn
SOURCE @lattes1
    rid: A01
END SOURCE

ITEM @lattes1
    quote: "x"
END ITEM
# papers.syn
SOURCE @papers1
    author_id: a01
END SOURCE

ITEM @papers1
    quote: "x"
END ITEM
<link>:0:0  [WARNING]  Orphan REFERS TO `a01` (researcher) — near match `A01` (differs only in case)

Como corrigir: Corrija a grafia na origem. Órfãos podem ser normais em corpora reais.

11.8 E085 — Valor ausente no dataset

Severidade: erro · Classe: MissingDatasetValue

Um campo REQUIRED ... ON DATASET não tem valor no registro TOML do SOURCE.

# template.synt
SOURCE FIELDS

    REQUIRED region ON DATASET "interview.region"
END SOURCE FIELDS

ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS
# records/s1.toml
[interview]
id = "silva2024"
annotations.syn:1:1  [ERROR]  Field `region` (ON DATASET "interview.region") missing in the record `@silva2024`

Como corrigir: Complete o registro, ou torne o campo OPTIONAL.

13 Papéis (ROLE) e modelo organizador

Estes diagnósticos aparecem quando o template atribui funções aos campos de ONTOLOGY com ROLE. Veja O Modelo Organizador.

13.1 E101 — Conceito citado sem bloco

Severidade: erro · Classe: UndeclaredConcept

Um campo CODE de ONTOLOGY cita um conceito que não tem bloco ONTOLOGY.

# template.synt
FIELD kind_of TYPE CODE
    SCOPE ONTOLOGY
    ROLE HIERARCHY KIND
END FIELD
# ontology.syno
ONTOLOGY smishing
    kind_of: phishing
END ONTOLOGY
ontology.syno:2:5  [ERROR]  `kind_of`: concept `phishing` without an ONTOLOGY block (parecido: `smishing`)

Como corrigir: Crie o bloco do conceito citado.

13.2 E102 — Item vazio em lista

Severidade: erro · Classe: InvalidValueForm

Uma lista de um campo CODE de ONTOLOGY tem um elemento vazio.

# ontology.syno
ONTOLOGY smishing
    kind_of: phishing, , fraud
END ONTOLOGY

ONTOLOGY phishing
END ONTOLOGY

ONTOLOGY fraud
END ONTOLOGY
ontology.syno:2:5  [ERROR]  `kind_of`: empty item in the list

Como corrigir: Remova a vírgula excedente.

13.3 E104 — Papel desconhecido

Severidade: erro · Classe: UnknownRole

O texto depois de ROLE não está no catálogo.

# template.synt
FIELD x TYPE TEXT
    SCOPE ONTOLOGY
    ROLE SYNONYM
END FIELD
template.synt:11:1  [ERROR]  Unknown role `SYNONYM` in the field `x`

Como corrigir: Use um papel do catálogo (LABEL, NOTE, HIERARCHY, USE).

13.4 E105 — Papel ainda indisponível

Severidade: erro · Classe: RoleNotAvailable

O papel está previsto (DIVISION EXCLUSIVE ou COMPLETE), mas ainda não foi implementado.

# template.synt
FIELD x TYPE CODE
    SCOPE ONTOLOGY
    ROLE DIVISION EXCLUSIVE
END FIELD
template.synt:11:1  [ERROR]  Role `DIVISION EXCLUSIVE` not yet available (field `x`)

Como corrigir: Remova a linha ROLE.

13.5 E106 — Papel sem espécie

Severidade: erro · Classe: RoleRequiresSpecies

LABEL, NOTE e HIERARCHY exigem a espécie.

# template.synt
FIELD x TYPE CODE
    SCOPE ONTOLOGY
    ROLE HIERARCHY
END FIELD
template.synt:11:1  [ERROR]  Role `HIERARCHY` without a species in the field `x`

Como corrigir: Escreva, por exemplo, ROLE HIERARCHY KIND.

13.6 E107 — Tipo incompatível com o papel

Severidade: erro · Classe: RoleTypeMismatch

LABEL e NOTE exigem TEXT; HIERARCHY e USE exigem CODE.

# template.synt
FIELD x TYPE TEXT
    SCOPE ONTOLOGY
    ROLE HIERARCHY KIND
END FIELD
template.synt:11:1  [ERROR]  `x`: `HIERARCHY KIND` exige TYPE CODE (e TEXT)

Como corrigir: Troque o TYPE do campo.

13.7 E108 — ROLE fora de ONTOLOGY

Severidade: erro · Classe: RoleOutsideOntology

Papéis só existem em campos SCOPE ONTOLOGY.

# template.synt
FIELD x TYPE TEXT
    SCOPE ITEM
    ROLE NOTE DEFINITION
END FIELD
template.synt:8:1  [ERROR]  ROLE NOTE DEFINITION in `x` (SCOPE ITEM): only valid in SCOPE ONTOLOGY

Como corrigir: Remova a linha ROLE ou mude o escopo.

13.8 E109 — ROLE repetido

Severidade: erro · Classe: DuplicateRole

O mesmo FIELD declara dois ROLE.

# template.synt
FIELD x TYPE TEXT
    SCOPE ONTOLOGY
    ROLE NOTE DEFINITION
    ROLE NOTE USAGE
END FIELD
template.synt:11:1  [ERROR]  Repeated ROLE in the field `x`

Como corrigir: Mantenha um.

13.9 E110 — Papel único em dois campos

Severidade: erro · Classe: DuplicateUniqueRole

Só pode haver um campo NOTE DEFINITION, um LABEL PREFERRED e um USE.

# template.synt
FIELD a TYPE TEXT
    SCOPE ONTOLOGY
    ROLE NOTE DEFINITION
END FIELD
# template.synt
FIELD b TYPE TEXT
    SCOPE ONTOLOGY
    ROLE NOTE DEFINITION
END FIELD
template.synt:16:1  [ERROR]  `NOTE DEFINITION` in two fields: `a` and `b`

Como corrigir: Mantenha o papel em um único campo.

13.10 E111 — Hierarquia obrigatória

Severidade: erro · Classe: RequiredHierarchy

Um campo HIERARCHY não pode ser REQUIRED: os conceitos de topo não têm pai.

# template.synt
ITEM FIELDS
    REQUIRED quote
END ITEM FIELDS

ONTOLOGY FIELDS
    REQUIRED kind_of
END ONTOLOGY FIELDS
# template.synt
FIELD kind_of TYPE CODE
    SCOPE ONTOLOGY
    ROLE HIERARCHY KIND
END FIELD
template.synt:11:1  [ERROR]  `kind_of` (HIERARCHY KIND) cannot be REQUIRED: the top concepts would be invalid

Como corrigir: Liste o campo como OPTIONAL.

13.11 E112 — Nome de campo reservado

Severidade: erro · Classe: ReservedOntologyFieldName

Um campo de ONTOLOGY usa um nome que é chave canônica do JSON.

# template.synt
FIELD frequency TYPE TEXT
    SCOPE ONTOLOGY
END FIELD
template.synt:11:1  [ERROR]  ONTOLOGY field `frequency` uses a name reserved in the JSON

Como corrigir: Renomeie o campo.

13.12 E113 — Mais de um rótulo preferido

Severidade: erro · Classe: MultiplePreferredLabels

Um conceito tem dois termos em LABEL PREFERRED.

# ontology.syno
ONTOLOGY smishing
    label: Smishing, SMS phishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  `smishing`: more than one preferred label

Como corrigir: Mantenha um; mova os outros para um campo LABEL ALTERNATIVE.

13.13 E114 — Termo em duas espécies de rótulo

Severidade: erro · Classe: LabelSpeciesOverlap

O mesmo termo está em dois campos LABEL do mesmo conceito.

# ontology.syno
ONTOLOGY smishing
    used_for: SMS phishing
    old_name: SMS phishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  `smishing`: `SMS phishing` in two LABEL species

Como corrigir: Deixe o termo em um só.

13.14 E115 — Rótulo ambíguo

Severidade: erro · Classe: AmbiguousLabel

O mesmo termo é rótulo de dois conceitos.

# ontology.syno
ONTOLOGY smishing
    used_for: text scam
END ONTOLOGY

ONTOLOGY vishing
    used_for: text scam
END ONTOLOGY
ontology.syno:5:1  [ERROR]  Label `text scam` on two concepts: `smishing` and `vishing`

Como corrigir: Um rótulo pertence a um só conceito.

13.15 E116 — Rótulo igual a outro conceito

Severidade: erro · Classe: LabelConflictsWithConcept

Um rótulo coincide com o nome de outro conceito.

# ontology.syno
ONTOLOGY smishing
    used_for: vishing
END ONTOLOGY

ONTOLOGY vishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  `smishing`: label `vishing` is the name of the concept `vishing`

Como corrigir: Remova o rótulo ou consolide os conceitos com USE.

13.16 E117 — Autorreferência na hierarquia

Severidade: erro · Classe: SelfReference

Um conceito é indicado como pai de si mesmo.

# ontology.syno
ONTOLOGY phishing
    kind_of: phishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  `phishing` points to itself in `kind_of`

Como corrigir: Indique o conceito mais amplo.

13.17 E118 — Ciclo na hierarquia

Severidade: erro · Classe: CyclicHierarchy

Seguindo os pais, volta-se ao conceito inicial.

# ontology.syno
ONTOLOGY phishing
    kind_of: smishing
END ONTOLOGY

ONTOLOGY smishing
    kind_of: phishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  Hierarchy cycle: phishing -> smishing -> phishing

Como corrigir: Quebre o ciclo. A proibição é uma regra do Synesis.

13.18 E119 — Par em duas espécies de hierarquia

Severidade: erro · Classe: DuplicateHierarchySpecies

O mesmo par filho-pai aparece em dois campos HIERARCHY.

# ontology.syno
ONTOLOGY smishing
    kind_of: phishing
    part_of: phishing
END ONTOLOGY

ONTOLOGY phishing
END ONTOLOGY
ontology.syno:1:1  [ERROR]  `smishing` -> `phishing` in two species (KIND, PART)

Como corrigir: Escolha uma espécie.

13.19 E120 — Conceito sem fundamentação

Severidade: aviso · Classe: UngroundedConcept

O bloco não é mencionado em nenhum ITEM, nem tem descendente mencionado.

# ontology.syno
ONTOLOGY phishing
END ONTOLOGY

ONTOLOGY smishing
    kind_of: phishing
END ONTOLOGY
ontology.syno:1:1  [WARNING]  `phishing` has no mention and no mentioned descendant
ontology.syno:4:1  [WARNING]  `smishing` has no mention and no mentioned descendant

Como corrigir: Codifique evidência para o conceito ou remova o bloco.

13.20 E121 — Hierarquia pelo nome do campo (rota antiga)

Severidade: aviso · Classe: DeprecatedNameBasedHierarchy

A hierarquia foi lida pelo nome parent/is_a, uma rota em desuso.

# template.synt
FIELD parent TYPE CHAIN
    SCOPE ONTOLOGY
    ARITY >= 2
END FIELD
# ontology.syno
ONTOLOGY smishing
    parent: smishing -> phishing
END ONTOLOGY

ONTOLOGY phishing
END ONTOLOGY
ontology.syno:1:1  [WARNING]  `smishing`: hierarchy by the name `parent` (deprecated route)

Como corrigir: Declare ROLE HIERARCHY no campo.
