Guia de Erros

Todas as mensagens do compilador — com exemplos reproduzíveis

Como usar este guia

Cada erro mostra: o que aconteceu, por que é problema, e como corrigir — com um trecho de código que você pode copiar para reproduzir o erro. Os projetos de teste completos estão na pasta do repositório de .

0.1 Convenções

  • (ERRO) — impede a compilação e bloqueia a exportação
  • (AVISO) — algo incompleto ou incomum; não bloqueia, mas deve ser investigado
  • (INFO) — informação de contexto; não indica defeito algum. Usado quando o compilador precisa registrar uma condição esperada, como uma referência entre projetos que só se resolve na linkagem (Seção 11.4)
  • Erros marcados com [implementado] já são detectados pelo compilador; [pendente] ainda não
  • Erros de template (39–60, 69) são problemas na definição das regras do projeto, não nas anotações
  • Erros de caminho (73–76) tratam da resolução de arquivos declarados no .synp; erros de ligação (77–84) tratam da conexão entre projetos independentes

0.2 Formato das mensagens

Toda mensagem segue esta estrutura:

ERRO  arquivo.syn  linha 42, coluna 7
  O código `Acietacao_Social` não está definido na ontologia.
  Você quis dizer `Aceitacao_Social`?
  • Nível — ERRO ou AVISO
  • Localização — arquivo, linha e coluna
  • Descrição — o que aconteceu
  • Sugestão — quando aplicável, o compilador sugere correções usando similaridade de texto

1 Vínculos Bibliográficos

Erros de ligação entre SOURCEs, ITEMs e o arquivo .bib. Projeto de teste: T01.

1.1 Erro 1 — Fonte não encontrada na bibliografia (AVISO)

O @bibref de um SOURCE não existe no arquivo .bib.

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @garcia2022
    summary: Estudo sobre aceitação social.
END SOURCE

Mas o arquivo .bib não contém a entrada garcia2022:

@article{smith2024,
    author = {Smith, Jane},
    title  = {Community Resilience},
    year   = {2024}
}
# garcia2022 não existe aqui

Adicione a entrada ao .bib ou corrija a grafia do @bibref. O compilador sugere alternativas similares quando encontra.

1.2 Erro 2 — ITEM sem SOURCE correspondente (ERRO)

Um ITEM referencia um @bibref que não tem bloco SOURCE no mesmo arquivo.

  • Exemplo que causa o erro
  • Como corrigir
# Nenhum bloco SOURCE @orphan_ref existe neste arquivo

ITEM @orphan_ref
    citation: Trecho sem fonte declarada.
    memo: Este item não tem SOURCE.
    tag: Aceitacao_Social
END ITEM

Crie um bloco SOURCE @orphan_ref antes do ITEM, ou corrija o @bibref.

1.3 Erro 24 — SOURCE sem ITEMs (AVISO)

Uma SOURCE foi declarada mas nenhum ITEM a referencia.

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @jones2023
    summary: Estudo urbano sem unidades de análise extraídas.
END SOURCE

# Nenhum ITEM @jones2023 existe no projeto

Adicione pelo menos um ITEM que referencie @jones2023, ou remova o SOURCE se não for mais necessário.

1.4 Erro 70 — SOURCE duplicada (ERRO)

O mesmo @bibref aparece em dois blocos SOURCE no mesmo arquivo.

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @smith2024
    summary: Primeira declaração.
END SOURCE

# ...outros blocos...

SOURCE @smith2024
    summary: Declaração duplicada.
END SOURCE

Unifique os dois blocos num único SOURCE, ou distribua as anotações em arquivos .syn separados.

2 Vínculos Ontológicos

Erros de ligação entre códigos usados em ITEMs e definições na ontologia. Projeto de teste: T01.

2.1 Erro 3 — Código não definido na ontologia (AVISO)

Um código usado no campo code de um ITEM não tem entrada ONTOLOGY correspondente.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @smith2024
    citation: Os custos foram citados como principal barreira.
    memo: Custo como fator determinante.
    tag: Custo_Inexistente, Aceitacao_Social
END ITEM

Custo_Inexistente não tem bloco ONTOLOGY no .syno.

Crie o conceito na ontologia:

ONTOLOGY Custo_Inexistente
    definition: ...
    group: ...
END ONTOLOGY

Ou corrija a grafia — o compilador sugere alternativas similares.

2.2 Erro 4 — Conceito de CHAIN não definido (AVISO)

Um nó conceitual usado numa CHAIN não existe na ontologia.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @smith2024
    citation: A percepção de risco influencia a aceitação.
    tag: Aceitacao_Social
    chain: Percepcao_Risco -> INFLUENCES -> Conceito_Fantasma
END ITEM

Conceito_Fantasma não tem entrada ONTOLOGY.

Crie o conceito na ontologia ou corrija a grafia.

2.3 Erro 68 — Conceito duplicado na ontologia (ERRO)

O mesmo nome de conceito aparece em dois blocos ONTOLOGY.

  • Exemplo que causa o erro
  • Como corrigir
ONTOLOGY Aceitacao_Social
    definition: Grau de aprovação de uma tecnologia.
    group: Fatores_Sociais
END ONTOLOGY

ONTOLOGY Aceitacao_Social
    definition: Definição duplicada.
    group: Duplicatas
END ONTOLOGY

Unifique os dois blocos num único ONTOLOGY, ou renomeie um deles.

2.4 Erro 71 — Descrições idênticas em conceitos diferentes (AVISO)

Dois blocos ONTOLOGY distintos têm exatamente a mesma definition.

  • Exemplo que causa o erro
  • Como corrigir
ONTOLOGY Conceito_A
    definition: Fator que influencia positivamente a adoção de tecnologias limpas.
    group: Fatores_Gerais
END ONTOLOGY

ONTOLOGY Conceito_B
    definition: Fator que influencia positivamente a adoção de tecnologias limpas.
    group: Fatores_Gerais
END ONTOLOGY

Diferencie as definições, ou verifique se os conceitos deveriam ser um único.

3 Cadeias (CHAINs) e Relações

Erros de estrutura e vínculo em campos CHAIN. Projeto de teste: T02.

Estes exemplos usam o seguinte template:

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    RELATIONS
        INFLUENCES: Efeito causal direto
        CONSTRAINS: Um conceito limita outro
        ENABLES:    Condição necessária
    END RELATIONS
END FIELD

3.1 Erro 7 — Relação não declarada no template (ERRO)

Uma CHAIN usa um nome de relação que não está no bloco RELATIONS.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Correlação não declarada.
    chain: Custo -> CORRELATES -> Aceitacao
END ITEM

CORRELATES não está nas RELATIONS do template (que define INFLUENCES, CONSTRAINS, ENABLES).

Use uma das relações disponíveis ou peça ao coordenador do projeto para incluir a nova relação no template.

3.2 Erro 9 — CHAIN simples onde relações são obrigatórias (ERRO)

A CHAIN foi escrita sem relações (A -> B), mas o template define RELATIONS e exige o formato qualificado (A -> RELAÇÃO -> B).

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Cadeia simples em campo que exige relações.
    chain: Custo -> Aceitacao
END ITEM

Reescreva com relações:

    chain: Custo -> INFLUENCES -> Aceitacao

3.3 Erro 10 — Estrutura mal formada em CHAIN qualificada (ERRO)

Uma CHAIN qualificada deve alternar conceitos e relações: Conceito -> RELAÇÃO -> Conceito. Um número par de elementos indica estrutura incorreta.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Estrutura mal formada.
    chain: Custo -> Aceitacao -> Percepcao_Risco -> Beneficio
END ITEM

4 elementos sem relações — o parser não sabe quais são conceitos e quais são relações.

Intercale com relações:

    chain: Custo -> INFLUENCES -> Aceitacao -> CONSTRAINS -> Percepcao_Risco

3.4 Erro 12 — CHAIN com poucos elementos (ERRO)

A CHAIN tem menos conceitos que o mínimo exigido pelo ARITY do template.

  • Exemplo que causa o erro
  • Como corrigir

Com ARITY >= 3 no template, esta CHAIN tem apenas 2 conceitos efetivos:

ITEM @autor2024
    citation: Cadeia com elemento único.
    chain: Custo -> INFLUENCES -> Aceitacao
END ITEM

Adicione conceitos até atingir o mínimo exigido.

3.5 Erro 14 — Conceito com mesmo nome de uma relação (ERRO)

Um elemento aparece na posição de conceito, mas também está declarado como relação no template. O compilador não consegue determinar o papel do elemento.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Conceito com mesmo nome de relação.
    chain: INFLUENCES -> CONSTRAINS -> Aceitacao
END ITEM

INFLUENCES é relação no template E está na posição de conceito.

Renomeie o conceito na ontologia para ser diferente dos nomes de relação.

3.6 Erro 15 — Conceito com espaços (ERRO)

Nomes de conceito em CHAINs não podem conter espaços — use underscore.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Conceito com espaço no nome.
    chain: Custo -> INFLUENCES -> Aceitacao Social
END ITEM
    chain: Custo -> INFLUENCES -> Aceitacao_Social

4 Bundles

Erros de campos que devem aparecer juntos. Projeto de teste: T03.

Estes exemplos usam o seguinte template:

ITEM FIELDS
    REQUIRED citation
    REQUIRED BUNDLE note, chain
    REQUIRED BUNDLE lone_field
END ITEM FIELDS

4.1 Erro 16 — Campo de bundle sem parceiro (ERRO)

Apenas um dos campos do bundle está presente.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Bundle parcial.
    note: Este memo não tem cadeia correspondente.
END ITEM

O campo note pertence ao bundle (note, chain), mas chain está ausente.

Adicione o campo chain ou remova note. Campos de bundle devem aparecer sempre juntos.

4.2 Erro 17 — Contagem desigual no bundle (ERRO)

Os campos do bundle aparecem em quantidades diferentes.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Bundle com contagens desiguais.
    note: Primeiro memo.
    chain: Custo -> INFLUENCES -> Aceitacao_Social
    note: Segundo memo sem cadeia correspondente.
END ITEM

note aparece 2 vezes, chain apenas 1.

Cada ocorrência de note precisa de uma ocorrência correspondente de chain.

4.3 Erro 18 — Bundle com campo único (ERRO)

Um bundle foi declarado no template com apenas um campo. Bundles existem para garantir co-ocorrência — com um campo só, não faz sentido.

  • Exemplo que causa o erro
  • Como corrigir

No template:

ITEM FIELDS
    REQUIRED BUNDLE lone_field
END ITEM FIELDS

Adicione pelo menos um campo parceiro ao bundle ou remova a declaração BUNDLE.

4.4 Erro 19 — Bundle obrigatório ausente (ERRO)

O ITEM não contém nenhuma ocorrência de um bundle declarado como REQUIRED.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Sem nenhuma ocorrência do bundle note+chain.
    lone_field: Apenas este campo presente.
END ITEM

Adicione ao menos uma ocorrência completa do bundle (note + chain).

5 Campos Obrigatórios

Erros de campos REQUIRED ausentes. Projeto de teste: T04.

5.1 Erro 20 — Campo obrigatório ausente no ITEM (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com REQUIRED citation no template:

ITEM @autor2024
    memo: Item sem citation obrigatório.
    rating: 3
END ITEM

Adicione citation: <valor> ao bloco.

5.2 Erro 21 — Campo obrigatório ausente no SOURCE (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com REQUIRED source_date no template:

SOURCE @autor2024
    summary: Fonte sem a data obrigatória.
END SOURCE

Adicione source_date: 2024-03-15 ao bloco.

5.3 Erro 22 — Campo obrigatório ausente no ONTOLOGY (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com REQUIRED definition, group no template:

ONTOLOGY Custo_Energia
    definition: Custo total de instalação.
    # "group" ausente
END ONTOLOGY

Adicione group: <valor> ao bloco.

5.4 Erro 23 — ITEM vazio (ERRO)

Bloco ITEM sem nenhum campo.

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
END ITEM

Adicione os campos exigidos pelo template ou remova o bloco.

6 Tipos de Campo

Erros de validação de tipo — quando o valor não corresponde ao tipo declarado. Projeto de teste: T04.

6.1 Erro 25 — Valor fora do intervalo SCALE (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com FORMAT [1..5] no template:

ITEM @autor2024
    citation: Valor fora do intervalo.
    rating: 8
END ITEM

Use um valor entre 1 e 5.

6.2 Erro 26 — Decimal em SCALE inteira (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Valor decimal em escala inteira.
    rating: 3.5
END ITEM

Use um valor inteiro, ou peça ao coordenador para ajustar o FORMAT (ex: [1.0..5.0]).

6.3 Erro 27 — Valor inválido em ENUMERATED (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com VALUES Ativo, Inativo, Pendente:

ITEM @autor2024
    citation: Valor inválido em campo ENUMERATED.
    status: Cancelado
END ITEM

Use um dos valores definidos: Ativo, Inativo ou Pendente.

6.4 Erro 28 — Valor inválido em ORDERED (ERRO)

  • Exemplo que causa o erro
  • Como corrigir

Com VALUES [1] Baixa, [2] Media, [3] Alta:

ITEM @autor2024
    citation: Valor inválido em campo ORDERED.
    importance: Critica
END ITEM

Use o rótulo (Baixa, Media, Alta) ou o índice numérico (1, 2, 3).

6.5 Erro 29 — Data em formato inválido (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @autor2024
    source_date: 15/03/2024
END SOURCE

Use o formato AAAA-MM-DD: source_date: 2024-03-15.

6.6 Erro 30 — Número em campo de texto (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: 42
END ITEM

Campos QUOTATION e TEXT esperam texto, não números isolados. Escreva o conteúdo como frase.

6.7 Erro 31 — Código duplicado no mesmo campo (AVISO)

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Código duplicado.
    tag: Aceitacao_Social, Aceitacao_Social
END ITEM

Remova a ocorrência duplicada.

6.8 Erro 32 — TOPIC com espaços (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ONTOLOGY Barreira_Economica
    definition: Fator econômico que dificulta a adoção.
    group: Economia Energia
END ONTOLOGY

Use underscore: group: Economia_Energia.

6.9 Erro 33 — Caractere inválido em identificador (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ONTOLOGY Custo-Alto
    definition: Custo elevado que representa barreira.
    group: Economia
END ONTOLOGY

O hífen (-) não é permitido em nomes de conceito.

Use underscore: Custo_Alto.

7 Escopo

Erros de campo usado fora do seu escopo declarado. Projeto de teste: T04.

7.1 Erro 34 — Campo ITEM usado em SOURCE (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @autor2024
    source_date: 2024-01-01
    citation: Campo de ITEM usado indevidamente em SOURCE.
END SOURCE

citation tem SCOPE ITEM no template.

Mova o campo para o ITEM correspondente.

7.2 Erro 35 — Campo SOURCE usado em ITEM (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Campo de SOURCE usado em ITEM.
    source_date: 2024-06-01
END ITEM

source_date tem SCOPE SOURCE no template.

Mova source_date para o bloco SOURCE correspondente.

7.3 Erro 36 — Campo ONTOLOGY usado em ITEM/SOURCE (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ITEM @autor2024
    citation: Campo de ONTOLOGY em ITEM.
    group: Economia
END ITEM

group tem SCOPE ONTOLOGY no template.

Campos com SCOPE ONTOLOGY pertencem ao arquivo .syno, não às anotações.

7.4 Erro 37 — TOPIC fora de ONTOLOGY (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
SOURCE @autor2024
    source_date: 2024-02-01
    category: Economia_Energia
END SOURCE

category é TYPE TOPIC com SCOPE ONTOLOGY.

Campos TOPIC organizam a ontologia — não pertencem a blocos SOURCE ou ITEM.

7.5 Erro 38 — CHAIN fora de ITEM (ERRO)

  • Exemplo que causa o erro
  • Como corrigir
ONTOLOGY Fator_Completo
    definition: Conceito com campo de escopo ITEM.
    group: Teste_Escopo
    citation: Trecho indevido em ONTOLOGY.
END ONTOLOGY

citation tem SCOPE ITEM — não pode ser usado em ONTOLOGY.

10 Arquivos e Caminhos

Erros na resolução dos caminhos declarados em TEMPLATE e INCLUDE. Todos os caminhos são resolvidos relativos à pasta onde está o arquivo .synp.

Por que o compilador restringe caminhos

Arquivos .synp e .syn circulam entre pesquisadores e são gerados automaticamente pelo synesis-coder. Um caminho como "../../documentos/pessoais.txt" faria o compilador ler e incorporar ao projeto um arquivo que o pesquisador nunca pretendeu publicar — e qualquer exportador o levaria adiante. Por isso o compilador só lê arquivos contidos na pasta do projeto, com uma única exceção declarada explicitamente: INCLUDE SHARED ONTOLOGY (ver Seção 11.8).

10.1 Erro 73 — Arquivo de anotações não encontrado (ERRO)

O caminho declarado em INCLUDE ANNOTATIONS não existe no disco.

  • Exemplo que causa o erro
  • Como corrigir
PROJECT Estudo_Aceitacao
    TEMPLATE "modelo.synt"
    INCLUDE BIBLIOGRAPHY "referencias.bib"
    INCLUDE ANNOTATIONS "entrevistas/entrevista_07.syn"
END PROJECT

Mas o arquivo entrevistas/entrevista_07.syn não existe.

Verifique o nome e o caminho, que deve ser relativo à pasta do .synp. Um INCLUDE quebrado não impede mais o parsing dos demais arquivos: o compilador reporta o arquivo ausente e segue processando o resto do projeto.

10.2 Erro 74 — Arquivo de ontologia não encontrado (ERRO)

O caminho declarado em INCLUDE ONTOLOGY não existe no disco.

  • Exemplo que causa o erro
  • Como corrigir
PROJECT Estudo_Aceitacao
    TEMPLATE "modelo.synt"
    INCLUDE BIBLIOGRAPHY "referencias.bib"
    INCLUDE ANNOTATIONS "anotacoes.syn"
    INCLUDE ONTOLOGY "ontologia/conceitos.syno"
END PROJECT

Mas ontologia/conceitos.syno não existe.

Verifique o nome e o caminho. Sem o arquivo de ontologia, os códigos usados nas anotações não podem ser validados — as anotações continuam sendo lidas, mas sem validação conceitual.

10.3 Erro 75 — Caminho aponta para fora do projeto (ERRO)

Um caminho em TEMPLATE ou INCLUDE escapa da pasta do projeto.

  • Exemplo que causa o erro
  • Como corrigir
PROJECT Estudo_Aceitacao
    TEMPLATE "modelo.synt"
    INCLUDE BIBLIOGRAPHY "referencias.bib"
    INCLUDE ANNOTATIONS "../outro_projeto/anotacoes.syn"
END PROJECT

O mesmo vale para padrões glob que escapem — INCLUDE ANNOTATIONS "../../*.syn" é recusado com o mesmo erro.

Mova o arquivo para dentro da pasta do projeto (ou de uma subpasta) e ajuste o caminho. Subpastas são sempre válidas: INCLUDE ANNOTATIONS "entrevistas/*.syn".

Se o objetivo é compartilhar uma ontologia entre vários projetos, use INCLUDE SHARED ONTOLOGY — a única forma autorizada de apontar para fora da pasta do projeto. Ver Seção 11.

10.4 Erro 76 — Arquivo incluído não pode ser lido (ERRO)

O arquivo existe, mas o compilador não conseguiu lê-lo ou interpretá-lo.

  • Exemplo que causa o erro
  • Como corrigir

Três situações produzem este erro:

  1. Codificação inválida — o arquivo não está em UTF-8 (por exemplo, salvo em ANSI/Latin-1 com acentos)
  2. Erro de sintaxe — o arquivo .syn ou .syno incluído tem sintaxe inválida
  3. Arquivo grande demais — acima de 32 MB, recusado para não travar o editor
# anotacoes.syn com bloco malformado
ITEM @silva2024
    citation: Trecho da entrevista.
# falta o END ITEM

A mensagem indica qual arquivo e qual foi a causa. Salve o arquivo em UTF-8, corrija a sintaxe apontada, ou divida um arquivo excessivamente grande em vários menores.

Por que o limite de 32 MB

O servidor LSP é um processo de longa duração dentro do editor. Um arquivo de vários gigabytes — por engano ou gerado automaticamente — travaria o VS Code inteiro. O limite protege a sessão de edição.

11 Ligação entre Projetos

Erros dos modificadores IDENTIFIES / REFERS TO e do passo de linkagem multiprojeto. Ver o guia Ligar Projetos Independentes para o fluxo completo.

Dois momentos distintos

Os erros 77, 78, 79 e 84 e o informativo 80 aparecem na compilação isolada de um projeto (synesis compile projeto.synp). Os erros 81, 82 e o aviso 83 só aparecem no passo de linkagem, quando dois ou mais projetos são compilados juntos (synesis compile p1.synp p2.synp).

11.1 Erro 77 — Valor de identidade duplicado (ERRO)

Dois SOURCEs do mesmo projeto têm o mesmo valor num campo IDENTIFIES.

  • Exemplo que causa o erro
  • Como corrigir

Template declarando a chave primária da entidade:

FIELD lattes_id TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD

Anotação com o mesmo valor em dois SOURCEs:

SOURCE @curriculo_maria
    lattes_id: 3474000000000167
END SOURCE

SOURCE @curriculo_maria_2020
    lattes_id: 3474000000000167
END SOURCE

IDENTIFIES declara uma chave primária: cada valor deve identificar um único SOURCE. Se os dois blocos são a mesma entidade, unifique-os num só SOURCE. Se são entidades distintas, corrija o valor duplicado.

A comparação é por igualdade exata após remover espaços nas pontas — sem normalização de maiúsculas/minúsculas.

11.2 Erro 78 — Modificador de ligação fora de SOURCE (ERRO)

IDENTIFIES ou REFERS TO usado em campo que não é SCOPE SOURCE.

  • Exemplo que causa o erro
  • Como corrigir
FIELD autor_citado TYPE TEXT
    SCOPE ITEM
    REFERS TO researcher
END FIELD

A ligação entre projetos opera sobre SOURCEs — as unidades de coleta —, não sobre ITEMs ou conceitos da ontologia. Mova o modificador para um campo SCOPE SOURCE, ou remova-o:

FIELD autor_citado TYPE TEXT
    SCOPE SOURCE
    REFERS TO researcher
END FIELD

11.3 Erro 79 — Valor obrigatório ausente na bibliografia (ERRO)

Um campo declarado REQUIRED ... ON BIBLIOGRAPHY não tem valor correspondente na entrada .bib do SOURCE.

  • Exemplo que causa o erro
  • Como corrigir

Template exigindo que o valor venha do .bib, não do texto:

SOURCE FIELDS
    REQUIRED lattes_id ON BIBLIOGRAPHY
END SOURCE FIELDS

Entrada .bib sem o campo:

@misc{curriculo_maria,
    author = {Silva, Maria},
    title  = {Currículo Lattes},
    year   = {2026}
    % lattes_id ausente
}

Adicione o campo à entrada .bib:

@misc{curriculo_maria,
    author   = {Silva, Maria},
    title    = {Currículo Lattes},
    year     = {2026},
    lattes_id = {3474000000000167}
}

Ou remova a exigência ON BIBLIOGRAPHY do template.

Por que ON BIBLIOGRAPHY

Alguns identificadores (ID Lattes, ORCID, CNPJ) são metadados da fonte, não conteúdo extraível do texto do documento. Declarar ON BIBLIOGRAPHY diz ao compilador que o valor vive na entrada .bib — exigi-lo no bloco SOURCE mentiria sobre a natureza do dado. Campos assim são excluídos da verificação do erro 21 (campo obrigatório ausente no SOURCE).

11.4 Informativo 80 — Referência externa declarada (INFO)

O projeto declara REFERS TO para uma entidade que não existe nele. Não é erro nem aviso.

  • Quando aparece
  • O que fazer
FIELD autor_id TYPE TEXT
    SCOPE SOURCE
    REFERS TO researcher
END FIELD

Ao compilar este projeto sozinho:

INFO  abstracts.synp
  Este projeto referencia a entidade externa `researcher` (`REFERS TO` em `autor_id`).
  As ligacoes nao estao materializadas neste artefato. Para resolve-las,
  compile este projeto junto com o projeto que declara `IDENTIFIES researcher`.

Nada — é o comportamento esperado. Uma referência externa só se resolve no passo de linkagem:

synesis compile lattes.synp abstracts.synp

A mensagem é emitida uma vez por entidade, em nível INFO, justamente para documentar que há ligações a materializar sem poluir o painel de problemas com um aviso recorrente.

11.5 Erro 81 — Entidade com dono duplicado (ERRO)

Dois projetos declaram IDENTIFIES do mesmo rótulo de entidade. Aparece apenas no passo de linkagem.

  • Exemplo que causa o erro
  • Como corrigir

lattes.synt:

FIELD lattes_id TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD

orcid.synt:

FIELD orcid TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD

Cada rótulo de entidade tem um único corpus proprietário — é a chave primária. Se são esquemas de identificação distintos da mesma pessoa (Lattes e ORCID), o corpus proprietário mantém o IDENTIFIES e o outro passa a apontar para ele:

# orcid.synt — passa a referenciar, não a identificar
FIELD lattes_id TYPE TEXT
    SCOPE SOURCE
    REFERS TO researcher
END FIELD

11.6 Erro 82 — Tipos divergentes na ligação (ERRO)

Campos que participam da mesma entidade têm TYPE diferente. Aparece apenas no passo de linkagem.

  • Exemplo que causa o erro
  • Como corrigir

lattes.synt:

FIELD lattes_id TYPE TEXT
    SCOPE SOURCE
    IDENTIFIES researcher
END FIELD

abstracts.synt:

FIELD autor_id TYPE NUMBER
    SCOPE SOURCE
    REFERS TO researcher
END FIELD

Todos os campos da mesma entidade — o IDENTIFIES e todos os REFERS TO — devem declarar o mesmo TYPE. A divergência indica que os dois lados não modelam a mesma coisa. Alinhe os tipos nos templates.

Este é um erro duro: a linkagem não prossegue, porque comparar valores de tipos distintos produziria casamentos arbitrários.

11.7 Aviso 83 — Referência órfã (AVISO)

Um valor de REFERS TO não casa com nenhum IDENTIFIES. Aparece apenas no passo de linkagem.

  • Quando aparece
  • Quase-casamento
  • Como corrigir
AVISO  abstracts.synp
  O valor `3474000000000999` (`REFERS TO researcher` em `abstracts`) nao tem
  `IDENTIFIES researcher` correspondente — e uma referencia orfa.
  Pode ser esperado (ex. autor externo sem curriculo no corpus). Nenhum no e criado.

Órfãos são frequentemente legítimos: um artigo citando um autor que não tem currículo no corpus é exatamente isso. Por isso é aviso, não erro.

Quando o valor casaria apenas sob normalização de maiúsculas/minúsculas, o aviso é enriquecido:

AVISO  abstracts.synp
  O valor `orcid-0000-1234` (`REFERS TO researcher` em `abstracts`) nao tem
  `IDENTIFIES researcher` correspondente — e uma referencia orfa.
  Casamento proximo: `ORCID-0000-1234` difere apenas em caixa/invisiveis.
  Se sao a mesma entidade, canonize o valor na origem (.bib/SOURCE) — o
  compilador nao normaliza automaticamente (evita fundir entidades distintas).

Se o órfão é esperado, nada a fazer. Se o quase-casamento indica a mesma entidade, corrija o valor na origem (no .bib ou no bloco SOURCE).

Por que o compilador não normaliza sozinho

Normalizar caixa automaticamente fundiria entidades que a fonte considera distintas — dois códigos de projeto AB-100 e ab-100 podem ser deliberadamente diferentes. O compilador detecta e sugere, mas nunca funde. A decisão é do pesquisador, registrada na fonte.

11.8 Erro 84 — SHARED usado fora de ONTOLOGY (ERRO)

A palavra SHARED foi aplicada a um INCLUDE que não é de ontologia.

  • Exemplo que causa o erro
  • Como corrigir
PROJECT Estudo_Aceitacao
    TEMPLATE "modelo.synt"
    INCLUDE SHARED BIBLIOGRAPHY "../compartilhado/referencias.bib"
END PROJECT

INCLUDE SHARED só é válido para ONTOLOGY:

INCLUDE SHARED ONTOLOGY "../compartilhado/vocabulario.syno"

A palavra SHARED autoriza um alvo fora da pasta do projeto. Essa exceção existe para compartilhar o vocabulário conceitual entre projetos do mesmo estudo — deixá-la valer para bibliografia ou anotações abriria a contenção para casos que a motivação não pediu. Remova o SHARED e mova o arquivo para dentro da pasta do projeto.

Não é possível reproduzi-los com arquivos sintaticamente válidos — eles são, por definição, erros de gramática.
