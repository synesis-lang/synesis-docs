Como Criar e Validar Chains

Guia prático para modelar relações causais estruturadas

1 Como Criar e Validar Chains

Este guia mostra como construir chains (cadeias) para expressar relações entre conceitos de forma sistemática e auditável.

Você deve usar este guia se:

  • Precisa expressar relações de causalidade, influência ou mediação
  • Quer construir mapas de relações entre conceitos
  • Precisa validar a consistência das suas chains
  • Quer extrair redes de relações para análise ou visualização

1.1 O que é uma Chain?

Uma chain é uma sequência de conceitos ligados por ->, que expressa como eles se relacionam. Quando o campo declara relações, cada ligação é nomeada.

conceito_a -> RELACAO -> conceito_b
ITEM @entrevista_01
    chain: custo_alto -> INIBE -> adocao
END ITEM

Lê-se: “custo_alto INIBE adocao”.

1.2 Como Declarar o Campo

As relações são declaradas no template, no campo de tipo CHAIN. O nome do campo é livre; ARITY é obrigatório.

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    DESCRIPTION Relação entre conceitos afirmada pela fonte
    RELATIONS
        CAUSA: X é causa direta de Y
        INIBE: X reduz a probabilidade ou a intensidade de Y
        FAVORECE: X promove ou facilita Y
        MEDIA: X intermedeia o efeito sobre Y
        CORRELACIONA: X e Y ocorrem juntos, sem direção causal definida
    END RELATIONS
    GUIDELINES
        Registre somente relações que o trecho afirma.
        Teste CAUSA ou FAVORECE: sem X, Y deixaria de ocorrer? Então CAUSA.
        Correto: custo_alto -> INIBE -> adocao (o trecho diz que o preço afasta)
        Errado: custo_alto -> CAUSA -> adocao (o trecho não afirma causa)
    END GUIDELINES
END FIELD
  • ARITY >= 2 aceita uma ligação simples
  • ARITY >= 3 exige um mediador (antecedente → mediador → resultado)

Se o campo não declarar RELATIONS, a cadeia é simples (a -> b): registra a associação, sem nomeá-la.

1.3 Como Criar Chains Simples

1.3.1 Dois conceitos

ITEM @entrevista_01
    quote: "O preço elevado desestimula a compra"
    memo: Barreira econômica identificada
    chain: preco_elevado -> INIBE -> decisao_de_compra
END ITEM

Quando usar: relações diretas.

1.3.2 Vários passos

ITEM @entrevista_01
    chain: falta_de_treinamento -> CAUSA -> baixa_competencia -> INIBE -> adocao
END ITEM

Lê-se: “falta de treinamento CAUSA baixa competência, que INIBE a adoção”. Cada par consecutivo vira uma relação (tripla) nas exportações.

Quando usar: para registrar mecanismos com elementos intermediários.

1.4 Como Escolher Relações

Um conjunto pequeno e bem separado vale mais que muitas relações sobrepostas. Se duas relações não se distinguem numa frase, são a mesma.

Relação Significado Exemplo
CAUSA X é causa direta de Y erro_de_software -> CAUSA -> falha_do_sistema
INIBE X reduz ou impede Y custo_alto -> INIBE -> adocao
FAVORECE X promove ou facilita Y treinamento -> FAVORECE -> usabilidade
MEDIA X intermedeia suporte_tecnico -> MEDIA -> satisfacao
CORRELACIONA ocorrem juntos, sem direção rotatividade -> CORRELACIONA -> desengajamento

1.5 Como Construir Estruturas

1.5.1 Divergentes (um causa vários)

ITEM @doc_01
    chain: falta_de_recursos -> INIBE -> investimento_em_ia
    chain: falta_de_recursos -> INIBE -> treinamento_de_equipe
    chain: falta_de_recursos -> CAUSA -> priorizacao_de_curto_prazo
END ITEM

1.5.2 Convergentes (vários causam um)

ITEM @doc_02
    chain: facilidade_de_uso -> FAVORECE -> satisfacao
    chain: suporte_responsivo -> FAVORECE -> satisfacao
    chain: custo_acessivel -> FAVORECE -> satisfacao
END ITEM

1.5.3 Com mediadores

ITEM @doc_03
    chain: capacitacao -> FAVORECE -> competencia_da_equipe -> FAVORECE -> qualidade
END ITEM

1.6 Como Qualificar uma Afirmação

Uma chain diz que uma relação existe. As fontes raramente dizem só isso: elas propõem hipóteses, testam, negam. Emparelhe a chain com seus qualificadores num BUNDLE:

ITEM FIELDS
    REQUIRED quote
    OPTIONAL BUNDLE chain, estatuto
END ITEM FIELDS

FIELD estatuto TYPE ENUMERATED
    SCOPE ITEM
    DESCRIPTION Como o texto apresenta a relação imediatamente anterior
    VALUES
        Afirmada: apresentada como achado ou fato
        Hipotetica: proposta sem ser afirmada
        Negada: o texto afirma que não ocorre
    END VALUES
END FIELD
ITEM @artigo_01
    quote: "O treinamento reduziu os cliques, mas não aumentou as denúncias."
    chain: treinamento -> INIBE -> cliques
    estatuto: Afirmada
    chain: treinamento -> FAVORECE -> denuncias
    estatuto: Negada
END ITEM

Cada chain: emparelha, pela posição, com o seu estatuto:. Sem o qualificador, uma hipótese e um achado ficam iguais em todas as exportações.

1.7 Como Validar Chains

1.7.1 Validação automática

synesis compile analysis.synp --check-codes

O compilador confere:

  1. a estrutura (alternância conceito → relação → conceito)
  2. se cada relação está declarada no campo
  3. se a aridade é atendida
  4. se os conceitos têm definição na ontologia
Mensagem Causa Solução
Relation 'Y' not declared in the template relação fora de RELATIONS use uma declarada ou acrescente-a ao template
Concept 'A B' contains spaces conceito com espaços use A_B
Simple chain in 'chain' but the template requires named relations falta a relação A -> REL -> B
Qualified chain with incorrect structure termina em relação ou falta um conceito conceito, relação, conceito
Chain with N element(s), the template requires >= M aridade complete a cadeia
Code 'X' is not defined in the organizing model conceito sem bloco defina em um .syno (aviso)

Detalhes no Guia de Erros.

1.7.2 Validação semântica manual

  1. Direção: A → B faz sentido, ou deveria ser B → A?
  2. Tipo: é INIBE mesmo, ou CAUSA?
  3. Completude: falta um mediador?
  4. Evidência: o trecho sustenta a relação?

O compilador confere a forma; a leitura é sua. Para chains geradas por IA, use o pipeline de revisão.

1.8 Como Extrair e Analisar Chains

1.8.1 CSV

synesis compile analysis.synp --csv saida/

saida/chains.csv, uma linha por tripla:

bibref,from_code,relation,to_code,source_file,source_line,source_column
'@entrevista_01,custo_alto,INIBE,adocao,anotacoes.syn,8,5

1.8.2 JSON

Cada item do corpus traz as suas cadeias, e indices.triples reúne todas, com a origem:

{
  "indices": {
    "triples": [
      {
        "from": "custo_alto",
        "relation": "INIBE",
        "to": "adocao",
        "source_item": "entrevista_01_item0001",
        "location": {"file": "anotacoes.syn", "line": 8, "column": 5}
      }
    ]
  }
}

1.9 Como Visualizar Chains

1.9.1 No VS Code

Com a extensão Synesis: Ctrl+Alt+G (por fonte), Ctrl+Alt+F (arquivo) ou Ctrl+Alt+I (item sob o cursor).

1.9.2 Em grafo

pip install synesis-graph
synesis-graph html --project analysis.synp --output grafo.html --all

Para análise de rede, veja Como exportar para Neo4j.

1.10 Padrões Comuns

1.10.1 Barreira → inibição

chain: falta_de_informacao -> INIBE -> confianca -> INIBE -> adocao

1.10.2 Facilitador → promoção

chain: demonstracao_pratica -> FAVORECE -> compreensao -> FAVORECE -> adocao

1.10.3 Ciclo de realimentação

Registre cada direção como a fonte a afirma, em cadeias separadas, usando os mesmos nomes de conceito:

ITEM @doc_04
    chain: satisfacao -> FAVORECE -> engajamento
    chain: engajamento -> FAVORECE -> satisfacao
END ITEM

Ciclos entre cadeias são permitidos: elas registram o que as fontes afirmam. A proibição de ciclos vale só para a hierarquia declarada na ontologia.

1.10.4 Dilema (trade-off)

ITEM @doc_05
    chain: automacao_completa -> FAVORECE -> eficiencia
    chain: automacao_completa -> INIBE -> flexibilidade
END ITEM

1.11 Como Iterar

1.11.1 1. Rascunho

ITEM @doc_01
    quote: "A tecnologia ajuda, mas é cara"
    chain: tecnologia -> FAVORECE -> eficiencia
    chain: custo -> INIBE -> adocao
END ITEM

1.11.2 2. Refinamento

Depois de várias fontes, consolide os conceitos recorrentes:

ITEM @doc_01
    chain: utilidade_percebida -> FAVORECE -> intencao_de_uso
    chain: custo_percebido -> INIBE -> intencao_de_uso
    chain: intencao_de_uso -> FAVORECE -> adocao
END ITEM

1.11.3 3. Comparação entre fontes

# Fonte A
ITEM @fonte_a
    chain: treinamento -> FAVORECE -> competencia -> FAVORECE -> adocao
END ITEM

# Fonte B
ITEM @fonte_b
    chain: mentoria -> FAVORECE -> competencia -> FAVORECE -> adocao
END ITEM
# Observação: "competencia" é um mediador recorrente

1.12 Como Documentar Decisões

Registre a justificativa num campo de memo (de preferência no mesmo BUNDLE da cadeia) e use comentários para decisões de método:

ITEM @policy_doc
    quote: "O investimento em infraestrutura digital reduziu custos operacionais"
    memo: Relação confirmada por dados quantitativos (Tabela 3)
    chain: infraestrutura_digital -> INIBE -> custos_operacionais
    # DECISÃO 2026-02-04: INIBE em vez de CAUSA, pela natureza gradual do efeito
END ITEM

1.13 Quando NÃO Usar Chains

  1. Descrições simples. Se a fonte só menciona um tema, use um campo CODE:

    # Forçado
chain: custo -> DESCREVE -> entrevista

# Apropriado
code: custo

  2. Relações incertas. Se não há direção ou tipo, registre o código e anote a incerteza no memo.

  3. Taxonomias. “É um tipo de” é uma decisão conceitual do projeto: declare-a na ontologia com ROLE HIERARCHY. Se for algo que as fontes afirmam, é uma cadeia — e pode ser levada a um vocabulário com MAP RELATIONS.

1.14 Exercício Prático

“A falta de suporte técnico adequado gerou frustração na equipe, o que levou à baixa adesão ao novo sistema.”

Construa a cadeia que captura a relação.

1.14.1 Solução proposta

ITEM @entrevista_gerente
    quote: "A falta de suporte técnico adequado gerou frustração na equipe, o que levou à baixa adesão ao novo sistema."
    memo: Cadeia temporal explícita: suporte insuficiente, frustração, baixa adesão
    code: suporte_tecnico_inadequado, frustracao, baixa_adesao
    chain: suporte_tecnico_inadequado -> CAUSA -> frustracao -> CAUSA -> baixa_adesao
END ITEM
  • Três conceitos, duas relações
  • CAUSA declarada no template
  • A cadeia segue a sequência do trecho
  • O memo explicita a interpretação

Repare nos nomes: o conceito é baixa_adesao, e a relação é a que o texto afirma (“levou à”). Escrever frustracao -> INIBE -> baixa_adesao inverteria o sentido.
