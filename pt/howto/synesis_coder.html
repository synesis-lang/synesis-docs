synesis-coder: Codificação Qualitativa com IA

Como gerar anotações, ontologias e processar corpora inteiros pela linha de comando

1 synesis-coder: Codificação Qualitativa com IA

O synesis-coder automatiza a codificação qualitativa com um modelo de linguagem (Claude por padrão, ou qualquer servidor compatível com a API OpenAI). A ferramenta lê o template do seu projeto (.synt) e gera blocos Synesis válidos (SOURCE, ITEM, ONTOLOGY) seguindo os campos, relações, valores permitidos e instruções (GUIDELINES) do template.

Use este guia se você:

  • quer codificar um trecho selecionado de um arquivo .syn
  • precisa processar em lote um corpus de resumos (.bib) ou de registros (.toml)
  • quer codificar um documento longo (entrevista, relatório)
  • precisa gerar definições para os conceitos já usados no corpus
  • quer revisar o que a IA anotou antes de incorporar
Nada é fixo no código

O synesis-coder não conhece nenhum nome de campo, relação ou valor. Tudo vem do template, lido pelo compilador. Se você muda o template, a IA segue as novas regras.

A IA propõe, o compilador confere, você decide

Compilar sem erros mostra que a forma está correta, não que a leitura está certa. Revise o que foi gerado (Seção 11). Dados enviados ao modelo saem do seu computador, salvo quando o modelo roda localmente.

2 Instalação

Requer Python 3.10+. O compilador (synesis ≥ 0.16.0) é instalado como dependência.

pip install synesis-coder
synesis-coder --version
# synesis-coder, version 0.15.1

2.1 Configuração

Crie um arquivo .env na pasta do projeto (de onde você executa os comandos):

# Anthropic (padrão)
ANTHROPIC_API_KEY=sk-ant-...

# Opcional: idioma dos campos de texto livre
SYNESIS_CODER_LANGUAGE=pt-BR

# Opcional: outro modelo (padrão: claude-opus-4-6)
# SYNESIS_CODER_MODEL=claude-sonnet-4-6

Para um servidor compatível com a API OpenAI (Ollama local, OpenRouter, RunPod…):

SYNESIS_CODER_BACKEND=openai
SYNESIS_CODER_API_URL=http://localhost:11434
SYNESIS_CODER_MODEL=nome-do-modelo
# SYNESIS_CODER_API_KEY=...   # dispensável no Ollama local

A precedência é: variável de ambiente > .env do projeto > arquivo de padrões indicado em SYNESIS_CODER_ENV_FILE. Nunca inclua o .env no controle de versão.

4 Modo item: codificar um trecho

synesis-coder item \
  --project social_acceptance.synp \
  --bibref ashworth2019 \
  --text "Community trust and environmental concern are the most important factors determining willingness to participate in renewable energy projects."

A saída é um bloco ITEM compilável, com os campos do seu template:

ITEM @ashworth2019
    text: Community trust and environmental concern are the most
          important factors determining willingness to participate
          in renewable energy projects.

    note: Reveals dual-factor mechanism where trust and environmental
          concern independently drive participation willingness
    chain: Community_Trust -> INFLUENCES -> Participation

    note: Environmental concern acts as value-based enabler of
          engagement with renewable energy
    chain: Environmental_Concern -> ENABLES -> Participation
END ITEM

Por padrão (--format plain) sai só o bloco Synesis, próprio para redirecionar:

synesis-coder item --project social_acceptance.synp --bibref ashworth2019 \
  --text "Local ownership models significantly reduce opposition." \
  >> anotacoes/ashworth2019.syn

--format verbose acrescenta um cabeçalho com o modelo, o resultado da validação e o horário.

5 Modo abstract: corpus bibliográfico

Processa um .bib e gera SOURCE e ITEM para cada referência que tenha resumo.

synesis-coder abstract \
  --project social_acceptance.synp \
  --input corpus/references.bib \
  --output-dir anotacoes/ \
  --concurrent 5
--output-dir é uma pasta

Não é um nome de arquivo. O nome antigo --output continua aceito como sinônimo.

Cada bloco é validado pelo compilador antes de ser gravado.

5.1 Formato da saída

Por padrão, tudo vai para um único annotations.syn. Escolha uma das alternativas para campanhas grandes:

Opção Resultado
--per-reference um .syn por referência (mais fácil de revisar e refazer)
--split-every 100 annotations_0001.syn, annotations_0002.syn… com 100 referências cada

Se o annotations.syn já existir, use --overwrite ou --backup.

5.2 Campanhas longas

synesis-coder abstract --project p.synp --input refs.bib --output-dir out/ \
  --per-reference --resume --batch-size 25 --cooldown auto
  • --resume pula o que já foi anotado com sucesso na pasta de saída; os registros que falharam são refeitos
  • --batch-size processa em lotes; entre eles o projeto é recarregado, e os conceitos já gerados entram no contexto
  • --cooldown define a pausa entre lotes (auto, segundos ou 0)
Opções do modo abstract
Opção Obrigatória Descrição
--project sim arquivo .synp
--input sim .bib com resumos
--output-dir não pasta de saída (padrão: a atual)
--concurrent não chamadas simultâneas
--batch-size não referências por lote (padrão: 25)
--per-reference / --split-every N não formato da saída
--resume não retoma uma campanha
--overwrite / --backup não arquivo existente

6 Modo dataset: registros estruturados

Para formulários, currículos, postagens ou qualquer corpus com um registro TOML por fonte. O .synp declara INCLUDE DATASET; os campos ON DATASET são resolvidos pelo compilador, e os campos interpretativos são gerados pelo modelo a partir das seções indicadas em CONTEXT FROM DATASET.

synesis-coder dataset --project lattes.synp --output-dir anotacoes/
Opções do modo dataset
Opção Descrição
--output-dir pasta de saída; um .syn por registro
--single-file um único dataset.syn
--dataset troca o padrão de INCLUDE DATASET só nesta execução (bom para testar um registro)
--concurrent chamadas simultâneas

7 Modo document: documentos longos

Divide um documento em trechos com sobreposição e gera um .syn. A referência (--bibref) precisa existir no .bib.

synesis-coder document \
  --project nave.synp \
  --bibref entrevista_01 \
  --input transcricoes/entrevista_01.txt \
  --output anotacoes/entrevista_01.syn
  • --chunk-size: tamanho máximo do trecho em caracteres (padrão: 12.000)
  • --overlap: sobreposição entre trechos (padrão: 2.400)
  • os conceitos criados nos trechos anteriores entram no contexto dos seguintes
Dimensionando o trecho

Templates com vários campos CHAIN e GUIDELINES extensas pedem trechos menores (8.000 a 10.000 caracteres).

8 Modo ontology: definir os conceitos

Analisa o corpus anotado, reúne evidência para cada código (frequência, fontes, relações, coocorrências, exemplos) e gera blocos ONTOLOGY fundamentados nesses dados.

synesis-coder ontology --project social_acceptance.synp --output ontologia.syno

O contexto de cada conceito inclui:

  • frequência e número de fontes
  • relações afirmadas pelas fontes (até 15), que o modelo não deve copiar como valor de campo
  • coocorrências (até 20)
  • exemplos de excertos (até 3)

Um bloco gerado:

ONTOLOGY Cost
    topic: Economics
    aspect: 11
    dimension: 2
    confidence: HIGH
    reasoning: Core economic factor representing financial expenditure.
        Mainly constrains deployment while enabling market penetration
        when reduced.
    description: Economic factor representing financial expenditure
        associated with energy technologies and systems.
END ONTOLOGY

Campos ORDERED são gravados pelo índice (aspect: 11).

8.1 Como o arquivo é atualizado

  • O .syno é editado bloco a bloco: um bloco existente recebe só os campos gerados; comentários, outros campos e a ordem ficam como estavam
  • --update gera apenas o que falta: conceitos sem bloco e campos obrigatórios ausentes
  • Campos CODE e CHAIN da ontologia são estrutura e não são gerados por este modo; rótulos (ROLE LABEL) ficam para a fase de sinônimos
  • Use --backup para guardar uma cópia; --prompt-only para ver o prompt

8.2 Blocos rejeitados não contaminam o .syno

Um bloco que não passa na validação, depois das tentativas de correção, vai para um arquivo à parte (ontologia.syno.rejected). O .syno continua compilável.

8.3 Geração estruturada (JSON Schema)

Quando o modelo suporta saída estruturada, o synesis-coder pede apenas os valores dos campos, com um JSON Schema derivado do template, e monta o bloco em código. Isso elimina por construção os erros de sintaxe. Sem suporte, a ferramenta usa texto livre; a validação pelo compilador é a mesma.

O template precisa ter ao menos um campo SCOPE ONTOLOGY.

9 Fases do modelo organizador: phase, review, consolidate

Com blocos PHASE no .synp, o modelo organizador é produzido em fases — definições, sinônimos, taxonomia. O tipo de cada fase sai dos papéis (ROLE) dos campos que ela produz.

synesis-coder phase projeto.synp --list          # o plano e a conexão de cada fase
synesis-coder phase projeto.synp definicoes      # executa uma fase
synesis-coder phase projeto.synp taxonomia --dry-run
synesis-coder review projeto.synp taxonomia --sample 100 --stratify depth
synesis-coder review projeto.synp taxonomia --score o.taxonomia.review_edge.csv
synesis-coder consolidate projeto.synp voice_phishing --into vishing
synesis-coder consolidate projeto.synp voice_phishing --revert
  • Cada execução grava um manifesto (<destino>.<fase>.manifest.json) com o que foi proposto, aplicado ou rejeitado; uma execução interrompida é retomada, e repetir sem mudança nas entradas não chama o modelo
  • review sorteia uma amostra estratificada (--unit edge|label|concept) e gera um CSV para julgamento (judgement: correct/wrong); --score estima a precisão com intervalo de confiança
  • consolidate funde um nome duplicado no conceito que vale, de forma reversível
  • Modelo e conexão por fase: SYNESIS_CODER_PHASE_<NOME>_MODEL, _BACKEND, _API_URL, _API_KEY

Detalhes em O Modelo Organizador.

10 Conferir citações sem IA: anchor

Antes de gastar com revisão por modelo, confira se cada citação existe na fonte:

synesis-coder anchor anotacoes/ref.syn --project projeto.synp
synesis-coder anchor anotacoes/entrevista_01.syn --project p.synp \
  --source-dir transcricoes/ --json relatorio.json

Cada citação de cada campo QUOTATION recebe um de três estados:

Estado Significado
found está na fonte (com normalização de espaços, aspas e caixa)
not found não está: o modelo reescreveu em vez de citar
unverifiable não há texto-fonte para aquela referência

As fontes são os arquivos <bibref>.txt ou .md de --source-dir e, em seguida, os resumos do .bib. --literal compara sem normalização; --strict sai com código 1 se alguma citação não for encontrada ou verificável.

11 O pipeline ACT: revisar antes de incorporar

A extração inicial produz anotações que precisam de revisão. O pipeline separa propor uma correção de aceitá-la, e nenhuma fase altera o .syn original sem pedido explícito.

O formato intermediário é o .synr: um arquivo de revisão com blocos # REVISION, que não entra no INCLUDE do projeto.

.syn  ──critique──▶  .synr  ──normalize──▶  .synr  ──incorporate──▶  .syn

11.1 critique: propor

Um modelo relê cada ITEM contra o texto-fonte e o template.

synesis-coder critique anotacoes/entrevista_01.syn --project nave.synp \
  --sensitivity standard
Opções do modo critique
Opção Descrição
--sensitivity lenient, standard (padrão), strict ou um número de 0 a 1
--output caminho do .synr
--model modelo crítico (SYNESIS_CODER_CRITIQUE_MODEL)
--concurrent, --debug execução

Sensibilidade alta gera mais falsos positivos, não mais verdade. A crítica pode usar outra conexão (SYNESIS_CODER_CRITIQUE_BACKEND, _API_URL, _API_KEY), o que reduz o viés de o gerador avaliar a si mesmo.

11.2 normalize: canonizar códigos

Olha o corpus inteiro e unifica variantes (Social_Acceptance, social_acceptance, SocialAcceptance).

synesis-coder normalize anotacoes/*.synr --project social_acceptance.synp \
  --confidence 0.65 --inventory inventario_codigos.txt

11.3 incorporate: aceitar

Aplica o .synr e grava o .syn final validado. Não usa IA: é determinístico e repetível.

synesis-coder incorporate anotacoes/entrevista_01.synr \
  --output anotacoes/entrevista_01_final.syn

Uma correção ambígua é recusada, não adivinhada. Use --backup quando o destino já existir.

11.4 refine: reextrair (opcional)

Em vez de aplicar correções pontuais, reextrai os ITEMs marcados, com a crítica no contexto. Só aceita uma versão com escore de suspeita menor.

synesis-coder refine anotacoes/entrevista_01.syn --project nave.synp --max-iter 2

Saída padrão: <nome>_refined.syn. O arquivo de entrada nunca é sobrescrito sem --overwrite.

11.5 Ordem recomendada

synesis-coder anchor      anotacoes/annotations.syn --project estudo.synp   # 1. grátis
synesis-coder critique    anotacoes/annotations.syn --project estudo.synp   # 2. propor
#                         (leia o .synr)                                    # 3. decidir
synesis-coder normalize   anotacoes/annotations.synr --project estudo.synp  # 4. canonizar
synesis-coder incorporate anotacoes/annotations.synr \
              --output anotacoes/final.syn --backup                         # 5. aceitar
synesis compile estudo.synp                                                 # 6. compilar

O passo 3 não é decoração: o .synr é texto legível, feito para você decidir o que entra nos seus dados.

12 Outros comandos

12.1 suggest: sugerir códigos

Retorna códigos do projeto pertinentes a um trecho, sem gerar um bloco. Códigos que ainda não existem vêm marcados [NEW].

synesis-coder suggest --project social_acceptance.synp \
  --text "Local ownership models significantly reduce opposition."

12.2 finetune: preparar dados de treino

Gera ou enriquece um JSONL no formato Alpaca.

synesis-coder finetune --project social_acceptance.synp \
  --output dataset_enriquecido.jsonl --enrich vary --enrich didactic
--enrich Efeito
vary (padrão) variações de formulação
didactic versões com explicação
counterfactual contraexemplos
Qualificadores das relações

Os pares gerados a partir do projeto não levam o qualificador de um BUNDLE com CHAIN (por exemplo, o estatuto “hipotética”). Para um dataset fiel, declare a composição num bloco EXPORT ALPACA com MAP e use o JSONL em --input.

13 Integração com VS Code

Na extensão Synesis, o modo item codifica o texto selecionado num .syn:

  1. selecione o trecho
  2. clique com o botão direito → Synesis: Code Selection (ou Ctrl+Shift+I / Cmd+Shift+I)

A extensão detecta o bibref do bloco sob o cursor, executa o synesis-coder na pasta do projeto (lendo o .env dela) e substitui a seleção pelo ITEM gerado. É possível cancelar na notificação de progresso. Se o executável não estiver no PATH:

{
  "synesisExplorer.coder.path": "C:/Python312/Scripts/synesis-coder.exe"
}

14 Como funciona por dentro

1. carregar    o compilador lê o projeto: campos, GUIDELINES, relações,
               conceitos existentes, DESCRIPTION e QUESTIONS
2. montar      prompt de sistema (estável, aproveita o cache da API)
               + prompt da vez (referência e texto)
3. gerar       chamada ao modelo (saída estruturada quando possível),
               com limites de requisições e tokens
4. validar     o compilador confere; se houver erros, eles voltam ao
               modelo para correção (até 3 tentativas)
5. gravar      só blocos válidos

A instrução de cada campo vem, nesta ordem, de GUIDELINES, de DESCRIPTION ou, sem ambas, de uma instrução genérica pelo tipo. Por isso vale escrever GUIDELINES em todo campo.

16 Erros comuns

16.1 synesis-coder não encontrado

O executável não está no PATH. Confira com pip show synesis-coder, use python -m synesis_coder ou configure o caminho na extensão.

16.2 Chave de API ausente

Crie o .env na pasta de onde o comando é executado, ou exporte a variável. Um .env ao lado da instalação não é lido.

16.3 Aviso de campo sem GUIDELINES

O modelo recebe apenas a DESCRIPTION (ou nada) para esse campo. Escreva as instruções no template.

16.4 O modelo não consegue produzir um bloco válido

Depois das tentativas, o bloco é registrado como falha (no modo ontology, no arquivo .rejected). Veja a mensagem do compilador, revise as GUIDELINES do campo envolvido e rode de novo (--resume no modo abstract).
