Synesis para Pesquisa Qualitativa

Tutorial prático para pesquisadores de humanidades

1 Bem-vindo, Pesquisador!

Neste tutorial, nós vamos criar juntos um projeto de análise qualitativa usando Synesis. Se você trabalha com entrevistas, análise documental, teoria fundamentada ou análise temática, este guia é para você.

O que você vai construir:

  • Um projeto de análise de entrevistas
  • Um sistema de codificação conceitual
  • Relações causais entre conceitos
  • Exportações para análise quantitativa

Pré-requisitos:

  • Python 3.10+ instalado e o compilador (pip install synesis)
  • Um gerenciador de referências (Zotero recomendado, mas opcional)
  • Familiaridade básica com pesquisa qualitativa
Novo no Synesis?

Se você nunca usou Synesis, comece com Getting Started. Este tutorial assume que você já conhece os comandos básicos.

1.1 Nosso Cenário de Pesquisa

Vamos trabalhar com um estudo fictício sobre resistência à adoção de telemedicina em comunidades rurais. Imagine que você conduziu 3 entrevistas semiestruturadas e agora precisa analisar os dados.

1.2 Passo 1: Preparar Nossas Fontes

Crie uma pasta para o projeto:

mkdir analise-telemedicina
cd analise-telemedicina

Crie referencias.bib com as referências das entrevistas. As chaves são neutras e não identificam os participantes:

@misc{entrevista01,
  author = {Participante 01},
  title = {Entrevista sobre acesso à saúde},
  year = {2026},
  note = {Moradora de comunidade rural, 45 minutos (dados fictícios)}
}

@misc{entrevista02,
  author = {Participante 02},
  title = {Entrevista sobre tecnologia e saúde},
  year = {2026},
  note = {Morador de comunidade rural, 60 minutos (dados fictícios)}
}

@misc{entrevista03,
  author = {Participante 03},
  title = {Entrevista, perspectiva profissional},
  year = {2026},
  note = {Médica rural, 40 minutos (dados fictícios)}
}
Checkpoint ✓

Você deve ter a pasta analise-telemedicina/ com o arquivo referencias.bib e suas 3 entrevistas.

1.3 Passo 2: Definir Nosso Template

Crie template.synt, adaptado à análise qualitativa:

TEMPLATE analise_qualitativa version: "1.0"

# ============================================
# CAMPOS DE SOURCE
# ============================================

SOURCE FIELDS
    REQUIRED tipo_fonte
END SOURCE FIELDS

FIELD tipo_fonte TYPE ENUMERATED
    SCOPE SOURCE
    DESCRIPTION Quem fala na fonte
    VALUES
        Usuario: Morador atendido pelo serviço
        Profissional: Profissional de saúde
    END VALUES
END FIELD

# ============================================
# CAMPOS DE ITEM
# ============================================

ITEM FIELDS
    REQUIRED quote, memo, chain
    OPTIONAL contexto
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Excerto textual extraído da entrevista
    GUIDELINES
        Copie a fala literalmente, em uma a três frases.
        Não copie as perguntas do entrevistador.
    END GUIDELINES
END FIELD

FIELD memo TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Memo analítico com a interpretação e o mecanismo identificado
    GUIDELINES
        Interprete a fala; não a repita.
        Separe o que a fonte afirma do que você infere.
    END GUIDELINES
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    DESCRIPTION Cadeia causal ou relacional entre conceitos da ontologia
    RELATIONS
        MEDIA: um fator atenua ou intermedeia o efeito de outro
        FAVORECE: efeito direto positivo (A favorece B)
        INIBE: limita ou restringe (A reduz a viabilidade de B)
        HABILITA: cria condição para que B ocorra
    END RELATIONS
    GUIDELINES
        Registre somente relações que a fala sustenta.
    END GUIDELINES
END FIELD

FIELD contexto TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Nuances do momento da fala (tom, emoção, hesitações)
    GUIDELINES
        Preencha apenas com o que foi registrado durante a entrevista.
    END GUIDELINES
END FIELD

# ============================================
# ONTOLOGIA
# ============================================

ONTOLOGY FIELDS
    REQUIRED descricao, grupo
END ONTOLOGY FIELDS

FIELD descricao TYPE TEXT
    SCOPE ONTOLOGY
    DESCRIPTION Definição do conceito e critério de aplicação
    GUIDELINES
        Defina o conceito e diga quando aplicá-lo.
    END GUIDELINES
END FIELD

FIELD grupo TYPE TOPIC
    SCOPE ONTOLOGY
    DESCRIPTION Grupo temático do conceito
    GUIDELINES
        Use um termo sem espaços.
    END GUIDELINES
END FIELD

Observe: o campo contexto é opcional e registra nuances qualitativas (hesitações, emoções, mudanças de tom).

Checkpoint ✓

Valide o template:

synesis validate-template template.synt

Deve retornar OK.

1.4 Passo 3: Construir Nossa Ontologia

Em pesquisa qualitativa os códigos emergem dos dados; vamos criar os iniciais a partir de uma leitura prévia. Crie ontologia.syno:

ONTOLOGY desconfianca_tecnologica
    descricao: Receio quanto à eficácia de atendimentos médicos remotos, como a dúvida sobre diagnosticar sem exame físico.
    grupo: barreiras
END ONTOLOGY

ONTOLOGY falta_de_infraestrutura
    descricao: Ausência ou precariedade de internet, equipamentos ou energia que inviabilizam o uso.
    grupo: barreiras
END ONTOLOGY

ONTOLOGY preferencia_por_contato_presencial
    descricao: Valorização do encontro face a face, associando a qualidade do atendimento à presença física.
    grupo: barreiras
END ONTOLOGY

ONTOLOGY letramento_digital_baixo
    descricao: Dificuldade com tecnologias digitais, que gera dependência de apoio externo.
    grupo: barreiras
END ONTOLOGY

ONTOLOGY necessidade_urgente
    descricao: Emergência ou falta de alternativa presencial que impulsiona a aceitação.
    grupo: facilitadores
END ONTOLOGY

ONTOLOGY apoio_comunitario
    descricao: Suporte de familiares, vizinhos ou agentes de saúde que intermedeia o acesso.
    grupo: facilitadores
END ONTOLOGY

ONTOLOGY adocao_de_telemedicina
    descricao: Disposição do paciente a utilizar serviços médicos remotos.
    grupo: desfechos
END ONTOLOGY

ONTOLOGY acesso_a_telemedicina
    descricao: Capacidade concreta de conectar-se e usar o serviço remoto.
    grupo: desfechos
END ONTOLOGY

ONTOLOGY uso_de_telemedicina
    descricao: Utilização efetiva de consultas remotas, autônoma ou intermediada.
    grupo: desfechos
END ONTOLOGY

ONTOLOGY aceitacao_de_telemedicina
    descricao: Receptividade à telemedicina após experiência ou percepção de necessidade.
    grupo: desfechos
END ONTOLOGY

ONTOLOGY diagnostico_aprofundado
    descricao: Diagnóstico que requer exame físico, apontado como contexto inadequado à telemedicina.
    grupo: desfechos
END ONTOLOGY
Checkpoint ✓

Você tem 11 conceitos organizados em 3 grupos (barreiras, facilitadores, desfechos). Ao analisar os dados, você pode acrescentar outros.

1.5 Passo 4: Anotar as Entrevistas

Agora vem a parte principal. Crie anotacoes.syn com a primeira entrevista:

SOURCE @entrevista01
    tipo_fonte: Usuario
END SOURCE

ITEM @entrevista01
    quote: "Eu não confio nessas coisas de conversar com médico pelo computador. Como ele vai saber o que eu tenho se não me examinar?"
    memo: Desconfiança quanto à eficácia diagnóstica. A participante associa a qualidade do atendimento à presença física.
    chain: desconfianca_tecnologica -> INIBE -> adocao_de_telemedicina
    contexto: Disse isso logo no início, antes de qualquer pergunta direta sobre telemedicina.
END ITEM

ITEM @entrevista01
    quote: "Aqui a internet cai toda hora. Às vezes fica dois, três dias sem. Como vou marcar consulta?"
    memo: A infraestrutura precária aparece como barreira concreta.
    chain: falta_de_infraestrutura -> INIBE -> acesso_a_telemedicina
    contexto: Falou com a voz mais alta, demonstrando irritação.
END ITEM

Agora é sua vez! Acrescente ao mesmo arquivo a segunda entrevista:

SOURCE @entrevista02
    tipo_fonte: Usuario
END SOURCE

ITEM @entrevista02
    quote: "Tentei usar uma vez que minha neta me ajudou. Foi bom, resolvi sem sair de casa. Mas sozinho eu não consigo, preciso de alguém pra mexer no celular."
    memo: Experiência positiva quando intermediada por familiar. Reconhece o benefício, mas depende de apoio informal.
    chain: apoio_comunitario -> MEDIA -> letramento_digital_baixo -> INIBE -> uso_de_telemedicina
    contexto: Mencionou a neta com gratidão e admitiu a dependência com resignação.
END ITEM

ITEM @entrevista02
    quote: "Quando meu filho ficou internado na capital, a médica daqui falou com o médico de lá pelo vídeo. Foi uma bênção, ela me explicou o caso direitinho."
    memo: Uso bem-sucedido entre profissionais, como continuidade do cuidado em situação crítica.
    chain: necessidade_urgente -> FAVORECE -> aceitacao_de_telemedicina
END ITEM
Dica de Pesquisador

O campo contexto captura o que a transcrição sozinha perde. Ele é valioso na interpretação, e por ser opcional não obriga a inventar o que não foi observado.

E a terceira, com a perspectiva profissional:

SOURCE @entrevista03
    tipo_fonte: Profissional
END SOURCE

ITEM @entrevista03
    quote: "Os pacientes têm dificuldade, mas é mais a internet do que a vontade. Quando funciona, eles gostam."
    memo: A profissional aponta a infraestrutura, e não a resistência cultural, como barreira principal.
    chain: falta_de_infraestrutura -> INIBE -> uso_de_telemedicina
    contexto: Frustração visível ao mencionar a internet.
END ITEM

ITEM @entrevista03
    quote: "Prefiro presencial quando posso, porque vejo coisas que não aparecem na tela. Mas para retorno e dúvida rápida, telemedicina é perfeita."
    memo: Diferencia contextos de uso adequado e inadequado. Não é rejeição, é uso contextualizado.
    chain: preferencia_por_contato_presencial -> HABILITA -> diagnostico_aprofundado
    contexto: Tom pragmático, de quem pondera prós e contras.
END ITEM

1.6 Passo 5: Criar o Arquivo de Projeto

Crie analise.synp para conectar tudo:

PROJECT analise_telemedicina_rural
    TEMPLATE "template.synt"
    INCLUDE BIBLIOGRAPHY "referencias.bib"
    INCLUDE ONTOLOGY "ontologia.syno"
    INCLUDE ANNOTATIONS "anotacoes.syn"

    METADATA
        version: 1.0
        author: Equipe de pesquisa
        created: 2026-01-15
    END METADATA

    DESCRIPTION
    Análise temática sobre barreiras e facilitadores à adoção
    de telemedicina em comunidades rurais (dados fictícios).
    END DESCRIPTION

    QUESTIONS
        Q1: Que barreiras ao uso da telemedicina os entrevistados relatam?
        Q2: O que favorece a aceitação?
    END QUESTIONS
END PROJECT

Repare no recuo: as linhas de texto de DESCRIPTION ficam no mesmo nível da palavra DESCRIPTION.

1.7 Passo 6: Compilar e Analisar

synesis compile analise.synp --stats
Compilation Summary:
  Sources        3
  Items          6
  Model entries  11  (11 concepts)
  Active codes   11
  Chains         6

Exporte os resultados:

synesis compile analise.synp --json resultados/analise.json --csv resultados/csv --xls resultados/analise.xlsx
resultados/
├── analise.json
├── analise.xlsx
└── csv/
    ├── sources.csv
    ├── items.csv
    ├── ontologies.csv
    └── chains.csv

1.7.1 Análise no Excel

Abra analise.xlsx. Há as abas sources, items, ontologies e chains. A aba chains traz uma linha por relação, com a fonte e o local de origem. Um trecho:

bibref from_code relation to_code
@entrevista01 desconfianca_tecnologica INIBE adocao_de_telemedicina
@entrevista01 falta_de_infraestrutura INIBE acesso_a_telemedicina
@entrevista02 apoio_comunitario MEDIA letramento_digital_baixo
@entrevista02 letramento_digital_baixo INIBE uso_de_telemedicina
@entrevista03 falta_de_infraestrutura INIBE uso_de_telemedicina

Com uma tabela dinâmica você conta relações, cruza conceitos com o tipo de fonte e volta ao trecho que sustenta cada linha.

Insight de Análise

falta_de_infraestrutura aparece na fala de uma usuária e na da profissional. Isso sugere investigar a barreira como concreta e sistêmica, não apenas como “resistência cultural”. Três entrevistas levantam a hipótese; não a demonstram.

1.8 Passo 7: Refinar a Análise (Processo Iterativo)

Depois de ver os primeiros padrões, volte aos dados.

1.8.1 7.1 Adicionar novos códigos

Acrescente à ontologia:

ONTOLOGY percepcao_de_exclusao_digital
    descricao: Sentimento de estar à margem por falta de acesso ou domínio de tecnologias digitais.
    grupo: barreiras
END ONTOLOGY

1.8.2 7.2 Refinar códigos existentes

Se um código é ambíguo, divida-o em dois com definições distintas. Se dois códigos são o mesmo conceito, consolide-os (veja ROLE USE).

1.8.3 7.3 Anotar mais e recompilar

Volte às entrevistas, anote trechos que passaram na primeira leitura e compile novamente. Um código ainda sem definição aparece num aviso de resumo; para ver cada ocorrência:

synesis compile analise.synp --check-codes

1.9 Passo 8: Visualizar as Relações

No VS Code, com a extensão Synesis, abra o anotacoes.syn e pressione Ctrl+Alt+F para ver o grafo das relações do arquivo.

Para um grafo que abre no navegador, ou num banco de grafos:

pip install synesis-graph
synesis-graph html --project analise.synp --output resultados/grafo.html --all

Veja synesis-graph e Como exportar para Neo4j.

1.11 Boas Práticas para Pesquisadores

1.11.1 1. Anote progressivamente

Não espere terminar a coleta para começar a anotar: a análise ajuda a ajustar o roteiro.

1.11.2 2. Use memos analiticamente

O campo memo não é para repetir a citação. Interprete, aponte contradições, levante hipóteses, conecte com a teoria.

1.11.3 3. Documente decisões

Registre por que atribuiu um código, nas definições e nos memos. As GUIDELINES do template são o seu protocolo.

1.11.4 4. Revise sistematicamente

A cada 5 a 10 anotações, compile e veja a distribuição. Um código está genérico demais? Outro aparece uma única vez? Há um padrão sem nome?

1.11.5 5. Valide com pares

Compartilhe o .syno e o template. Pergunte se as definições são claras e se há sobreposições.

1.11.6 6. Proteja os participantes

Use chaves neutras, retire dados identificadores e verifique o que vai para serviços de IA.

1.12 Diferenças de Abordagens Metodológicas

1.12.1 Teoria Fundamentada (Grounded Theory)

  • Comece sem ontologia (o compilador resume os códigos sem conceito em um único aviso)
  • Deixe os códigos emergirem dos dados e defina-os depois
  • Use chain para relacionar categorias
  • Itere até a saturação teórica

1.12.2 Análise Temática

  • Defina temas iniciais (dedutivos) ou deixe-os emergir (indutivos)
  • Agrupe os conceitos por um campo TOPIC
  • Use o memo para reflexões sobre temas recorrentes

1.12.3 Análise de Conteúdo

  • Template mais rígido, com campos ENUMERATED e ORDERED
  • Ontologia definida a priori
  • Foco em frequência, a partir das tabelas CSV

1.12.4 Análise Crítica do Discurso

  • Use o campo de contexto extensivamente (prosódia, hesitações, silêncios)
  • Registre estratégias discursivas nos memos
  • Use chain para explicitar pressupostos
