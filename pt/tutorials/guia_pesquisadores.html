Synesis para Pesquisa Qualitativa

Tutorial prático para pesquisadores de humanidades

1 Bem-vindo, Pesquisador!

Neste tutorial, nós vamos criar juntos um projeto de análise qualitativa usando Synesis. Se você trabalha com entrevistas, análise documental, teoria fundamentada ou análise temática, este guia é para você.

O que você vai construir:

  • Um projeto de análise de entrevistas
  • Um sistema de codificação conceitual
  • Relações causais entre conceitos
  • Exportações para análise quantitativa

Pré-requisitos:

  • Python 3.10+ instalado
  • Um gerenciador de referências (Zotero recomendado, mas opcional)
  • Familiaridade básica com pesquisa qualitativa
Novo no Synesis?

Se você nunca usou Synesis, comece com Getting Started primeiro. Este tutorial assume que você já conhece os comandos básicos.

1.1 Nosso Cenário de Pesquisa

Vamos trabalhar com um estudo fictício sobre resistência à adoção de telemedicina em comunidades rurais. Imagine que você conduziu 3 entrevistas semiestruturadas e agora precisa analisar os dados.

1.2 Passo 1: Preparar Nossas Fontes

Primeiro, crie uma pasta para o projeto:

mkdir analise-telemedicina
cd analise-telemedicina

Agora, crie um arquivo texto chamado referencias.bib com as referências de suas entrevistas:

@interview{entrevista_dona_maria2026,
  author = {Maria da Silva},
  title = {Entrevista sobre acesso à saúde},
  year = {2026},
  location = {Vila Rural X},
  type = {Entrevista semiestruturada},
  duration = {45 minutos}
}

@interview{entrevista_sr_joao2026,
  author = {João Santos},
  title = {Entrevista sobre tecnologia e saúde},
  year = {2026},
  location = {Vila Rural Y},
  type = {Entrevista em profundidade},
  duration = {60 minutos}
}

@interview{entrevista_dra_ana2026,
  author = {Ana Costa},
  title = {Entrevista - perspectiva profissional},
  year = {2026},
  role = {Médica rural},
  type = {Entrevista semiestruturada},
  duration = {40 minutos}
}

Salve este arquivo.

Checkpoint ✓

Você deve ter agora: - Pasta analise-telemedicina/ criada - Arquivo referencias.bib com 3 entrevistas

1.3 Passo 2: Definir Nosso Template

Vamos criar um template adaptado para análise qualitativa. Crie template.synt:

TEMPLATE analise_qualitativa
# VERSION 1.0
# DESCRIPTION: "Template para análise temática de entrevistas"

# ============================================
# CAMPOS DE SOURCE
# ============================================

SOURCE FIELDS
    REQUIRED tipo_ref
END SOURCE    

FIELD tipo_ref TYPE ENUMERATED
    SCOPE SOURCE
    DESCRIPTION: "Tipo de referência"
    VALUES
        PRIM: Fonte primária, entrevistas
        SEC: Fonte secundária, páginas da WEB
        REF: Fonte referêncial, especialistas
    END VALUES
END FIELD

# ============================================
# CAMPOS DE ITEM
# ============================================

ITEM FIELDS
    REQUIRED quote, memo, chain, context
END ITEM FIELDS

FIELD quote TYPE QUOTATION
    SCOPE ITEM
    DESCRIPTION Excerto textual extraído das entrevistas
END FIELD

FIELD memo TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Memo analítico explicando a interpretação e mecanismo causal identificado
END FIELD

FIELD chain TYPE CHAIN
    SCOPE ITEM
    ARITY >= 2
    DESCRIPTION Cadeia causal/relacional entre conceitos da ontologia
    RELATIONS
        MEDIA: Condição facilitadora (A facilita que B ocorra)
        FAVORECE: Efeito causal direto (A afeta positivamente B)
        INIBE: Limita ou restringe (A reduz opções ou viabilidade de B)
        HABILITA: Torna possível ou cria condição para (A viabiliza B)
    END RELATIONS
END FIELD

FIELD context TYPE MEMO
    SCOPE ITEM
    DESCRIPTION Nuances qualitativas do momento da fala: tom, emoção, linguagem corporal, hesitações
END FIELD

# ============================================
# ONTOLOGIA
# ============================================

ONTOLOGY FIELDS
    REQUIRED descricao, grupo
END ONTOLOGY FIELDS

Observe: Adicionamos o campo context — isso é útil para registrar nuances qualitativas (como hesitações, emoções, mudanças de tom).

Checkpoint ✓

Valide o template:

synesis check template.synt

Deve retornar: ✓ Template is valid

1.4 Passo 3: Construir Nossa Ontologia

Agora vamos definir os códigos conceituais. Em pesquisa qualitativa, esses códigos emergem dos dados, mas vamos criar alguns iniciais baseados em leitura prévia. Crie ontologia.syno:

ONTOLOGY desconfianca_tecnologica
    descricao: "Receio ou incredulidade em relação à eficácia de tecnologias médicas remotas. Ex.: dúvida sobre capacidade diagnóstica sem exame físico presencial."
    grupo: barreiras_a_adocao
END ONTOLOGY

ONTOLOGY falta_de_infraestrutura
    descricao: "Ausência ou precariedade de internet, equipamentos ou eletricidade que inviabilizam o uso de telemedicina."
    grupo: barreiras_a_adocao
END ONTOLOGY

ONTOLOGY preferencia_por_contato_presencial
    descricao: "Valorização do encontro face-a-face com o profissional de saúde, associando qualidade do atendimento à presença física."
    grupo: barreiras_a_adocao
END ONTOLOGY

ONTOLOGY letramento_digital_baixo
    descricao: "Dificuldade ou falta de familiaridade com uso de tecnologias digitais, gerando dependência de suporte externo para uso."
    grupo: barreiras_a_adocao
END ONTOLOGY

ONTOLOGY necessidade_urgente
    descricao: "Situação de emergência ou falta de alternativas viáveis presenciais que impulsiona a aceitação da telemedicina."
    grupo: facilitadores
END ONTOLOGY

ONTOLOGY apoio_comunitario
    descricao: "Suporte de vizinhos, familiares ou agentes de saúde que media o acesso de pacientes com baixo letramento digital."
    grupo: facilitadores
END ONTOLOGY

ONTOLOGY adocao_de_telemedicina
    descricao: "Decisão ou disposição do paciente de utilizar serviços médicos mediados por tecnologia remota."
    grupo: desfechos
END ONTOLOGY

ONTOLOGY acesso_a_telemedicina
    descricao: "Capacidade concreta de conectar-se e utilizar serviços de telemedicina, condicionada à infraestrutura disponível."
    grupo: desfechos
END ONTOLOGY

ONTOLOGY uso_de_telemedicina
    descricao: "Utilização efetiva de consultas ou serviços médicos remotos, seja autônoma ou mediada por terceiros."
    grupo: desfechos
END ONTOLOGY

ONTOLOGY aceitacao_de_telemedicina
    descricao: "Aprovação ou receptividade do paciente à telemedicina após experiência direta ou percepção de necessidade."
    grupo: desfechos
END ONTOLOGY

ONTOLOGY uso_efetivo_de_telemedicina
    descricao: "Realização de consultas ou atendimentos remotos com sucesso técnico e clínico, dependente de conectividade estável."
    grupo: desfechos
END ONTOLOGY

ONTOLOGY diagnostico_aprofundado
    descricao: "Processo diagnóstico que requer exame físico presencial, identificado como contexto de uso inapropriado para telemedicina."
    grupo: desfechos
END ONTOLOGY

Valide:

synesis check ontologia.syno
Checkpoint ✓

Você agora tem 12 conceitos definidos na ontologia, organizados em 3 grupos (barreiras_a_adocao, facilitadores, desfechos). À medida que analisar os dados, você pode adicionar mais.

1.5 Passo 4: Anotar Nossa Primeira Entrevista

Agora vem a parte principal: vamos anotar trechos das entrevistas. Crie anotacoes.syn:

SOURCE @entrevista_dona_maria2026
    tipo_ref: PRIM
END SOURCE

ITEM @entrevista_dona_maria2026
    quote: "Eu não confio nessas coisas de conversar com médico pelo computador. Como ele vai saber o que eu tenho se não me tocar, não me examinar?"
    memo: Participante expressa desconfiança na eficácia diagnóstica da telemedicina. Associa qualidade do atendimento à presença física e ao exame clínico presencial. Fala com tom de incredulidade.
    chain: desconfianca_tecnologica -> INIBE -> adocao_de_telemedicina
    context: Disse isso logo no início da conversa, antes mesmo de eu perguntar diretamente sobre telemedicina
END ITEM

ITEM @entrevista_dona_maria2026
    quote: "Aqui a internet cai toda hora. Às vezes fica dois, três dias sem. Como vou marcar consulta se nem WiFi tenho direito?"
    memo: Infraestrutura precária como barreira concreta. Frustração evidente na fala. O termo "nem WiFi tenho direito" sugere percepção de exclusão ou injustiça.
    chain: falta_de_infraestrutura -> INIBE -> acesso_a_telemedicina
    context: Falou com voz mais alta, demonstrando irritação
END ITEM

Agora é sua vez! Continue anotando. Vamos adicionar trechos da segunda entrevista:

SOURCE @entrevista_sr_joao2026
    tipo_ref: PRIM
END SOURCE

ITEM @entrevista_sr_joao2026
    quote: "Eu tentei usar uma vez que minha neta me ajudou. Foi bom, resolvi sem sair de casa. Mas sozinho eu não consigo não, preciso de alguém pra mexer no celular pra mim."
    memo: Experiência positiva quando mediada por familiar. Reconhece benefício (evitar deslocamento) mas identifica dependência de suporte técnico informal. Dicotomia entre percepção de utilidade e capacidade de uso autônomo.
    chain: apoio_comunitario -> MEDIA -> letramento_digital_baixo -> FAVORECE -> uso_de_telemedicina
    context: Falou com gratidão ao mencionar a neta, mas com resignação ao admitir a dependência
END ITEM

ITEM @entrevista_sr_joao2026
    quote: "Quando meu filho ficou internado na capital, a médica daqui falou com o médico de lá pelo vídeo. Foi uma bênção, porque ela pôde explicar o caso dele direitinho."
    memo: Exemplo concreto de uso bem-sucedido entre profissionais (comunicação inter-hospitalar). Contextualiza telemedicina como ferramenta para continuidade de cuidado, não apenas para primeira consulta. Termo religioso ("bênção") indica forte impacto emocional positivo.
    chain: necessidade_urgente -> FAVORECE -> aceitacao_de_telemedicina
    context: Única vez na entrevista em que sorriu ao falar do tema
END ITEM
Dica de Pesquisador

Observe como o campo context captura nuances qualitativas importantes (tom de voz, emoções, linguagem corporal). Essas anotações serão valiosas na fase de interpretação mais profunda.

1.6 Passo 5: Anotar a Terceira Entrevista (Perspectiva Profissional)

Agora vamos adicionar a perspectiva da profissional de saúde:

SOURCE @entrevista_dra_ana2026
    tipo_ref: REF
END SOURCE

ITEM @entrevista_dra_ana2026
    quote: "Os pacientes têm dificuldade, mas é mais a internet do que a vontade. Quando funciona, eles gostam. O problema é que nem sempre funciona."
    memo: Profissional identifica infraestrutura como barreira principal, não resistência cultural. Reconhece aceitação dos pacientes quando condições técnicas são adequadas. Importante contraponto à narrativa de "resistência ao novo".
    chain: falta_de_infraestrutura -> INIBE -> uso_efetivo_de_telemedicina
    context: Disse isso com frustração visível, gesticulando ao mencionar a internet
END ITEM

ITEM @entrevista_dra_ana2026
    quote: "Eu prefiro presencial quando posso, porque consigo ver coisas que não aparecem na tela. Mas para retorno, para tirar dúvida rápida, telemedicina é perfeita."
    memo: Profissional diferencia contextos de uso apropriado vs inapropriado. Nuança importante: não é rejeição binária, mas uso contextualizado. Sugere que telemedicina complementa, não substitui presencial.
    chain: preferencia_por_contato_presencial -> HABILITA -> diagnostico_aprofundado
    context: Tom pragmático, não emotivo. Fala de quem avalia prós e contras tecnicamente
END ITEM

Salve o arquivo anotacoes.syn.

Checkpoint ✓

Você anotou 6 trechos de 3 entrevistas diferentes. Validate:

synesis check anotacoes.syn

1.7 Passo 6: Criar o Arquivo de Projeto

Agora vamos conectar tudo. Crie analise.synp:

PROJECT analise_telemedicina_rural
# VERSION 1.0

TEMPLATE "template.synt"

INCLUDE BIBLIOGRAPHY "referencias.bib"
INCLUDE ONTOLOGY "ontologia.syno"
INCLUDE ANNOTATIONS "anotacoes.syn"

DESCRIPTION
    Análise qualitativa sobre barreiras e facilitadores
    à adoção de telemedicina em comunidades rurais.
    Abordagem: Análise temática
    Período: Janeiro-Fevereiro 2026
END DESCRIPTION

METADATA
    researcher: "Seu Nome"
    institution: "Sua Universidade"
    ethics_approval: "CEP-2025-XXX"
END METADATA

END PROJECT

1.8 Passo 7: Compilar e Analisar

Compile o projeto:

synesis compile analise.synp --output resultados/

Verifique os arquivos gerados:

resultados/
├── analise.json          # Estrutura completa
├── sources.csv          # Lista de fontes
├── items.csv            # Todas as anotações
├── codes.csv            # Frequência de códigos
├── chains.csv           # Relações causais
├── memos.csv            # Todos os memos
└── analise.xlsx         # Excel multi-aba

1.8.1 Análise no Excel

Abra analise.xlsx. Você verá:

Aba “Codes”: | Código | Frequência | Fontes | |——–|————|——–| | falta_de_infraestrutura | 2 | dona_maria, dra_ana | | desconfianca_tecnologica | 1 | dona_maria | | preferencia_por_contato_presencial | 1 | dra_ana | | apoio_comunitario | 1 | sr_joao | | necessidade_urgente | 1 | sr_joao | | … | … | … |

Aba “Chains”: | Relação | Conceito A | Conceito B | Frequência | |———|————|————|————| | INIBE | desconfianca_tecnologica | adocao_de_telemedicina | 1 | | INIBE | falta_de_infraestrutura | acesso_a_telemedicina | 1 | | INIBE | falta_de_infraestrutura | uso_efetivo_de_telemedicina | 1 | | FAVORECE | necessidade_urgente | aceitacao_de_telemedicina | 1 | | HABILITA | preferencia_por_contato_presencial | diagnostico_aprofundado | 1 | | … | … | … | … |

Insight de Análise

Observe que “Falta de Infraestrutura” aparece em todas as 3 entrevistas (pacientes E profissional). Isso sugere que a barreira não é apenas “resistência cultural”, mas concreta e sistêmica.

1.9 Passo 8: Refinar Análise (Processo Iterativo)

Agora que você viu os padrões iniciais, volte aos dados. Você pode:

1.9.1 8.1 Adicionar Novos Códigos

Se você identifica um padrão recorrente, adicione à ontologia:

ONTOLOGY percepcao_de_exclusao_digital
    descricao: "Sentimento de estar à margem da sociedade devido à falta de acesso ou domínio de tecnologias digitais."
    grupo: barreiras_a_adocao
END ONTOLOGY

1.9.2 8.2 Refinar Códigos Existentes

Se um código está ambíguo, divida:

# Antes:
ONTOLOGY desconfianca_tecnologica
    descricao: "Receio ou incredulidade em relação à eficácia de tecnologias médicas remotas."
    grupo: barreiras_a_adocao
END ONTOLOGY

# Depois (dividido em dois):
ONTOLOGY desconfianca_na_eficacia_diagnostica
    descricao: "Dúvida sobre a capacidade de diagnóstico sem exame físico presencial."
    grupo: barreiras_a_adocao
END ONTOLOGY

ONTOLOGY desconfianca_na_seguranca_de_dados
    descricao: "Receio sobre privacidade e vazamento de informações médicas em plataformas digitais."
    grupo: barreiras_a_adocao
END ONTOLOGY

1.9.3 8.3 Adicionar Mais Anotações

Volte às entrevistas originais e anote trechos adicionais que você não havia percebido na primeira leitura.

1.9.4 8.4 Recompilar

synesis compile analise.synp --output resultados/

Veja como os números mudaram!

1.12 Boas Práticas para Pesquisadores

1.12.1 1. Anote Progressivamente

Não espere terminar todas as entrevistas para começar a anotar. Analise à medida que coleta dados — isso permite ajustar roteiro de entrevistas.

1.12.2 2. Use Memos Analiticamente

O campo memo não é para repetir a citação. Use para: - Interpretar o significado - Identificar contradições ou nuances - Levantar hipóteses - Conectar com teoria

1.12.3 3. Documente Decisões

No campo context ou em memos, registre POR QUE você atribuiu determinado código. Isso será crucial na fase de escrita.

1.12.4 4. Revise Sistematicamente

A cada 5-10 anotações, compile e veja a distribuição de códigos. Pergunte: - Algum código está superabundante (muito genérico)? - Algum código aparece uma única vez (muito específico)? - Há padrões emergentes não capturados?

1.12.5 5. Valide com Pares

Compartilhe seu arquivo .syno (ontologia) com colegas. Peça para eles: - Verificarem se as definições são claras - Identificarem sobreposições conceituais - Sugerirem códigos ausentes

1.13 Diferenças de Abordagens Metodológicas

1.13.1 Teoria Fundamentada (Grounded Theory)

  • Comece com ontologia vazia
  • Adicione códigos conforme emergem dos dados (codificação aberta)
  • Use chain para capturar categorias centrais e relações entre categorias
  • Itere até saturação teórica

1.13.2 Análise Temática

  • Defina temas iniciais (dedutivos) ou deixe emergir (indutivos)
  • Use ONTOLOGY para temas e subtemas, agrupando pelo campo grupo
  • Campo memo para reflexões sobre temas recorrentes

1.13.3 Análise de Conteúdo

  • Template mais rígido, com campos predefinidos
  • Ontologia criada a priori baseada em literatura
  • Foco em frequência (use output CSV para quantificação)
  • Menos uso de chain, mais uso de conceitos de ONTOLOGY

1.13.4 Análise Crítica do Discurso

  • Use context extensivamente (prosódia, hesitações, silêncios)
  • Campo memo para identificar estratégias discursivas
  • chain para capturar pressupostos ideológicos
  • Anote o que NÃO foi dito (silêncios significativos)

1.15 Próximo Projeto

Agora que você domina o básico, experimente:

  1. Projeto com múltiplos tipos de fonte: Combine entrevistas + documentos + observações
  2. Análise longitudinal: Anote dados coletados em diferentes momentos
  3. Análise comparativa: Use o campo grupo na ontologia para separar subcasos e comparar distribuições entre grupos
